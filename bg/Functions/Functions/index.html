    Функции (Functions) в C++ - Пълно техническо ръководство

    1. Въведение: Повече от блокове код

    Функциите са основната единица за логическа абстракция в C++. В професионалния софтуер функцията не е просто начин за избягване на повторението на код (DRY principle). Тя е контракт – дефинира точно какво влиза (input), какво излиза (output) и какви са страничните ефекти (side effects). C++ функциите са уникални със своята гъвкавост: те могат да съществуват свободно (free functions), да бъдат част от класове (методи) или дори да се генерират по време на компилация (template functions).

    2. Механика на извикването (The Call Stack Deep Dive)

    ⚠️ ИНЖЕНЕРЕН ПОГЛЕД: Когато извикате функция, вие не просто "скачате" до нов ред код. Операционната система и процесорът извършват сложна операция по управление на паметта.

    2.1. Анатомия на Stack Frame

    Стекът (Call Stack) е област от паметта, която расте и се свива динамично. За всяко извикване на функция се създава нова "рамка" (stack frame), която съдържа:

    1. Аргументи: Данните, които подавате на функцията (ако не се събират в процесорните регистри).
    2. Return Address: Адресът на инструкцията в кода, към която процесорът трябва да се върне след като функцията приключи (команда RET).
    3. Saved Registers: Стойностите на регистрите на извикващата функция, които трябва да се възстановят по-късно.
    4. Локални променливи: Всички променливи, дефинирани вътре в тялото на функцията.

    2.2. Calling Conventions (cdecl, stdcall, fastcall)

    Това са "протоколите", по които функциите си говорят на ниско ниво. Те определят: * Кой почиства стека (извикващият или извиканият)? * Къде се слагат аргументите (в регистри или в стека)? * В какъв ред се подават аргументите (отляво-надясно или обратно)?

    Например, __fastcall (често използван в x64) се опитва да подаде първите няколко аргумента директно в регистрите (RCX, RDX, R8, R9 под Windows), избягвайки бавния достъп до RAM паметта.

    3. Предаване на параметри: Борба за производителност

    Изборът как да подадете данните може да ускори или забави програмата ви с порядъци.

    3.1. Pass by Value (По стойност)

    void func(int x);
    Създава копие на аргумента. * Кога: За примитивни типове (int, double, bool, char*). * Плюс: Пълна изолация. Промяната на x вътре не влияе на оригинала. * Минус: Скъпо за големи обекти.

    3.2. Pass by Reference (T&)

    void func(GamePlayer& player);
    Подава се скрит указател към оригинала. * Кога: Когато искате функцията да промени състоянието на обекта (Output Parameter). * Минус: Опасност от нежелани странични ефекти.

    3.3. Pass by Const Reference (const T&)

    void func(const std::string& text);
    Златният стандарт в C++. * Механика: Подава се адрес (като референция), но компилаторът забранява промяна на данните. * Кога: За всички сложни обекти (string, vector, потребителски класове), които само четем.

    3.4. Pass by R-value Reference (T&&) - Move Semantics

    void func(std::vector<int>&& data);
    Позволява на функцията да "открадне" ресурсите на временен обект. Вместо да копираме 1GB данни, ние просто копираме указателя към буфера с данните и нулираме стария.

    4. Return Value Optimization (RVO) и Copy Elision

    В миналото, връщането на голям обект от функция беше бавно: 

    std::vector<int> createHugeVector() {
    std::vector<int> v(1000000);
    return v; // Тук се правеше копие!
}
    Модерните компилатори (C++17 и нагоре) прилагат Guaranteed Copy Elision. Обектът v се конструира директно в паметта на променливата, която приема резултата. Няма копиране, няма дори преместване (move). Това прави връщането по стойност предпочитано за създаване на нови обекти.

    5. Претоварване и Name Mangling

    C++ позволява да имате void print(int) и void print(double). На ниво асемблер/обектен код обаче, имената трябва да са уникални. Компилаторът извършва Name Mangling (декориране на имена): * print(int) -> _Z5printi * print(double) -> _Z5printd

    Това е причината да не можете лесно да викате C++ функции от C, освен ако не ги оградите с extern "C", което изключва mangling-а.

    6. Модерни функции в C++ (Функционално програмиране)

    6.1. Ламбда изрази (Lambda Expressions)

    Ламбдите са анонимни функции, дефинирани на място. Те са мощни заради способността си да "прихващат" (capture) променливи от обкръжаващия scope.

    int factor = 10;
auto multiplier = [factor](int n) { return n * factor; };
    Под капака, компилаторът генерира уникален клас (Functor) с член-променлива factor и претоварен operator().

    6.2. std::function - Универсалният контейнер

    Библиотеката <functional> предоставя std::function<Ret(Args...)>. Това е обект, който може да съхранява: * Обикновена функция. * Ламбда. * Функтор (обект с operator()). * Резултат от std::bind.

    ⚠️ Внимание: std::function има overhead (виртуални извиквания и динамична памет). Използвайте template или auto, ако скоростта е критична.

    7. Рекурсия срещу Итерация

    7.1. Рискът от Stack Overflow

    Всяко рекурсивно извикване добавя нова рамка в стека. 

    void recursive() { recursive(); }
    Тъй като стекът е ограничен (често 1MB - 8MB), дълбока рекурсия (напр. обхождане на списък с 1 милион елемента) ще доведе до Stack Overflow и мигновен краш.

    7.2. Tail Call Optimization (TCO)

    Ако рекурсивното извикване е последната операция във функцията, компилаторът може да го оптимизира, превръщайки го в обикновен цикъл (JMP инструкция). Това запазва стека чист. За съжаление, C++ стандартите не гарантират TCO във всички случаи.

    8. Inline Functions

    Ключовата дума inline е подсказка към компилатора: "Вместо да викаш тази функция (call + ret), копирай тялото ѝ директно на мястото на извикването". * Плюс: Елиминира цената на извикването (stack frame, registers). * Минус: Увеличава размера на изпълнимия файл (Code Bloat), което може да влоши работата на инструкционния кеш (Instruction Cache).

    9. Професионално обобщение

    1. Чисти функции: Стремете се функциите да нямат странични ефекти (да не променят глобални променливи).
    2. Една отговорност: Функцията трябва да прави едно нещо и да го прави добре.
    3. Const Correctness: Ако параметър не трябва да се променя, задължително го маркирайте с const.
    4. Noexcept: Ако функцията не хвърля изключения, маркирайте я с noexcept. Това позволява на компилатора да генерира по-бърз код.
    5. RVO: Връщайте големи обекти по стойност, разчитайки на оптимизацията на връщаната стойност.
