    Print Formatting и I/O (std::print & std::format) - Пълно техническо ръководство

    1. Въведение: Историята на C++ I/O

    C++ входно-изходната система (I/O) е преминала през три големи епохи, всяка със своите предимства и недостатъци.

    Епоха 1: C-style printf (1972)

    • Плюсове: Изключително бърз, компактен синтаксис, малък binary size.
    • Минуси: Небезопасен (Type-unsafe). %s очаква char*, ако подадете std::string (обект), програмата крашва или печата паметта. Не може да се разширява за потребителски типове.

    Епоха 2: C++ iostreams (1998)

    • Плюсове: Безопасен за типовете (Type-safe), разширяем (чрез претоварване на operator<<).
    • Минуси: Бавен (много виртуални извиквания), ужасен синтаксис за форматиране (std::cout << std::hex << std::setw(8) << std::setfill('0')). Състоянието на потока е глобално (stateful) – ако промените прецизността, тя остава такава завинаги, което е източник на бъгове.

    Епоха 3: Modern Formatting (C++20/23)

    Библиотеката <format> (C++20) и <print> (C++23) обединяват най-доброто: безопасността на iostreams, скоростта на printf и удобния синтаксис на Python/Rust.

    2. std::format (C++20): Енджинът

    std::format е функция, която връща std::string. Тя не печата.

    #include <format>
std::string msg = std::format("User {} logged in at {}", "admin", "12:00");

    2.1. Позиционни аргументи

    Можете да пренареждате аргументите, което е критично за локализация (превод на други езици, където словоредът е различен). 

    // {0} е първият аргумент, {1} е вторият
std::string s = std::format("{1} is the surname of {0}", "John", "Doe");

    2.2. Форматиращ синтаксис (Mini-language)

    Форматът е: { [arg_id] : [fill] [align] [sign] [#] [0] [width] [.precision] [type] }

    • Align: {:>10} (дясно), {:<10} (ляво), {:^10} (център).
    • Fill: {:_>10} -> ______text.
    • Sign: {:+} (винаги показвай знак, дори за положителни).
    • Type:
      • b (binary), B (Binary), x (hex), o (octal).
      • f (fixed), e (scientific), g (general).
    // Принтира "Int: 0042, Hex: 0x2a"
std::format("Int: {:04d}, Hex: {:#x}", 42, 42);

    3. std::print (C++23): Изходът

    std::print е по-бърз от std::cout и printf в повечето случаи. Той пише директно в буфера на операционната система, заобикаляйки тежката йерархия на ostream.

    #include <print>

int main() {
    std::print("Hello World!\n");
    std::println("Value: {}", 42); // Автоматичен нов ред

    // Писане във файл (File Stream)
    FILE* f = fopen("log.txt", "w");
    std::println(f, "Error code: {}", 500);
}

    3.1. Проблемът с Unicode в Windows

    Една от най-големите победи на std::print е, че той най-накрая решава проблема с "маймуницата" в Windows конзолата. Ако печатате UTF-8 низ, std::print автоматично открива дали изходът е конзола и използва правилния Unicode API (WriteConsoleW), вместо да разчита на остарелите Code Pages. Няма нужда повече от SetConsoleOutputCP(65001).

    4. Разширяване: std::formatter

    За да направите вашия клас Point да работи с std::print("{}", p), трябва да специализирате std::formatter.

    struct Point { int x, y; };

template <>
struct std::formatter<Point> {
    // 1. Parse: Анализира форматния низ (напр. "{:a}" за алтернативен изглед)
    constexpr auto parse(std::format_parse_context& ctx) {
        // Тук можем да четем опции. Засега просто връщаме края.
        return ctx.begin();
    }

    // 2. Format: Записва резултата
    auto format(const Point& p, std::format_context& ctx) const {
        // format_to е като append
        return std::format_to(ctx.out(), "Point({}, {})", p.x, p.y);
    }
};

    5. Специализирано форматиране

    5.1. Хронометрия и Дати (Chrono)

    В C++20 std::chrono получи пълна интеграция с std::format. Вече няма нужда да ползвате strftime или макроси.

    #include <chrono>
#include <format>

auto now = std::chrono::system_clock::now();
// ISO 8601 формат
std::string iso = std::format("{:%Y-%m-%d %H:%M:%S}", now);

// Само часът
std::string time = std::format("Current time: {:%T}", now);

    5.2. Ranges и Колекции (C++23)

    В C++23 можете да подадете цял вектор директно на std::print.

    std::vector<int> v = {1, 2, 3};
std::println("Vector: {}", v); // Изход: Vector: [1, 2, 3]

std::map<string, int> m = {{"Apple", 5}, {"Banana", 10}};
std::println("Map: {}", m);    // Изход: Map: {"Apple": 5, "Banana": 10}
    Това е изключително полезно за дебъгване (Logging), тъй като елиминира нуждата от писане на цикли само за да видите съдържанието на контейнер.

    6. Производителност и std::format_to

    Ако искате максимална скорост и нулева алокация на памет (Zero-allocation), използвайте std::format_to с предварително заделен буфер.

    char buffer[100];
std::format_to_n(buffer, 100, "Fast format: {}", 123);
    Това е идеално за Embedded системи или High-Frequency Trading логъри.

    Сравнение на производителността (Benchmark): 1. printf: Много бърз, но прави runtime parsing на формата. 2. std::cout: Бавен заради синхронизацията и виртуалните функции. 3. std::print: Най-бърз. Форматният низ се парсва по време на компилация (ако е constexpr), а системните извиквания са оптимизирани.

    7. Compile-time Checks (Safety)

    std::format и std::print проверяват валидността на форматния низ по време на компилация.

    // std::print("{:d}", "Hello"); 
// ГРЕШКА ПРИ КОМПИЛАЦИЯ!
// "Hello" е низ, а {:d} иска число.
    При printf това щеше да се компилира и да гръмне при стартиране (Runtime Crash). C++ постига това чрез consteval конструктори и магическа template метапрограма.

    8. Често срещани грешки

    • Забравяне на аргументи: Ако напишете std::format("{} {}") и подадете само един аргумент, кодът няма да се компилира.
    • Смесване на локали: Внимавайте, ако ползвате std::locale с std::print. По подразбиране е "C" локал (точка за десетична запетая).
    • Използване на std::string_view: Ако пазите резултата от std::format (който е std::string) в std::string_view, внимавайте за живота на временния обект.

    9. Професионално обобщение

    1. Мигрирайте: Забравете за iostream за форматиран изход. Използвайте std::print. Ползвайте std::cout само за бързи тестове или ако трябва да поддържате C++98.
    2. За библиотеки: Ако пишете библиотека, не принтирайте. Връщайте std::string или приемайте std::ostream& (за съвместимост), но най-добре предоставете std::formatter специализация.
    3. Локализация: std::format е "Locale-independent" по подразбиране (десетичната запетая е винаги точка). Ако искате локализиран изход (със запетая), използвайте std::format(std::locale("bg_BG"), ...) (когато бъде имплементирано в компилаторите, все още е експериментално).
    4. ANSI Colors: std::print не поддържа цветове автоматично (освен чрез ANSI escape codes). За цветен терминал се препоръчва да ползвате външни библиотеки, които обвиват std::print и се справят с Windows конзолата.
