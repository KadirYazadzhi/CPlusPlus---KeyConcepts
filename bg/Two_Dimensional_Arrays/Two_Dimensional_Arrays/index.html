    Двумерни Масиви (2D Arrays) в C++ - Пълно техническо ръководство

    1. Въведение: Представяне на матрици и таблици

    Двумерният масив (матрица) е инструментът, с който описваме структури от данни, организирани в редове и колони – като електронни таблици, изображения (пиксели) или игрални полета. В C++, разбирането на това как тези данни се съхраняват във физическата памет е разликата между работещия софтуер и високопроизводителния софтуер.

    2. Физически модел: Илюзията за 2D

    ⚠️ КЛЮЧОВА КОНЦЕПЦИЯ: Паметта на компютъра (RAM) е линейна (едноизмерна). Тя е просто една дълга лента от байтове с адреси от 0 до N.

    Двумерният масив не съществува като физическа "таблица" или "мрежа" в паметта. C++ подрежда елементите линейно, използвайки модела Row-Major Order (Ред след ред).

    Ако имаме int a[2][3] (2 реда, 3 колони), в паметта те изглеждат така: [0,0], [0,1], [0,2], [1,0], [1,1], [1,2]

    Първо се записват всички елементи от първия ред, после всички от втория, и т.н. Това е различно от Fortran или MATLAB, които използват Column-Major Order.

    2.1. Математическата формула за достъп (Indexing Mapping)

    Когато напишете matrix[i][j], компилаторът трансформира тези две координати в един линеен адрес:

    Линеен_Индекс = (i * Брой_Колони) + j
Адрес = Базов_Адрес + (Линеен_Индекс * sizeof(Тип))
    • i е индексът на реда.
    • j е индексът на колоната.
    • Брой_Колони е ширината на матрицата (stride).

    Това обяснява защо при подаване на масив на функция, задължително трябва да посочите броя на колоните. Без това число, компилаторът не знае колко голям е един "ред" и не може да пресметне, къде започва следващият (i * Брой_Колони).

    3. Декларация и Инициализация (Всички варианти)

    3.1. Статична матрица (Stack)

    Всичко е в един блок памет. Най-бързият вариант.

    int matrix[3][3] = {
    {1, 2, 3}, // Ред 0
    {4, 5, 6}, // Ред 1
    {7, 8, 9}  // Ред 2
};

// Частична инициализация
int grid[5][5] = { {1, 2}, {3} }; // Останалите стават 0

    3.2. Динамична матрица (Heap) - Вариант с масив от указатели

    Това е класическият, но опасен и бавен начин ("Jagged Array").

    int rows = 3, cols = 4;
int** matrix = new int*[rows]; // 1. Масив от указатели (гръбнак)
for(int i = 0; i < rows; ++i) {
    matrix[i] = new int[cols]; // 2. Заделяне на всеки ред поотделно
}
    • Проблем 1 (Фрагментация): Всеки ред може да е на произволно място в паметта. Няма гаранция за непрекъснатост.
    • Проблем 2 (Cache Misses): Скачането от ред на ред убива производителността.
    • Проблем 3 (Memory Leak): Изисква сложен цикъл за освобождаване: 
      for(int i = 0; i < rows; ++i) delete[] matrix[i];
delete[] matrix;

    3.3. Динамична матрица - Професионален подход (Contiguous Block)

    Заделяме всичко наведнъж, за да е бързо.

    int* flatMatrix = new int[rows * cols];
// Достъп: flatMatrix[i * cols + j]

    4. Оптимизация: Traversal и Cache Locality

    Начинът, по който обхождате матрицата, може да промени скоростта на кода ви драстично (от 2 до 20 пъти по-бавно).

    4.1. Cache-friendly (Правилно)

    Винаги обхождайте така, както е подредена паметта – ред по ред.

    // i = ред, j = колона
for(int i = 0; i < rows; ++i) {
    for(int j = 0; j < cols; ++j) {
        sum += matrix[i][j]; 
    }
}
    * Защо? Процесорът зарежда част от реда в кеша. Следващите итерации на j четат директно от L1 кеша (мигновено).

    4.2. Cache-hostile (Грешно)

    Обхождането по колони е катастрофа за производителността.

    for(int j = 0; j < cols; ++j) {     // Външният цикъл е по колони
    for(int i = 0; i < rows; ++i) { // Скачаме между редовете
        sum += matrix[i][j]; 
    }
}
    * Защо? При всяка итерация на вътрешния цикъл скачаме на адрес + width. Това вероятно е извън текущата кеш линия. Предизвикваме Cache Miss на почти всяка стъпка, карайки CPU да чака бавната RAM памет.

    5. Професионално решение: Flattening и std::vector

    В съвременния C++ (Game Dev, High Frequency Trading), ние избягваме int**. Използваме класове-обвивки или "splatting" (изравняване).

    5.1. 1D Вектор като 2D Матрица

    class Matrix {
    std::vector<int> data;
    int cols;
public:
    Matrix(int r, int c) : data(r * c), cols(c) {}

    int& at(int r, int c) {
        return data[r * cols + c];
    }
};
    Предимства: 1. Една алокация: Само един new (скрит във вектора). 2. RAII: Паметта се чисти автоматично. 3. Скорост: Максимална кеш локалност.

    6. Подаване на 2D масиви на функции

    Ако ползвате статични масиви, синтаксисът е специфичен.

    // Задължително трябва да знаем всички измерения без първото!
void process(int mat[][10], int rows); 

// Или с template, за да хванем и двата размера:
template <size_t R, size_t C>
void process(int (&mat)[R][C]) {
    // R и C са константи тук
}

    7. Многомерни масиви (3D, 4D...)

    Логиката е същата. int space[X][Y][Z] се разгъва като: Адрес = Z + Width*Y + Width*Height*X ... Колкото повече измерения, толкова по-сложна става аритметиката и по-важна става кеш локалността.

    8. Обобщение

    1. Паметта е линейна. 2D масивите са абстракция.
    2. Винаги итерирайте по редове (най-дясното измерение трябва да се променя най-бързо във вътрешния цикъл).
    3. Избягвайте int** (масив от указатели) заради фрагментацията.
    4. Използвайте Flattening (1D масив с аритметика) за сериозни задачи.
    5. Помнете: Strides (стъпките) са скъпи, последователният достъп е евтин.
