    Претоварване на Оператори (Operator Overloading) - Пълно техническо ръководство

    1. Въведение: Синтактична захар или мощ?

    В C++ операторите са просто функции със специални имена. Вместо add(a, b), пишем operator+(a, b). Това позволява на потребителските типове (матрици, комплексни числа, стрингове) да се държат естествено, сякаш са вградени в езика. Без претоварване на оператори, кодът за умножение на матрици би изглеждал така: Matrix c = Matrix::multiply(Matrix::add(a, b), d); С претоварване: Matrix c = (a + b) * d;

    ⚠️ Внимание: "С голямата сила идва голяма отговорност". Не претоварвайте оператори, ако значението им не е очевидно. operator+ за събиране на двама потребители (User + User) е лоша идея. Какво означава това? Брак? Дете?

    2. Основни правила и ограничения

    1. Приоритет: Не можете да променяте приоритета на операторите. * винаги се изпълнява преди +.
    2. Арност: Не можете да променяте броя на аргументите. + винаги е унарен (знак) или бинарен (събиране).
    3. Нови оператори: Не можете да измисляте нови символи като **, $$ или -->.
    4. Вградени типове: Не можете да претоварите operator+(int, int). Поне един от аргументите трябва да е ваш потребителски тип.

    3. Член-функция срещу Свободна функция

    Операторите могат да се дефинират по два начина:

    3.1. Като метод на класа (Member function)

    Левият операнд автоматично е *this. Това е задължително за операторите =, [], (), ->.

    class Complex {
public:
    // c1 += c2
    Complex& operator+=(const Complex& rhs) {
        real += rhs.real;
        imag += rhs.imag;
        return *this; // Връщаме референция за верижност (a += b += c)
    }
};

    3.2. Като свободна функция (Non-member function)

    Препоръчително за симетрични оператори (+, -, ==, !=). Това позволява автоматично преобразуване (Implicit Conversion) на левия аргумент.

    Пример: Имаме Complex(double). * Ако operator+ е метод: c + 5.0 работи, но 5.0 + c НЕ работи (защото double няма метод operator+). * Ако operator+ е свободна функция: 5.0 + c работи, защото компилаторът превръща 5.0 в Complex(5.0).

    // c3 = c1 + c2
Complex operator+(Complex lhs, const Complex& rhs) {
    lhs += rhs; // Използваме += за имплементацията
    return lhs;
}

    4. The Spaceship Operator <=> (C++20)

    Преди C++20, за да поддържате пълно сравнение, трябваше да напишете 6 оператора: ==, !=, <, >, <=, >=. Това е много код и риск от грешки.

    C++20 въведе Three-way comparison operator (<=>). Той връща обект, който казва дали е по-малко, равно или по-голямо (като strcmp или compareTo).

    #include <compare>

class Version {
    int major, minor, patch;
public:
    // Компилаторът генерира ВСИЧКИ 6 оператора автоматично!
    auto operator<=>(const Version&) const = default; 
};
    Това е една от най-добрите функционалности на C++20, спестяваща стотици редове код.

    5. Специални оператори

    5.1. Оператор () (Functor)

    Превръща обекта във функция. Това е основата на Ламбда изразите. 

    struct Hasher {
    size_t operator()(const std::string& s) const {
        return std::hash<std::string>{}(s);
    }
};

    5.2. Оператори * и -> (Smart Pointers)

    Позволяват обектът да се държи като указател (Proxy Pattern). 

    T& operator*() const { return *ptr; }
T* operator->() const { return ptr; }

    5.3. Оператор [] (Subscript)

    За достъп до масиви или матрици. ⚠️ От C++23 операторът [] може да приема множество аргументи: matrix[x, y]. Преди това трябваше да ползваме matrix(x, y).

    5.4. Оператор new и delete

    Можете да претоварите начина, по който се заделя памет за вашия клас (напр. от Pool Allocator вместо от Heap).

    6. I/O Оператори (<< и >>)

    Те задължително са свободни функции (friend functions), защото левият операнд е std::ostream, който е системен клас и не можем да го променяме.

    class User {
    std::string name;
public:
    friend std::ostream& operator<<(std::ostream& os, const User& u) {
        os << "User(" << u.name << ")";
        return os; // За верижност: cout << u << endl;
    }
};

    7. Професионално обобщение

    1. Принципът на най-малката изненада: Операторите трябва да правят това, което математиката предполага. a + b не трябва да променя a.
    2. Канонични форми: Винаги имплементирайте бинарните оператори (+) чрез съставните (+=). Това гарантира логическа съгласуваност и намалява дублирането на код.
    3. Идиомът Copy-and-Swap: За operator=, използвайте този идиом за безопасност при изключения (Exception Safety). Приемате аргумента по стойност (копие) и го разменяте (swap) с this.
