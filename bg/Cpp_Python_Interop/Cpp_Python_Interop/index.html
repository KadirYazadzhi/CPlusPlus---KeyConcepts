    C++ и Python Interoperability - Пълно техническо ръководство

    1. Въведение: Съюзът на Титаните

    В света на софтуерното инженерство днес доминират два езика с коренно различни философии. C++ е езикът на производителността. Той дава пълен контрол над хардуера, паметта и процесора. Използва се за гейм енджини, високочестотна търговия (HFT), бази данни и операционни системи. Python е езикът на продуктивността. Той е лесен за четене, динамичен и има най-богатата екосистема за Data Science, AI и Machine Learning.

    Интеграцията между тях позволява да вземете най-доброто от двата свята: бързо ядро на C++ и гъвкав интерфейс на Python. Всъщност, повечето "Python" библиотеки за AI (TensorFlow, PyTorch, NumPy) са просто тънки обвивки над тежък C++ код.

    2. История на инструментите (SWIG vs Boost.Python vs Pybind11)

    През годините са създадени много инструменти за свързване на двата езика.

    2.1. Python C API (Hardcore Mode)

    Python (CPython) е написан на C. Можете да ползвате неговия C API директно (#include <Python.h>). * Плюсове: Никакви зависимости. Пълен контрол. * Минуси: Изключително вербозен код. Ръчно управление на Reference Counting (Py_INCREF, Py_DECREF). Лесно е да направите Memory Leak или Segfault.

    2.2. SWIG (Simplified Wrapper and Interface Generator)

    Инструмент, който чете C++ хедъри и генерира код за много езици (Java, Python, C#, Ruby). * Плюсове: Поддържа много езици едновременно. * Минуси: Изисква собствен интерфейсен файл (.i). Генерираният код е огромен и труден за дебъгване. Остаряла технология.

    2.3. Boost.Python

    Първата библиотека, която използва C++ темплейти за автоматично генериране на връзките. * Минуси: Изисква инсталацията на гигантската библиотека Boost. Бавна компилация.

    2.4. Pybind11 (Златният стандарт днес)

    Наследникът на Boost.Python. Header-only библиотека, която използва модерните възможности на C++11/14/17. * Плюсове: Лека, бърза, елегантен синтаксис. Поддържа NumPy, Smart Pointers, Exceptions.

    3. Pybind11: Практически пример

    #include <pybind11/pybind11.h>
namespace py = pybind11;

// C++ функция
int add(int i, int j) {
    return i + j;
}

// Дефиниция на модула
PYBIND11_MODULE(example, m) {
    m.doc() = "pybind11 example plugin"; // docstring
    m.def("add", &add, "A function which adds two numbers");
}
    Този код се компилира до споделена библиотека (example.so), която Python може да импортира: import example.

    4. Споделяне на памет (Zero-Copy) с NumPy

    Най-критичната част при интеграцията е предаването на големи масиви данни (изображения, матрици). Ако копирате данните всеки път (маршалинг), губите цялата полза от C++. Python има Buffer Protocol, който позволява директен достъп до паметта на обекти. Pybind11 го поддържа чрез py::array_t.

    #include <pybind11/numpy.h>

void process_image(py::array_t<uint8_t> input) {
    py::buffer_info buf = input.request();

    if (buf.ndim != 2) throw std::runtime_error("Must be 2D image");

    uint8_t* ptr = static_cast<uint8_t*>(buf.ptr);

    // Директна манипулация на пикселите в паметта на Python!
    for (size_t i = 0; i < buf.size; i++) {
        ptr[i] = 255 - ptr[i]; // Инвертиране (Invert colors)
    }
}
    В този пример C++ кодът чете и пише директно в паметта, заделена от NumPy в Python. Няма копиране (Zero-Copy).

    5. The GIL (Global Interpreter Lock)

    Това е най-голямото ограничение на Python. Интерпретаторът може да изпълнява само една нишка байткод в даден момент (заради thread-unsafe управление на паметта). Когато извикате C++ функция от Python, GIL остава заключен. Това означава, че всички други Python нишки са блокирани.

    Ако вашата C++ функция извършва тежка работа (напр. training на ML модел), тя трябва да освободи GIL.

    {
    py::gil_scoped_release release; // GIL се отключва

    // Тук сме в "C++ Land". Можем да ползваме std::thread, OpenMP и да натоварим всички ядра.
    // В същото време Python нишките (GUI, Web Server) могат да работят паралелно.
    heavy_computation();

} // GIL се заключва автоматично обратно при излизане от скопа (RAII).

    6. Дебъгване и Разпространение

    6.1. Дебъгване

    Дебъгването на смесен код е сложно. * GDB: Използвайте gdb python. GDB има разширения за Python, които позволяват да виждате Python stack frames (py-bt) заедно с C++ stack frames (bt). * IDE: Visual Studio и VS Code поддържат Mixed-Mode debugging, където можете да стъпвате (Step Into) от Python код директно в C++ кода.

    6.2. Python Wheels

    За да разпространите библиотеката си, трябва да я пакетирате като Wheel (.whl). Това е архив, който съдържа компилираните бинарни файлове (.so/.pyd). Тъй като C++ е зависим от платформата, трябва да компилирате отделни Wheels за Linux, Windows, macOS и за всяка версия на Python. Инструментът cibuildwheel автоматизира това в CI/CD (GitHub Actions).

    7. Професионално обобщение

    1. Интерфейс: Дръжте интерфейса между C++ и Python "дебел" (Chunky interface). Избягвайте "бъбриви" (Chatty) интерфейси, където Python вика C++ милиони пъти в цикъл. Всеки call има overhead. Вместо това, преместете цикъла в C++.
    2. Собственост: Внимавайте с жизнения цикъл на обектите. py::keep_alive политиката в Pybind11 казва на Python GC да не трие C++ обекта, докато друг обект го държи.
    3. Изключения: Всички C++ изключения автоматично се превръщат в Python Runtime Errors. Това прави обработката на грешки естествена.
