    Работа с Файлове и I/O (File I/O) - Пълно техническо ръководство

    1. Въведение: Потоците (Streams) и Абстракцията

    В C++ работата с файлове се извършва чрез класовете във <fstream>. Те са част от мощната, но сложна йерархията на iostream. Основната идея на потоците е абстракцията. За вашата програма няма значение дали пишете в конзолата, във файл, в стринг (stringstream) или в сокет. Интерфейсът е един и същ: операторите << и >>.

    Основните класове са: * std::ofstream: Output File Stream (за писане). * std::ifstream: Input File Stream (за четене). * std::fstream: Input/Output Stream (за едновременно четене и писане).

    Тези класове използват RAII (Resource Acquisition Is Initialization). Отварянето на файла става в конструктора, а затварянето – автоматично в деструктора. Това предотвратява изтичане на ресурси (File Handles), ако забравите да затворите файла или ако възникне изключение.

    2. Текстови срещу Бинарни файлове

    Това е първият избор, който трябва да направите.

    2.1. Текстов режим (Default)

    Файлът се третира като поредица от редове. * Преобразуване на нов ред: При четене, системните знаци за нов ред (\r\n в Windows, \n в Linux) се превръщат автоматично в \n. При писане става обратното. * Употреба: Конфигурационни файлове (.ini, .json), логове, изходен код.

    2.2. Бинарен режим (std::ios::binary)

    Файлът се третира като "торба с байтове" (Raw Bytes). Никаква магия не се случва. * Употреба: Изображения (.png, .jpg), аудио, база данни, сериализирани обекти. * Важно: Винаги използвайте read() и write() за бинарни файлове, а не << и >>. Операторите за поток са предназначени за форматиран текст (напр. числото 123 се записва като 3 байта "1", "2", "3", а не като 4-байтово цяло число).

    // Четене на цял файл в паметта (най-бързият стандартен начин)
std::ifstream file("data.bin", std::ios::binary | std::ios::ate); // ate = at the end
if (!file) throw std::runtime_error("Cannot open file");

std::streamsize size = file.tellg(); // Взимаме текущата позиция (която е края)
file.seekg(0, std::ios::beg);        // Връщаме се в началото

std::vector<char> buffer(size);
if (file.read(buffer.data(), size)) {
    // Данните са в буфера
}

    3. Буфериране и Производителност (std::flush)

    Писането на диск е невероятно бавно (милисекунди) в сравнение с писането в RAM (наносекунди). За да не спира програмата при всяко file << "a", ofstream използва вътрешен буфер (обикновено 4KB или 8KB). Данните се записват реално на диска (System Call write) само когато: 1. Буферът се препълни. 2. Изрично извикате file.flush() или std::flush. 3. Използвате std::endl (което е еквивалентно на << '\n' << std::flush). 4. Файлът се затвори (нормално или при унищожаване на обекта).

    ⚠️ Performance Tip: Никога не използвайте std::endl в цикли! 

    // ЛОШО: 1000 записа на диска
for(int i=0; i<1000; ++i) file << i << std::endl;

// ДОБРО: 1 запис на диска (или колкото е буфера)
for(int i=0; i<1000; ++i) file << i << '\n';

    4. std::filesystem (C++17): Модерната ера

    Преди C++17, работата с директории, права за достъп и пътища беше кошмар от #ifdef _WIN32. Библиотеката <filesystem> (в namespace std::filesystem или fs) решава това.

    4.1. Класът path

    Той абстрахира разделителите (/ или \). 

    fs::path p = "data";
p /= "users"; // Автоматично добавя правилния разделител
p /= "config.xml"; 
// Резултат: "data/users/config.xml" (Linux) или "data\users\config.xml" (Windows)

    4.2. Unicode и Пътища

    Windows използва UTF-16 (wchar_t) за файловата система. Linux използва UTF-8 (char). std::filesystem::path се справя с това автоматично. * path.string(): Връща std::string (може да загуби данни в Windows, ако имате китайски йероглифи и английски локал). * path.u8string(): Връща UTF-8 низ (препоръчително за преносимост). * path.wstring(): Връща Wide string (за Windows API).

    4.3. Операции

    • fs::exists(p): Проверка за съществуване.
    • fs::file_size(p): Размер в байтове.
    • fs::create_directories("a/b/c"): Еквивалент на mkdir -p.
    • fs::directory_iterator: Обхождане на файлове в папка.

    5. Заключване на Файлове (File Locking)

    Стандартният C++ няма механизъм за заключване на файлове. Ако два процеса пишат в един файл едновременно -> Data Corruption. Трябва да използвате платформено-специфични API или библиотеки (Boost): * Linux: flock() или fcntl(). * Windows: LockFileEx(). * Boost.Interprocess: Преносими file_lock класове.

    6. Memory Mapped Files (MMAP)

    За работа с огромни файлове (по-големи от RAM паметта) или за екстремна скорост, се използва Memory Mapping. Това казва на ОС: "Направи този файл да изглежда като масив в паметта ми". ОС се грижи да зарежда страници от диска само когато ги достъпите (Lazy Loading). Това избягва копирането на данни от Kernel Space в User Space буфери. * В C++ няма стандартен mmap. Използвайте boost::iostreams::mapped_file или малки библиотеки като mio.

    7. Професионално обобщение

    1. Проверка за грешки: Винаги проверявайте file.is_open() след отваряне. Не предполагайте, че файлът е там.
    2. Затваряне: Не викайте file.close() ръчно, освен ако не искате да проверите дали записът е успял (close може да върне грешка, ако дискът е пълен при flush). Оставете деструктора да го направи.
    3. Локализация: Внимавайте с std::locale. Ако записвате числа с десетична запетая в България (3,14) и ги четете в САЩ (3.14), програмата ще гръмне. Винаги ползвайте "C" локал за файлови формати.
