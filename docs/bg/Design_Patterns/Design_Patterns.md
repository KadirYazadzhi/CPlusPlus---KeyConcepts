# Шаблони за Дизайн (Design Patterns) - Пълно техническо ръководство

## 1. Въведение: Езикът на софтуерните архитекти

Шаблоните за дизайн не са готов код, а утвърдени и доказани във времето рецепти за решаване на често срещани проблеми в софтуерната архитектура. В C++, където управлението на паметта и йерархиите са комплексни, шаблоните ни помагат да спазваме принципите на **SOLID** и да пишем код, който е лесен за поддръжка.

---

## 2. Създаващи Шаблони (Creational Patterns)

### 2.1. Singleton (Единствена Инстанция)
Гарантира, че един клас има само една инстанция и предоставя глобална точка за достъп до нея.

**C++ Имплементация (Meyers Singleton):**
Най-безопасният начин в C++11 (Thread-safe initialization).
```cpp
class Logger {
public:
    static Logger& get() {
        static Logger instance; // Инициализира се само веднъж, безопасно
        return instance;
    }
    // Забраняваме копиране
    Logger(const Logger&) = delete;
    void operator=(const Logger&) = delete;
private:
    Logger() {} // Частен конструктор
};
```

### 2.2. Factory Method (Фабричен Метод)
Дефинира интерфейс за създаване на обекти, но оставя на подкласовете да решат кой клас да инстанцират. Това е ключово за **Dependency Injection**.

```cpp
class Creator {
public:
    virtual std::unique_ptr<Product> createProduct() = 0;
};
```

## 3. Структурни Шаблони (Structural Patterns)

### 3.1. Adapter (Адаптер)
Прави два несъвместими интерфейса да работят заедно. Пример: Имате стар клас `LegacyRectangle` и нов интерфейс `IShape`. Адаптерът обвива `LegacyRectangle` и го представя като `IShape`.

### 3.2. PIMPL (Pointer to Implementation)
Това е специфичен за C++ идиом (наричан още "Cheshire Cat").
*   **Проблем:** Промяна в `private` полетата на клас в `.h` файл изисква рекомпилация на всички файлове, които го включват.
*   **Решение:** Изнесете всички `private` данни в отделна структура (`struct Impl`) и дръжте само указател към нея в главния клас.
    ```cpp
    class Widget {
        struct Impl; // Forward declaration
        std::unique_ptr<Impl> pImpl;
    public:
        Widget();
        ~Widget();
    };
    ```
Това драстично намалява времето за компилация (Compilation Firewall) и осигурява бинарна съвместимост (ABI stability).

## 4. Поведенчески Шаблони (Behavioral Patterns)

### 4.1. Observer (Наблюдател)
Един обект (Subject) променя състоянието си и автоматично уведомява всички зависими обекти (Observers).
*   **C++ Предизвикателство:** Как да избегнем висящи указатели, ако Наблюдателят бъде изтрит преди Субекта?
*   **Решение:** Използвайте `std::weak_ptr` в списъка с абонати. Ако `weak_ptr::lock()` върне `nullptr`, значи наблюдателят вече не съществува и го премахваме от списъка.

### 4.2. Strategy (Стратегия)
Позволява да изберете алгоритъм по време на изпълнение.
Пример: `Sorter` клас, който приема `ISortStrategy` (QuickSort, BubbleSort). В C++ това често се прави и по време на компилация чрез **Policies** (шаблони), което е по-бързо (няма виртуални функции).

## 5. RAII (Resource Acquisition Is Initialization)

Макар и да не е в книгата на GoF, това е **най-важният** шаблон в C++.
Идеята е проста: всеки ресурс (памет, файл, мутекс, мрежова връзка) трябва да бъде "притежаван" от обект в стека.
1.  **Конструктор:** Взима ресурса.
2.  **Деструктор:** Освобождава ресурса.

Тъй като C++ гарантира извикването на деструкторите (дори при изключения), RAII прави кода устойчив на грешки без нужда от `finally` блокове.

---

## 6. Професионални съвети: Over-engineering

Най-честата грешка е да се опитвате да вкарате шаблони навсякъде.
*   **KISS (Keep It Simple, Stupid):** Не правете Factory, ако едно просто `new` върши работа.
*   **YAGNI (You Ain't Gonna Need It):** Не добавяйте гъвкавост (като Strategy), ако нямате поне два различни алгоритъма.

---

## 7. Професионално обобщение

*   Шаблоните са речник за комуникация ("Това е Singleton").
*   PIMPL е задължителен за големи библиотеки (напр. Qt, OpenCV).
*   RAII е религията на C++.
*   Предпочитайте шаблони на компилацията (Templates/Policies) пред шаблони на изпълнението (Virtual functions), когато скоростта е критична.
