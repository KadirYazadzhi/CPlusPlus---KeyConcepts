# Масиви (Arrays) в C++ - Пълно техническо ръководство

## 1. Въведение: Гръбнакът на цифровия свят

Масивът е най-фундаменталната, примитивна и същевременно най-мощна структура от данни в компютърните науки. В света на C++, където контролът над хардуера е от първостепенно значение, масивите не са просто контейнери; те са директно отражение на начина, по който компютърната памет е организирана.

Масивът представлява **последователност от обекти от един и същи тип**, съхранявани в **непрекъснат (contiguous)** блок от физическата памет. Няма "дупки", няма метаданни между елементите. Само чисти данни.

---

## 2. Физическото ниво: Защо масивите са толкова бързи?

### 2.1. Аритметика на адресите (O(1))
Когато дефинирате `int a[5]`, вие заемате точно 20 байта (5 * 4), разположени един след друг. Това позволява на хардуера да прави чудеса.
За да достъпи `a[i]`, процесорът не "търси" елемента. Той не обхожда списък. Той изчислява адреса му чрез проста формула:

```text
Адрес_на_елемент = Базов_адрес + (Индекс * sizeof(Тип))
```

Тази операция се извършва за константно време **O(1)** и често се изпълнява от специализиран модул в процесора (AGU - Address Generation Unit) паралелно с други инструкции.

### 2.2. Кеш Локалност (Cache Locality) и Prefetching
Това е тайната на скоростта в модерния хардуер.
*   **Spatial Locality:** Когато процесорът зареди `a[0]` в L1 кеша, той не зарежда само тези 4 байта. Той зарежда цяла "кеш линия" (обикновено 64 байта). Това означава, че `a[1]`, `a[2]` и т.н. вече са в кеша преди дори да сте ги поискали.
*   **Hardware Prefetching:** CPU разпознава шаблони на достъп. Ако започнете да четете `a[0]`, `a[1]`, `a[2]`, процесорът предсказва, че ще искате `a[3]` и го изтегля от RAM паметта предварително.

Списъците (`std::list`) и дърветата (`std::set`) са разпръснати из паметта и убиват тази оптимизация, водейки до скъпи "Cache Misses".

## 3. Декларация, Инициализация и Памет

### 3.1. Статични масиви (Stack Allocated)
Живеят в стека (stack). Те са "автоматични" променливи.
*   **Предимство:** Алокацията е мигновена (просто преместване на stack pointer-а). Няма нужда от `new`/`delete`.
*   **Недостатък:** Размерът трябва да е известен по време на компилация (`constexpr`). Ограничени са от размера на стека (обикновено няколко MB).

```cpp
int board[8][8]; // Неинициализиран (съдържа "боклук" от паметта)
int scores[10] = {100, 200, 300}; // Първите 3 са зададени, останалите 7 стават 0
int autoSize[] = {1, 2, 3, 4}; // Размерът е 4, компилаторът го разбира сам
```

### 3.2. Динамични масиви (Heap Allocated)
Заделят се в хийпа (heap).
*   **Предимство:** Размерът се определя по време на изпълнение (runtime). Могат да бъдат огромни (GBs).
*   **Недостатък:** Бавна алокация (търсене на свободно място). Изисква ръчно управление.

```cpp
size_t n;
std::cin >> n;
int* bigData = new int[n]; // Връща указател към първия елемент
// ... работа ...
delete[] bigData; // ⚠️ ЗАДЪЛЖИТЕЛНО: delete[], не delete!
```

## 4. Феноменът "Array-to-Pointer Decay"

В C++, масивът не е "обект" в смисъла на Java или C#. Името на масива е специален идентификатор, който при най-малкия повод "деградира" (decays) до **указател към първия си елемент**.

```cpp
void func(int* p) { ... }

int arr[5] = {10, 20, 30, 40, 50};
func(arr); // Тук arr автоматично става &arr[0]
```

**Къде НЕ става decay:**
1.  **`sizeof(arr)`:** Връща общия размер в байтове (напр. 20), а не размера на указател (8). *Само ако е в същия scope!*
2.  **`&arr`:** Връща указател към **целия масив** (`int (*)[5]`), а не `int*`. Разликата е в типа и аритметиката – ако добавите 1 към този указател, той ще прескочи целия масив (20 байта), а не 4.
3.  **`decltype(arr)`:** Връща типа `int[5]`.

## 5. Масиви и Функции: Капаните

Начинаещите често пишат това:
```cpp
void printSize(int arr[10]) { // Числото 10 е ЛЪЖА. Компилаторът го игнорира.
    std::cout << sizeof(arr); // Извежда 8 (размер на pointer), НЕ 40!
}
```
Параметърът `int arr[]` или `int arr[10]` във функция е абсолютно еквивалентен на `int* arr`. Информацията за размера се губи безвъзвратно.

**Правилните подходи:**
1.  **C-Style:** Подаване на размер отделно.
    ```cpp
    void process(int* arr, size_t size);
    ```
2.  **Template (запазва размера):**
    ```cpp
    template <size_t N>
    void process(int (&arr)[N]) { /* N е налично тук */ }
    ```
3.  **Modern C++ (std::span):** Най-доброто решение от C++20.
    ```cpp
    void process(std::span<int> data);
    ```

## 6. Модерният C++: `std::array` и `std::vector`

Суровите масиви (`int a[5]`) се наричат "C-Style arrays". В C++ се препоръчва използването на обекти-обвивки.

### 6.1. `std::array<T, N>` (Zero Overhead)
Това е буквално C-масив, увит в структура. Няма никаква загуба на производителност.
*   **Предимства:**
    *   Помни своя `.size()`.
    *   Не decay-ва до указател случайно.
    *   Има стойностна семантика (може да се присвоява `a = b`).
    *   Поддържа итератори (`begin()`, `end()`) за работа с `std::sort`, `std::find`.

### 6.2. `std::vector<T>`
Де факто стандартът за динамични масиви.
*   Управлява паметта автоматично (RAII).
*   Расте автоматично (`push_back`).
*   Гарантира непрекъсната памет (съвместим с C API).

---

## 7. Bounds Checking (Проверка на границите)

C++ е език, който ви позволява да се простреляте в крака, ако поискате. Достъпът `arr[i]` **НИКОГА** не проверява дали `i` е валиден индекс.
*   `arr[-1]` или `arr[1000]` ще прочете/запише памет извън масива.
*   **Резултат:** Undefined Behavior. Може да крашне, може да промени друга променлива, може да отвори дупка в сигурността (Buffer Overflow exploit).

**Сигурен достъп:**
При `std::vector` и `std::array`, методът `.at(i)` прави проверка и хвърля изключение `std::out_of_range`, ако сбъркате. Операторът `[]` не го прави заради скоростта.

## 8. Асемблерен поглед (x86-64)

Достъпът до масив е изключително проста инструкция.
```cpp
int x = arr[i];
```
В асемблер това често е **една** инструкция:
```asm
mov eax, DWORD PTR [rdi + rsi*4]
```
*   `rdi`: Базов адрес на `arr`.
*   `rsi`: Стойността на `i`.
*   `4`: Размер на `int` (scale factor).
Това демонстрира силата на "Scale Index Byte" (SIB) адресирането в x86.

---

## 9. Професионално обобщение

1.  **Използвайте `std::vector`** по подразбиране за всичко динамично.
2.  **Използвайте `std::array`** за малки, фиксирани буфери.
3.  **Избягвайте `new[]` и `delete[]`** – те са податливи на memory leaks.
4.  **Никога** не разчитайте на `sizeof` върху параметър на функция.
5.  Помнете, че масивите са царете на кеша (Cache Kings). Всяка оптимизация на производителността започва от правилната употреба на масиви.
