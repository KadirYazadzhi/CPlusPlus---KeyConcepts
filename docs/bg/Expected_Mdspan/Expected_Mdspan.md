# std::expected и std::mdspan (C++23) - Пълно техническо ръководство

## 1. Въведение: Революцията на C++23

Стандартът C++23 не е просто малка актуализация; той въвежда инструменти, които фундаментално променят начина, по който се справяме с грешките и как достъпваме данни в многомерни пространства. Тази глава изследва двете най-значими попълнения: `std::expected` (алтернатива на изключенията) и `std::mdspan` (абстракция над многомерни масиви).

---

## 2. std::expected: Модерната обработка на грешки

### 2.1. Философията на "Предвидимия код"
В продължение на десетилетия C++ програмистите бяха разделени между два лагера: използване на изключения (`try-catch`) или използване на кодове за грешка (C-style). Изключенията са мощни, но имат непредвидима цена за производителността (RTTI, stack unwinding). Кодовете за грешка са бързи, но лесни за игнориране.

`std::expected<T, E>` е **Sum Type** (подобно на `std::variant`), който съдържа или очаквания резултат от тип `T`, или обект за грешка от тип `E`. Той принуждава програмиста да провери резултата, преди да го използва.

### 2.2. Защо std::expected е по-добър от std::optional?
`std::optional` ни казва само, че нещо липсва. `std::expected` ни казва **защо** липсва.

```cpp
#include <expected>
#include <string>
#include <fstream>

enum class FileError { NotFound, AccessDenied, DiskFull };

std::expected<std::string, FileError> readFile(std::string path) {
    if (!std::filesystem::exists(path)) 
        return std::unexpected(FileError::NotFound); // Връщаме грешка
    
    // ... четене ...
    return "Content of the file..."; // Връщаме успех
}

void process() {
    auto result = readFile("config.json");
    if (result) {
        std::cout << *result; // Достъп до T
    } else {
        std::cerr << "Error code: " << (int)result.error(); // Достъп до E
    }
}
```

### 2.3. Монадични операции (Monadic Operations)
C++23 добавя функционални методи към `std::expected`, които позволяват "верижно" свързване на операции без досадни `if` проверки (Railway Oriented Programming):

*   **`.and_then(func)`**: Продължи със следващата стъпка, само ако текущата е успешна.
*   **`.or_else(func)`**: Справи се с грешката или я трансформирай.
*   **`.transform(func)`**: Промени успешната стойност (напр. от `string` към `int`), но запази грешката, ако има такава.

```cpp
auto finalResult = readFile("data.txt")
    .and_then(parseJson)       // Само ако файлът е прочетен
    .and_then(extractUserId)   // Само ако JSON-ът е валиден
    .or_else(logError);        // Ако нещо се счупи по веригата
```

### 2.4. Анализ на производителността
`std::expected` е "zero-cost" абстракция в сравнение с изключенията. Той не изисква Stack Unwinding и е напълно детерминистичен.
*   **Памет:** Заема `max(sizeof(T), sizeof(E)) + bool`.
*   **Скорост:** Връщането на `std::expected` е толкова бързо, колкото връщането на структура по стойност. RVO (Return Value Optimization) работи перфектно.
*   **Real-time:** В системи за реално време (гейм енджини, embedded), където изключенията са забранени, това е новият стандарт.

## 3. std::mdspan: Многомерни изгледи (Views)

### 3.1. Проблемът с многомерните масиви
Традиционно, работата с 2D или 3D данни в C++ изискваше или вложени вектори (`vector<vector<T>>`), което е кошмар за кеша, или плоски масиви с ръчно изчисляване на индекси (`index = z*XY + y*X + x`).

`std::mdspan` е **непритежаващ изглед** (non-owning view), който превръща всеки плосък блок памет в многомерна структура.

### 3.2. Архитектура на mdspan
Той се дефинира чрез четири компонента:
1.  **Element Type:** Типът на данните (напр. `double`).
2.  **Extents:** Размерите на измеренията. Може да има статични (по време на компилация) и динамични измерения.
3.  **Layout Mapping:** Как се подреждат данните:
    *   `std::layout_right` (C-style / Row-major): Последното измерение е непрекъснато.
    *   `std::layout_left` (Fortran-style / Column-major): Първото измерение е непрекъснато.
4.  **Accessor:** Как се достъпват данните (напр. за SIMD векторизация или GPU памет).

### 3.3. Пример за 2D обработка
```cpp
#include <mdspan>
#include <vector>

void processImage(std::vector<float>& buffer, int width, int height) {
    // Създаваме 2D изглед над 1D вектора
    // std::dextents<int, 2> означава 2 динамични измерения
    auto image = std::mdspan(buffer.data(), height, width);

    for (int i = 0; i < image.extent(0); ++i) { // Редове
        for (int j = 0; j < image.extent(1); ++j) { // Колони
            // Новият оператор [] приема много аргументи!
            image[i, j] *= 1.1f; 
        }
    }
}
```

### 3.4. Slicing и Submdspan
Една от най-мощните функции е `std::submdspan`. Тя позволява вземане на "парчета" от данните без копиране.
Можете да вземете под-матрица, конкретен ред от 3D тензор или диагонал за **O(1)** време.

```cpp
auto subregion = std::submdspan(image, std::pair{10, 20}, std::pair{10, 20});
// subregion е нов, по-малък mdspan, сочещ към същата памет.
```

## 4. Системно ниво: Какво вижда процесорът?

### 4.1. Асемблерен анализ на mdspan
Компилаторът е наясно с математиката на `mdspan`. Когато напишете `image[i, j]`, той генерира инструкции за адресна аритметика (`base + i*stride + j`), които са идентични с ръчно написания C код.
Предимството е, че `mdspan` позволява на компилатора да приложи **SIMD** оптимизации автоматично, защото знае, че паметта е подредена (ако ползвате правилния Layout).

### 4.2. Ефектът върху Кеша
Използвайки `std::layout_right` (Row-major) при обхождане по редове, вие гарантирате **Spatial Locality**. Процесорът зарежда цяла кеш линия и следващите елементи са вече там. Вложените вектори никога не могат да постигнат това.

## 5. Сравнение на методите за обработка на грешки

| Метод | Предимства | Недостатъци |
| :--- | :--- | :--- |
| **Exceptions** | Чист код, не се предава ръчно | Недетерминистичен, бавен при грешка, изисква RTTI |
| **Error Codes** | Много бърз, предвидим | Труден за поддръжка, лесен за игнориране, няма контекст |
| **std::expected** | Бърз, безопасен, монадичен | Увеличава размера на връщания обект |

---

## 6. Професионално обобщение

1.  **std::expected:** Използвайте го за логически грешки (File Not Found, Invalid Input), които са част от нормалния работен процес.
2.  **Exceptions:** Запазете ги за наистина "изключителни" събития (Out of Memory, Hardware Failure), които не могат да се обработят локално.
3.  **std::mdspan:** Стандартът за научни изчисления, графика, AI тензори и обработка на изображения. Никога повече не пишете `vec[y * w + x]` ръчно.
4.  C++23 прави езика по-близък до Python/NumPy по леснота на писане, но запазва скоростта на асемблер.
