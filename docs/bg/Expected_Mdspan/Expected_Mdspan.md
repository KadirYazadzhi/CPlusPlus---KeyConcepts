# std::expected и std::mdspan (C++23) - Пълно техническо ръководство

## 1. Въведение: Революцията на C++23
Стандартът C++23 не е просто малка актуализация; той въвежда инструменти, които фундаментално променят начина, по който се справяме с грешките и как достъпваме данни в многомерни пространства. Тази глава изследва двете най-значими попълнения: `std::expected` (алтернатива на изключенията) и `std::mdspan` (абстракция над многомерни масиви).

---

## 2. std::expected: Модерната обработка на грешки

### 2.1. Философията на "Предвидимия код"
В продължение на десетилетия C++ програмистите бяха разделени между два лагера: използване на изключения (`try-catch`) или използване на кодове за грешка (C-style). Изключенията са мощни, но имат непредвидима цена за производителността (RTTI, stack unwinding). Кодовете за грешка са бързи, но лесни за игнориране.

`std::expected<T, E>` е **Sum Type** (подобно на `std::variant`), който съдържа или очаквания резултат от тип `T`, или обект за грешка от тип `E`.

### 2.2. Защо std::expected е по-добър от std::optional?
`std::optional` ни казва само, че нещо липсва. `std::expected` ни казва **защо** липсва.

```cpp
#include <expected>
#include <string>

enum class FileError { NotFound, AccessDenied, DiskFull };

std::expected<std::string, FileError> readFile(std::string path) {
    if (!exists(path)) return std::unexpected(FileError::NotFound);
    return "Content of the file...";
}
```

### 2.3. Монадични операции (Monadic Operations)
C++23 добавя функционални методи към `std::expected`, които позволяват "верижно" свързване на операции без `if` проверки:
*   `.and_then()`: Продължи, ако има стойност.
*   `.or_else()`: Справи се с грешката.
*   `.transform()`: Трансформирай стойността, ако съществува.

### 2.4. Анализ на производителността
`std::expected` е "zero-cost" абстракция в сравнение с изключенията. Той не изисква Stack Unwinding и е напълно детерминистичен. В системи за реално време (Real-time) това е предпочитаният начин за обработка на логически грешки.

## 3. std::mdspan: Многомерни изгледи (Views)

### 3.1. Проблемът с многомерните масиви
Традиционно, работата с 2D или 3D данни в C++ изискваше или вложени вектори (бавно, лош кеш), или плоски масиви с ръчно изчисляване на индекси (`index = z*XY + y*X + x`).

`std::mdspan` е **непритежаващ изглед** (non-owning view), който превръща всеки плосък блок памет в многомерна структура.

### 3.2. Архитектура на mdspan
Той се дефинира чрез четири компонента:
1.  **Element Type:** Типът на данните (напр. `double`).
2.  **Extents:** Размерите на измеренията (статични или динамични).
3.  **Layout Mapping:** Как се подреждат данните (Row-major, Column-major или потребителски).
4.  **Accessor:** Как се достъпват данните (напр. през отдалечена памет).

### 3.3. Пример за 2D обработка
```cpp
#include <mdspan>
#include <vector>

void processImage(std::vector<float>& buffer, int width, int height) {
    // Създаваме 2D изглед над 1D вектора
    auto image = std::mdspan(buffer.data(), height, width);

    for (int i = 0; i < image.extent(0); ++i) {
        for (int j = 0; j < image.extent(1); ++j) {
            image[i, j] *= 1.1f; // Използваме новия оператор [] с няколко аргумента!
        }
    }
}
```

### 3.4. Slicing и Submdspan
Една от най-мощните функции е възможността за вземане на "парчета" от данните без копиране. Можете да вземете под-матрица или конкретен ред от 3D тензор за O(1) време.

## 4. Системно ниво: Какво вижда процесорът?

### 4.1. Асемблерен анализ на mdspan
Компилаторът оптимизира `mdspan` до същите инструкции, които бихте написали ръчно. Предимството е, че `mdspan` гарантира правилното подравняване и позволява на компилатора да приложи **SIMD** оптимизации автоматично.

### 4.2. Ефектът върху Кеша
Използвайки `std::layout_right` (Row-major), вие гарантирате, че последователният достъп до елементите ще бъде кеш-ефективен. `mdspan` прави тези архитектурни решения явни и лесни за промяна.

## 5. Сравнение на методите за обработка на грешки

| Метод | Предимства | Недостатъци |
| :--- | :--- | :--- |
| **Exceptions** | Чист код, не се предава ръчно | Недетерминистичен, бавен при грешка |
| **Error Codes** | Много бърз, предвидим | Труден за поддръжка, лесен за игнориране |
| **std::expected** | Бърз, безопасен, монадичен | Увеличава размера на обекта (T + E) |

## 6. Професионално обобщение
*   Използвайте `std::expected` за логически грешки (бизнес логика).
*   Използвайте изключения за фатални системни грешки (out of memory).
*   Използвайте `std::mdspan` за всякакви научни изчисления, графика и AI.
*   C++23 прави езика по-близък до Python по леснота на писане (mdspan), но запазва скоростта на асемблер.
