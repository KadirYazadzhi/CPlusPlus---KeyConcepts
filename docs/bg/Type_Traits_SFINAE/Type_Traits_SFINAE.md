# Type Traits и SFINAE - Пълно техническо ръководство

## 1. Въведение: Интроспекция по време на компилация

C++ е статично типизиран език. Всичко е известно по време на компилация.
Но какво, ако искаме да напишем функция, която работи по един начин за числа (`int`, `float`) и по друг за обекти (`std::string`)?
В езици като Java/Python използваме `Reflection` по време на работа (което е бавно). В C++ използваме **Type Traits** (Характеристики на типовете) по време на компилация (което е бързо и има нулев overhead).

Type Traits са мета-функции: те приемат тип като аргумент (template parameter) и връщат друг тип или константа.

---

## 2. Библиотеката `<type_traits>`

Това е една от най-важните библиотеки за разработчици на шаблони (Template Libraries). Всички traits са структури, които имат статична константа `value`.

### 2.1. Проверки (Predicates)
Връщат `true` или `false`.
*   `std::is_integral<T>::value`: Дали е цяло число?
*   `std::is_pointer<T>::value`: Дали е указател?
*   `std::is_abstract<T>::value`: Дали е абстрактен клас?
*   `std::is_same<T, U>::value`: Дали двата типа са еднакви?

**Примерна имплементация на `is_same`:**
Как работи магията? Чрез специализация на шаблони.
```cpp
// Основен шаблон: Два типа са различни по подразбиране
template<typename T, typename U>
struct is_same { static const bool value = false; };

// Специализация: Ако двата типа са Т и Т (еднакви), стойността е true
template<typename T>
struct is_same<T, T> { static const bool value = true; };
```

### 2.2. Трансформации
Променят типа.
*   `std::remove_const<T>::type`: Маха `const`.
*   `std::add_pointer<T>::type`: Добавя `*`.
*   `std::decay<T>::type`: Превръща масив в пойнтър, функция в пойнтър, маха референции.

## 3. Исторически контекст: Andrei Alexandrescu

Книгата "Modern C++ Design" (2001) на Андрей Александреску положи основите на тази технология. Той показа как чрез шаблони могат да се реализират списъци от типове (Typelists) и сложни логически операции по време на компилация. Стандартната библиотека `<type_traits>` в C++11 е директен наследник на тези идеи.

## 4. SFINAE (Substitution Failure Is Not An Error)

Това е "черната магия" на C++.
Когато компилаторът се опитва да инстанцира шаблон, ако заместването на типа доведе до невалиден код (напр. достъп до несъществуващ тип `T::value_type`), компилаторът **не дава грешка**. Той просто си казва "Този шаблон не става" и продължава да търси друг overload.

### `std::enable_if`
Това е инструментът за управление на SFINAE. Той "включва" или "изключва" функции.

```cpp
// Версия 1: Само за числа
template <typename T>
typename std::enable_if<std::is_arithmetic<T>::value, T>::type
square(T x) { return x * x; }

// Версия 2: За всичко останало
// Ако подадем int, Версия 1 е валидна.
// Ако подадем string, Версия 1 е невалидна (enable_if няма ::type) и се маха от списъка с кандидати.
```

## 5. `if constexpr` (C++17): Краят на SFINAE?

Преди C++17, SFINAE беше единственият начин. Сега имаме `if constexpr`.
Това е условна конструкция, която се оценява по време на компилация.

```cpp
template <typename T>
void print(T value) {
    if constexpr (std::is_pointer_v<T>) {
        // Този блок се компилира САМО ако T е указател
        std::cout << "Pointer: " << *value << "\n";
    } else {
        // Този блок се компилира САМО ако T НЕ е указател
        std::cout << "Value: " << value << "\n";
    }
}
```
Ако подадете `int`, първият блок (с `*value`) се изхвърля напълно. Ако го нямаше `constexpr`, компилаторът щеше да даде грешка, че `int` не може да се дереферира.

## 6. Concepts (C++20): Бъдещето

Concepts заменят SFINAE и `enable_if` с чист, четим синтаксис.

```cpp
template <typename T>
concept Saveable = requires(T v) {
    v.save(); // Изискваме метод save()
};

template <Saveable T>
void process(T obj) {
    obj.save();
}
```
Ако подадете обект без `.save()`, грешката ще бъде четима: "T does not satisfy Saveable", вместо 100 реда template error logs.

## 7. Професионално обобщение

1.  **Оптимизация:** Използвайте `std::is_trivially_copyable`, за да избирате между `memcpy` (супер бързо) и copy constructor (бавно) във вашите контейнери.
2.  **Tag Dispatch:** Техника за избор на overload чрез празни структури (`std::true_type`). По-чисто от `enable_if`.
3.  **Модернизация:** Ако можете, използвайте `if constexpr` и `Concepts`. Оставете SFINAE и `enable_if` само за поддръжка на стари компилатори.
