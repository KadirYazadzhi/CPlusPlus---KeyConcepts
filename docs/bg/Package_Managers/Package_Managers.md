# Пакетни Мениджъри в C++ (Conan & Vcpkg) - Пълно техническо ръководство

## 1. Въведение: Краят на "Dependency Hell"

Години наред C++ изоставаше от езици като Python (pip), Node.js (npm) или Rust (cargo). Инсталирането на библиотека означаваше:
1.  Търсене на уебсайта на библиотеката.
2.  Изтегляне на `.zip`.
3.  Борба с тяхната билд система (Make, Autotools, SCons...).
4.  Ръчно копиране на `.lib` и `.h` файлове в системни папки.
5.  Повтаряне на всичко това за всяка нова версия и за всеки колега в екипа.

Това вече е минало. Днес имаме два мощни, индустриални стандарта: **Vcpkg** (от Microsoft) и **Conan** (от JFrog).

---

## 2. Vcpkg: Простота и Интеграция

Vcpkg е "Source-based" пакетен мениджър. Неговата философия е: "Дай ми рецептата, аз ще си го сготвя (компилирам) сам". Това гарантира, че всички библиотеки са компилирани с **точно същия компилатор и флагове** като вашия проект, избягвайки проблемите с несъвместими ABI (Application Binary Interface).

### 2.1. Manifest Mode (`vcpkg.json`)
Това е модерният начин на работа. В корена на проекта си създавате файл:

```json
{
  "name": "super-engine",
  "version-string": "1.0.0",
  "dependencies": [
    "fmt",
    "nlohmann-json",
    {
      "name": "sdl2",
      "features": ["vulkan"]
    }
  ]
}
```

### 2.2. Интеграция с CMake
Просто добавяте един флаг при конфигурацията:

```bash
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=[path/to/vcpkg]/scripts/buildsystems/vcpkg.cmake
```
Vcpkg автоматично ще прочете `vcpkg.json`, ще изтегли сорсовете, ще ги компилира и ще ги направи достъпни за `find_package()`.

### 2.3. Overlay Ports (Къстъмизация)
Ако искате да пачнете библиотека (напр. да промените нещо в SDL2), можете да създадете "Overlay Port". Копирате рецептата на библиотеката в папка `custom-ports`, променяте я и казвате на Vcpkg да ползва нея.

## 3. Conan: Гъвкавост и Бинарни Кешове

Conan е по-сложен, но и по-мощен. Той е децентрализиран и поддържа **Binary Binaries**.
Това е критично за големи компании. Вместо всеки програмист да компилира Boost (което отнема 20 минути), CI сървърът го компилира веднъж, качва го в **Artifactory** сървър, и всички програмисти просто теглят готовия бинар за 5 секунди.

### 3.1. Рецептата (`conanfile.py`)
Conan използва Python за конфигурация, което дава безгранична сила.

```python
from conan import ConanFile
from conan.tools.cmake import cmake_layout

class MyGame(ConanFile):
    settings = "os", "compiler", "build_type", "arch"
    generators = "CMakeDeps", "CMakeToolchain"

    def requirements(self):
        self.requires("fmt/9.1.0")
        self.requires("sfml/2.5.1")

    def layout(self):
        cmake_layout(self)
```

### 3.2. Профили (Profiles)
Conan използва "профили", за да знае кой сте.
`conan profile detect` създава дефолтен профил (напр. Linux, GCC 11, x86_64).
Можете да имате различни профили: `linux_release`, `windows_debug`, `android_arm`.

### 3.3. Workflow
1.  `conan install . --build=missing` -> Тегли зависимостите и генерира CMake файлове.
2.  `cmake --preset conan-release` -> Билдва проекта ви.

## 4. Сравнение: Кой да избера?

| Характеристика | Vcpkg | Conan |
| :--- | :--- | :--- |
| **Основна философия** | Build form source (Леснота) | Binary management (Мащаб) |
| **Сървър** | Няма (Git базиран) | Conan Center / Artifactory |
| **Интеграция** | Toolchain файл | Генератори |
| **Къстъмизация** | Overlay ports | Python скриптове |
| **Корпоративна среда** | Добра | Отлична (Private Packages) |

## 5. Как да пакетираме собствените си библиотеки?

Истинската сила идва, когато започнете да разделяте собствения си монолитен проект на малки пакети.
*   Екип А разработва `PhysicsEngine`. Пакетира го с Conan/Vcpkg.
*   Екип Б разработва `GameLogic`. Те просто казват `requires("PhysicsEngine/1.2")`.

Това позволява **версиониране**. Екип Б може да стои на версия 1.2, докато Екип А вече работи по версия 2.0, без да чупи билда на колегите си.

## 6. Професионално обобщение

1.  **Никога не инсталирайте системно:** Забравете за `sudo apt-get install libboost-dev`. Системните библиотеки са стари и конфликтни.
2.  **Започнете с Vcpkg:** Ако сте Open Source проект или малък екип, Vcpkg е "Plug and Play".
3.  **Минете към Conan:** Ако сте голяма фирма с CI/CD пайплайни, множество платформи и нужда от строг контрол над бинарите.
4.  **Vendoring:** Като последна мярка (ако нямате интернет), можете да копирате сорса на библиотеките във вашия Git (Vendoring), но това утежнява репозиторито.
