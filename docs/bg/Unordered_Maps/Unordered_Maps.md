# Неподредени Карти (Unordered Maps) в C++ - Пълно техническо ръководство

## 1. Въведение: Революцията на скоростта
`std::unordered_map` (въведен в C++11) промени начина, по който C++ програмистите работят с големи обеми данни. Докато традиционният `std::map` залага на подредбата, `std::unordered_map` залага на **екстремната скорост**. Той е реализиран чрез **Хеш таблица**, което го прави идеалния избор за кеш системи, речници и всякакви сценарии, където търсенето е най-честата операция.

---

## 2. Как работи Хеш таблицата? (Under the Hood)

### 2.1. Хеширане и "Кофи" (Buckets)
Процесът е следният:
1.  Взима се ключът (напр. "User123").
2.  Прилага се **Хеш функция**, която превръща низа в голямо число.
3.  Това число се разделя по модул на броя на вътрешните "кофи" (buckets).
4.  Стойността се записва в съответната кофа.

### 2.2. Колизии (Collisions)
Когато два различни ключа произведат един и същ хеш (или попаднат в една и съща кофа), се получава колизия. C++ се справя с това чрез **Separate Chaining** – елементите в кофата се подреждат в свързан списък.

---

## 3. Производителност: Среден срещу Най-лош случай

*   **Средна сложност (Average):** **O(1)**. Търсенето е мигновено, независимо дали имате 100 или 100 милиона елемента.
*   **Най-лош случай (Worst Case):** **O(N)**. Ако хеш функцията е лоша и всички елементи попаднат в една и съща кофа, таблицата се изражда в списък.

---

## 4. Управление на "Натоварването" (Load Factor)
Професионалното използване на `unordered_map` изисква разбиране на два параметъра:
1.  **Load Factor:** Съотношението `size / bucket_count`. Ако то надвиши определен праг (обикновено 1.0), таблицата прави **Rehash**.
2.  **Rehashing:** Заделя се нова, по-голяма памет и всички елементи се преизчисляват и местят. Това е скъпа операция (**O(N)**).

**Съвет:** Ако знаете броя на елементите, използвайте `reserve()`, за да избегнете Rehash.

---

## 5. Изисквания към ключа (Custom Keys)
За да използвате свой клас като ключ, трябва да предоставите две неща:
1.  **operator==**: За да може таблицата да различава обектите при колизия.
2.  **Hash Function**: Специализация на `std::hash`.

```cpp
struct Point { int x, y; };

namespace std {
    template <>
    struct hash<Point> {
        size_t operator()(const Point& p) const {
            return hash<int>()(p.x) ^ hash<int>()(p.y);
        }
    };
}
```

---

## 6. Сравнителен анализ: Map срещу Unordered Map

| Характеристика | std::map | std::unordered_map |
| :--- | :--- | :--- |
| **Структура** | Red-Black Tree | Hash Table |
| **Скорост** | O(log N) | O(1) средно |
| **Ред** | Сортиран | Хаотичен |
| **Памет** | По-малко (на елемент) | Повече (заради кофите) |
| **Стабилност** | Предвидима | Зависи от хеш функцията |

---

## 7. Професионално обобщение
*   Използвайте `unordered_map` винаги, когато търсите скорост и не ви трябва сортиран ред.
*   Внимавайте с итераторите – те са **Forward Iterators** (могат само напред) и се инвалидизират при Rehash.
*   За критични системи, проектирайте внимателно хеш функцията си, за да избегнете атаки тип "Hash DoS".
