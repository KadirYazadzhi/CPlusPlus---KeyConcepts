# Референции (References) в C++

## 1. Онтология и Вътрешна Архитектура

### 1.1. Дефиниция според Стандарта

Според стандарта на C++, референцията не е обект. Тя е **alias** (друго име) за съществуващ обект или функция. Тъй като не е обект, фундаментално тя няма адрес.

* **Концептуално:** Референцията е запис в символните таблици (symbol tables) на компилатора, който се свързва със същия адрес в паметта като оригиналната променлива.

* **Физически (Implementation detail):** В повечето случаи, когато референцията трябва да съществува в runtime (например като член на клас или параметър на функция, която не е inline), компилаторът я реализира като **постоянен указател** (`T* const`).

### 1.2. Парадоксът на паметта

Една от най-големите заблуди е свързана с размера на референцията.

```cpp
struct S {
    char& r; // В паметта това заема 8 байта (на 64-bit OS), точно колкото указател.
};

char c = 'a';
char& ref = c;

// sizeof(ref) връща 1 (размера на char), а не 8!

```

**Обяснение:** Операторът `sizeof` винаги връща размера на *реферирания тип*, а не на самата референция. Няма легален начин в C++ да получите "размера на референцията" или "адреса на референцията" директно. Взимането на адрес (`&ref`) връща адреса на обекта `c`.

## 2. Категории Стойности (Value Categories) и Референции

За да разберем референциите в дълбочина, трябва да разберем таксономията на стойностите в C++17/20:

1. **lvalue (locator value):** Обект, който има идентичност (име) и адрес в паметта.
2. **prvalue (pure rvalue):** Временна стойност, която няма идентичност (напр. литерал `5`, резултат от `x + y`).
3. **xvalue (eXpiring value):** Обект, който има идентичност, но е маркиран като "готов за преместване" (напр. резултат от `std::move(x)`).
4. **glvalue (generalized lvalue):** Обект с идентичност (lvalue + xvalue).
5. **rvalue:** Обект, от който можем да "крадем" ресурси (prvalue + xvalue).

### 2.1. L-value References (`T&`)

Могат да се свързват само с **glvalue** (неща с адрес).

* **Употреба:** Модификация на съществуващи обекти.

### 2.2. Const L-value References (`const T&`)

Могат да се свързват с **всичко** (glvalue, prvalue, xvalue).

* **Механизъм "Lifetime Extension":** Когато `const T&` се свърже с временен обект (prvalue), животът на този временен обект се удължава до края на scope-а на референцията. Това се прави чрез скрита променлива в стека.

```cpp
const int& r = 5 + 5; 
// Компилаторът генерира:
// int __temp = 10;
// const int& r = __temp;

```

### 2.3. R-value References (`T&&`)

Въведени в C++11, те могат да се свързват само с **rvalue** (prvalue и xvalue).

* **Цел:** Да се детектират обекти, които са на път да бъдат унищожени, за да се откраднат техните ресурси (Move Semantics).

## 3. Reference Collapsing и Forwarding References

Това е една от най-сложните теми в шаблонното метапрограмиране.

### 3.1. Правила за свиване (Collapsing Rules)

В C++ е забранено да дефинирате референция към референция директно (`int& & x` е грешка). Но при шаблони (`template`) или `typedef`/`using`, това често се случва автоматично. Компилаторът прилага следните правила (Reference collapsing):

* `T&` + `&`   **`T&`**
* `T&` + `&&`  **`T&`**
* `T&&` + `&`  **`T&`**
* `T&&` + `&&`  **`T&&`**

**Правило:** Ако има поне едно `&`, резултатът е l-value reference. Само `&&` + `&&` дава r-value reference.

### 3.2. Universal References (Forwarding References)

Термин, въведен от Скот Майерс (Scott Meyers), официално наричан "Forwarding references" в стандарта.

Синтаксисът `T&&` в шаблонна функция **НЕ винаги** означава r-value reference.

```cpp
template<typename T>
void wrapper(T&& arg) { ... }

```

Ако `T` трябва да се дедуцира (deduced type):

1. Ако подадем **lvalue** (напр. `int x`), `T` се дедуцира като `int&`. Тогава `arg` става `int& &&`, което колапсира до **`int&`**.
2. Ако подадем **rvalue** (напр. `5`), `T` се дедуцира като `int`. Тогава `arg` става **`int&&`**.

Това позволява на `std::forward<T>` да работи: той запазва категорията на стойността (lvalue или rvalue) при предаване нататък.

## 4. Дълбока дисекция на std::move и std::forward

### 4.1. std::move е лъжа

`std::move` не мести нищо. Той не генерира машинен код за местене на памет.

* **Какво прави:** Това е просто `static_cast`, който превръща всеки аргумент в **xvalue** (r-value reference). Това казва на компилатора: *"Третирай този обект като временен, можеш да ползваш move constructor-а му"*.

**Имплементация (опростена):**

```cpp
template<typename T>
typename std::remove_reference<T>::type&& move(T&& t) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(t);
}

```

### 4.2. std::forward - Условният cast

Използва се заедно с Forwarding References. Той казва: *"Cast-ни към r-value само ако оригиналният аргумент е бил r-value"*.

## 5. Референции и Type Deduction (auto & decltype)

Правилата за `auto` са критични при работа с референции.

```cpp
int x = 10;
int& rx = x;

auto a = rx;  // a e int (копие), референтността се губи!
auto& b = rx; // b e int& (нова референция към x)

const int cx = 20;
auto c = cx;  // c e int (const се губи при копиране)
const auto& d = cx; // d e const int&

```

**decltype** работи различно:

* `decltype(var)` връща точния тип на променливата.
* `decltype(expr)` (ако е израз):
* Ако изразът връща lvalue  добавя `&` (напр. `decltype((x))` е `int&`).
* Ако изразът връща prvalue  чист тип.
* Ако изразът връща xvalue  добавя `&&`.



## 6. Специални случаи и "Undefined Behavior" (UB)

### 6.1. Dangling References (Висящи референции)

Това е най-честият източник на бъгове.

```cpp
const int& getBadRef() {
    int local = 5;
    return local; // UB! local се унищожава, връщаме адрес към стека, който вече е невалиден.
}

```

### 6.2. Reference Slicing (Отрязване)

При полиморфизъм, ако присвоите обект от дъщерен клас на променлива от базов клас (не референция), се случва "Slicing". Ако ползвате референция, полиморфизмът работи.

```cpp
class Base { ... };
class Derived : public Base { ... };

Derived d;
Base b = d;  // Slicing! Частта на Derived се изрязва. Копира се само Base частта.
Base& br = d; // Няма Slicing. br сочи към пълния обект d. V-table работи.

```

### 6.3. Null Reference?

В стандарта на C++ **референцията не може да бъде null**. Няма синтаксис за `int& r = nullptr`.
Въпреки това, чрез зъл код (UB), може да се постигне:

```cpp
int* p = nullptr;
int& r = *p; // Undefined Behavior, но технически създава "null reference".
             // Всеки опит за ползване на 'r' ще крашне програмата.

```

## 7. std::reference_wrapper`<T>`

Референциите имат недостатъци: не са CopyAssignable (не могат да се "пренасочват") и не могат да бъдат в масиви.
`std::reference_wrapper` (от `<functional>`) решава това. Той е обект, който:

1. Държи указател вътрешно.
2. Има оператор за преобразуване към `T&`.
3. Може да се пренасочва.
4. Може да се слага в `std::vector<std::reference_wrapper<T>>`.

## 8. Асемблерен анализ (x86-64)

Нека сравним указател и референция на ниво инструкции.

**C++:**

```cpp
void by_ptr(int* p) { *p = 10; }
void by_ref(int& r) { r = 10; }

```

**GCC Output (-O2):**

```assembly
; void by_ptr(int* p)
by_ptr(int*):
    mov DWORD PTR [rdi], 10  ; rdi държи адреса, пишем 10 директно в паметта
    ret

; void by_ref(int& r)
by_ref(int&):
    mov DWORD PTR [rdi], 10  ; Абсолютно същият код!
    ret

```

**Извод:** За процесора няма разлика. Референцията е **синтактична захар** с по-строги правила за безопасност на ниво компилатор (type safety check), но генерира идентичен машинен код като указателя.

## 9. Таблица за вземане на решения

| **Ситуация** | **Решение** | **Защо?** |
| --- | --- | --- |
| **Вграден тип (int, bool, double)** | Pass by Value (`int x`) | Референцията е указател (8 байта), `int` е 4 байта. Индирекцията е по-бавна. |
| **Обект (std::string, vector, class)** | `const T&` | Избягва дълбоко копиране. |
| **Трябва да променям обекта** | `T&` | Позволява output параметри. |
| **Обектът може да липсва (optional)** | `T*` (или `std::optional`) | Референцията не може да е null. |
| **Move Constructor / Setter** | `T&&` | За да откраднем ресурсите. |
| **Шаблони / Forwarding** | `T&&` (Universal Ref) | За да работи Perfect Forwarding. |
