# Мултикарти (Multimaps) в C++ - Пълно техническо ръководство

## 1. Въведение: Релацията "Едно към Много"

Стандартната карта (`std::map`) изисква строга уникалност на ключа. В реалния свят обаче често ни трябва структура, която позволява един ключ да бъде свързан с множество стойности.

**Примери от реалния свят:**
*   **Библиотека:** Един автор -> Много книги.
*   **Училище:** Един ученик -> Много оценки.
*   **Файлова система:** Едно име на файл -> Много пътища (дубликати в различни папки).
*   **DNS Сървър:** Едно домейн име -> Много IP адреси.

`std::multimap` е асоциативният контейнер, създаден точно за тези сценарии.

---

## 2. Архитектура: Сортирано дърво с дубликати

Подобно на `map`, мултикартата използва **Червено-черно дърво (Red-Black Tree)**.
Ключовата разлика е в алгоритъма за вмъкване – той не проверява за наличието на ключа, а просто вмъква новата двойка на правилната позиция спрямо реда.

### 2.1. Стабилност на Дубликатите (Stable Ordering)
Това е критична гаранция на C++ стандарта (след C++11):
Елементи с **еднакъв ключ** се съхраняват в реда на тяхното вмъкване.
Ако вмъкнете `("Key", 1)`, после `("Key", 2)`, при обхождане гарантирано ще получите първо 1, после 2. Това прави структурата предвидима.

## 3. Операции и Работа с диапазони

### 3.1. Защо няма `operator[]`?
Това е най-честият въпрос на интервюта.
При `std::map`, `m["Key"]` връща референция към *единствената* стойност.
При `std::multimap`, за ключ "Key" може да има 0, 1 или 100 стойности. Коя да върне операторът? Няма верен отговор. Затова `operator[]` и `at()` са премахнати, за да се избегне двусмислие.

### 3.2. Достъп до данни: `equal_range`
Професионалният начин за достъп до данни в мултикарта не е `find`, а `equal_range`. Тя връща двойка итератори (`pair<iterator, iterator>`), които очертават началото и края на всички елементи с дадения ключ.

```cpp
std::multimap<string, int> scores;
scores.insert({"Player1", 100});
scores.insert({"Player1", 200});
scores.insert({"Player1", 50});

auto range = scores.equal_range("Player1");

// Итерираме само през записите на "Player1"
for (auto it = range.first; it != range.second; ++it) {
    std::cout << "Score: " << it->second << std::endl;
}
```

### 3.3. Броене и Търсене
*   `count(key)`: Връща броя на елементите с този ключ. Внимавайте: това е **O(log N + Count)**, така че ако имате милиони дубликати, може да е бавно.
*   `find(key)`: Връща итератор към **първия** елемент с този ключ.

---

## 4. Производителност (Complexity Analysis)

*   **Вмъкване (Insertion):** **O(log N)**. Винаги добавя нов възел.
*   **Изтриване (Deletion):** **O(log N + K)**, където K е броят на изтритите елементи.
*   **Търсене (Search):** **O(log N)**.

---

## 5. Професионални съвети и Капани

### 5.1. Капанът на `erase`
Бъдете внимателни!
*   `m.erase("Key")` изтрива **ВСИЧКИ** записи с този ключ.
*   Ако искате да изтриете само **един конкретен** запис (напр. само оценката 50 на Player1), трябва първо да го намерите с итератор и да подадете итератора на `erase`.

```cpp
// Триене само на първата срещната "50-ка" на Player1
auto range = m.equal_range("Player1");
for (auto it = range.first; it != range.second; ++it) {
    if (it->second == 50) {
        m.erase(it);
        break; // Важно! Итераторът става невалиден след триене.
    }
}
```

### 5.2. Архитектурна Алтернатива
Понякога `std::multimap<Key, Value>` не е най-доброто решение.
Разгледайте `std::map<Key, std::vector<Value>>`.
*   **Предимство на вектора:** По-добра кеш локалност за стойностите. По-малко memory overhead (само един възел в дървото за ключ).
*   **Предимство на мултикартата:** По-лесно добавяне на единични елементи (не трябва да търсите вектора, да правите push_back и т.н.). Сортираните стойности са "плоски".

---

## 6. Обобщение

Използвайте `std::multimap`, когато:
1.  Имате нужда от релация "Много-към-много" или "Едно-към-много".
2.  Искате данните да са винаги сортирани по ключ.
3.  Искате да запазите реда на вмъкване за дубликатите.

Ако не ви трябва сортировка, помислете за `std::unordered_multimap` за O(1) достъп.
