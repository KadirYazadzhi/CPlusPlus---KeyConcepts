# Двумерни Масиви (2D Arrays) в C++ - Пълно техническо ръководство

## 1. Концепция: Абстракция срещу Реалност
Двумерният масив често се визуализира като таблица с редове и колони. В действителност обаче, физическата RAM памет е **линейна**. C++ използва модел, наречен **Row-Major Order**, за да превърне тази 2D абстракция в 1D реалност.

---

## 2. Представяне в паметта (The Layout)

⚠️ **КРИТИЧНО:** Ако имате `int matrix[3][4]`, това са 12 цели числа, подредени едно след друго. Първо е целият първи ред, после целият втори и т.н.

### 2.1. Изчисляване на индекси (Pointer Arithmetic)
За да намери елемента на ред `i` и колона `j`, компилаторът прави следната сметка:
`Адрес = Начало + (i * Брой_Колони + j) * sizeof(Тип)`

Това е причината, поради която при подаване на 2D масив на функция, трябва **задължително** да укажете броя на колоните (напр. `void func(int arr[][4])`). Без това число, компилаторът не знае колко голям е един "ред" и не може да "прескочи" до следващия.

---

## 3. Оптимизация: Пътят на данните (Traversal)

Начинът, по който обхождате матрицата, може да промени скоростта на кода ви **стотици пъти**.

### 3.1. Row-Major Traversal (Правилно)
```cpp
for(int i = 0; i < rows; ++i)
    for(int j = 0; j < cols; ++j)
        sum += matrix[i][j]; // Достъпваме паметта последователно. Процесорът е доволен.
```

### 3.2. Column-Major Traversal (Грешно)
```cpp
for(int j = 0; j < cols; ++j)
    for(int i = 0; i < rows; ++i)
        sum += matrix[i][j]; // Прескачаме паметта. Това убива кеша на процесора (Cache Thrashing).
```

---

## 4. Динамични Двумерни Масиви (The Pointer Trap)

Често начинаещите създават "матрица" по този начин:
`int** matrix = new int*[rows];`
Това е **"Jagged Array"** (назъбен масив). Той не е непрекъснат в паметта. Всеки ред е на произволно място в Heap-а.
*   **Минус:** Ужасна производителност (липса на cache locality).
*   **Плюс:** Редовете могат да имат различна дължина.

---

## 5. Професионалното решение: Плосък масив
В високопроизводителния софтуер (игри, AI, симулации) 2D масивите се съхраняват като **плосък 1D масив**:
```cpp
std::vector<int> flat_matrix(rows * cols);
// Достъп: 
int val = flat_matrix[i * cols + j];
```
Това гарантира перфектна Cache Locality и само една алокация на памет.

---

## 6. Обобщение
*   **Статичен 2D масив:** Добре за малки матрици.
*   **Vector of Vectors:** Удобно за писане, но бавно (Jagged layout).
*   **Flat Vector (1D):** Инженерният стандарт за скорост.
