# Класове и Обекти: Сърцето на C++ - Пълно техническо ръководство

## 1. Въведение: Повече от просто данни

В C++ класовете (`class`) са основният инструмент за абстракция. Те обединяват данни (полета) и поведение (методи) в едно цяло.
Интересен факт: В C++, единствената разлика между `struct` и `class` е видимостта по подразбиране:
*   **struct:** Всичко е `public`. (Останало от C за съвместимост).
*   **class:** Всичко е `private`. (За енкапсулация).

Въпреки това, конвенцията е: използвайте `struct` за прости пакети от данни (POD - Plain Old Data), и `class` за обекти с инварианти и логика.

## 2. Подредба в Паметта (Memory Layout)

Когато създадете обект, той е просто парче памет. Няма метаданни (освен vptr, ако има виртуални функции).
Полетата са подредени последователно (освен `static` полетата, които са глобални).

### 2.1. Padding и Alignment (Подравняване)
Компилаторът добавя "дупки" (padding) между полетата, за да ги подравни на адреси, удобни за процесора (напр. кратни на 4 или 8).
```cpp
struct A {
    char c; // 1 байт
    // 3 байта padding (загубени!)
    int i;  // 4 байта
}; 
// sizeof(A) == 8, а не 5.
```
**Съвет:** Подреждайте полетата от най-голямо към най-малко (`double`, `long`, `int`, `char`), за да минимизирате загубата на памет (Packing).

### 2.2. The `this` pointer
Във всеки метод на класа има скрит параметър – `this`. Това е указател към текущия обект.
Когато викате `obj.method(5)`, компилаторът го превръща в `Class::method(&obj, 5)`.
`this` е `const` указател (не можете да промените към какво сочи, но можете да променяте обекта, към който сочи).

## 3. Специалните Методи (The Rule of 5)

Компилаторът автоматично генерира 6 метода за вас, ако не ги напишете:
1.  **Default Constructor:** `A()`.
2.  **Destructor:** `~A()`.
3.  **Copy Constructor:** `A(const A&)`.
4.  **Copy Assignment:** `operator=(const A&)`.
5.  **Move Constructor:** `A(A&&)`.
6.  **Move Assignment:** `operator=(A&&)`.

**Правилото на 5-те:** Ако напишете ръчно Деструктор (за да триете памет), значи автоматично генерираните Copy/Move методи са грешни (ще направят Shallow Copy и Double Free). Трябва да напишете и петте!

## 4. `explicit`, `default` и `delete`

### 4.1. `explicit` (Изричен)
Конструкторите с един аргумент действат като неявни конвертори.
`void f(MyClass c);` -> `f(10);` (ако MyClass има `MyClass(int)`).
Това често е нежелано. `explicit` забранява това.
```cpp
explicit MyClass(int x);
```

### 4.2. `default` и `delete`
*   `MyClass() = default;`: Казва на компилатора "генерирай ми стандартния конструктор, въпреки че написах друг".
*   `MyClass(const MyClass&) = delete;`: Забранява копирането. Ако някой се опита да копира обекта, ще получи грешка при компилация.

## 5. `const` Методи и `mutable`

Ако метод не променя обекта, маркирайте го с `const` (накрая).
```cpp
int getValue() const { return x; }
```
Това позволява методът да се вика върху `const` обекти. В тялото на метода, `this` става `const Class*`.

### `mutable`
Понякога искаме методът да е логически `const` (не променя състоянието на обекта от гледна точка на потребителя), но физически да променя нещо (напр. кеш или mutex).
Ключовата дума `mutable` позволява на поле да бъде променяно дори в `const` метод.

```cpp
class Data {
    mutable std::mutex mtx; // Мутексът трябва да се заключва дори при четене!
    int value;
public:
    int get() const {
        std::lock_guard<std::mutex> lock(mtx); // OK, защото е mutable
        return value;
    }
};
```

## 6. Приятели (Friends)

Ключовата дума `friend` позволява на външна функция или друг клас да достъпва `private` членовете на вашия клас.
Това често се критикува като нарушаване на енкапсулацията, но в C++ е необходимо за:
1.  Оператори (`operator<<` за `std::ostream`).
2.  Тясно свързани класове (напр. `Iterator` и `Container`), където итераторът трябва да пипа вътрешността на контейнера за ефективност.

## 7. Професионално обобщение

1.  **RAII:** Класовете са основният механизъм за управление на ресурси (Resource Acquisition Is Initialization). Конструкторът заема, деструкторът освобождава.
2.  **PIMPL:** За да скриете private детайлите и да ускорите компилацията (чрез премахване на зависимостите в хедъра), използвайте "Pointer to Implementation" идиома.
3.  **Small Classes:** Дръжте класовете малки. Ако класът има 50 метода, той вероятно нарушава Single Responsibility Principle.
