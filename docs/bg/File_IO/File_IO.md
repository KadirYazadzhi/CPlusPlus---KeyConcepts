# Работа с Файлове (File I/O) в C++ - Пълно техническо ръководство

## 1. Въведение: Потоците (Streams) като абстракция

В C++ работата с външни носители (дискове) е абстрахирана чрез концепцията за "потоци" (streams). Библиотеката `<fstream>` ни предоставя класове, които имитират поведението на стандартните `cin` и `cout`, но насочени към файловата система.
Това е един от най-добрите примери за силата на ООП дизайна в C++: полиморфизмът ни позволява да пишем код, който работи еднакво добре с конзолата, файлове или стрингове.

---

## 2. Ключови класове и тяхната роля

Всички класове наследяват от `std::ios_base`.

### 2.1. `std::ifstream` (Input File Stream)
Използва се единствено за четене.
*   Има дефиниран `operator>>` за форматирано четене.
*   Метод `get()` за четене на символи.
*   Метод `read()` за бинарни блокове.

### 2.2. `std::ofstream` (Output File Stream)
Използва се за създаване и писане във файлове.
*   По подразбиране, отварянето му **изтрива (truncates)** съдържанието на съществуващ файл, освен ако не е указано друго.

### 2.3. `std::fstream` (Bidirectional)
Позволява едновременно четене и писане в един и същ файлов обект. Изключително полезно за бази данни на ниско ниво или лог файлове, които трябва да се четат и допълват.

---

## 3. Режими на работа (Open Modes)

При отваряне на файл (чрез конструктор или `open()`) подаваме битови флагове:

*   **`std::ios::in`**: Отваряне за четене (Default за `ifstream`).
*   **`std::ios::out`**: Отваряне за писане (Default за `ofstream`).
*   **`std::ios::app` (Append):** Всички записи отиват гарантирано в края на файла. Не можете да преместите показалеца за писане назад.
*   **`std::ios::ate` (At End):** Отваря файла и веднага премества показалеца в края, но ви позволява да го местите свободно след това.
*   **`std::ios::trunc` (Truncate):** Изтрива съдържанието при отваряне.
*   **`std::ios::binary`**: **Критично важно!** Изключва трансформацията на нови редове (напр. `\n` -> `\r\n` в Windows). Задължително за картинки, аудио и бинарни данни.

---

## 4. Позициониране (Seeking)

В C++ файловете не се четат само последователно. Можете да "скачате" до произволни байтове.

*   **`seekg(offset, direction)`**: (Seek Get) Мести показалеца за четене.
*   **`seekp(offset, direction)`**: (Seek Put) Мести показалеца за писане.
*   **`tellg() / tellp()`**: Връща текущата позиция (в байтове от началото).

**Посоки:**
*   `std::ios::beg` (Начало).
*   `std::ios::cur` (Текуща позиция).
*   `std::ios::end` (Край).

**Пример (Размер на файл):**
```cpp
std::ifstream file("data.bin", std::ios::binary | std::ios::ate);
std::streamsize size = file.tellg(); // Вече сме в края заради 'ate'
```

## 5. Бинарни файлове срещу Текстови

### 5.1. Текстов режим
Удобен за хора. Числата се превръщат в текст ("123" са 3 байта).
```cpp
file << "Score: " << 100 << std::endl;
```

### 5.2. Бинарен режим
Удобен за машини. Бърз и компактен. Записват се суровите битове от RAM паметта.
```cpp
int x = 12345;
file.write(reinterpret_cast<const char*>(&x), sizeof(x)); // Точно 4 байта
```
⚠️ **Опасност:** Бинарните файлове не са преносими между различни процесори (заради **Endianness** - Little vs Big Endian) или компилатори (заради Padding в структурите).

## 6. C++17 Filesystem (`<filesystem>`)

Това е модерният начин за работа с файловата система (създаване на папки, копиране, итериране).
*   `std::filesystem::path`: Абстракция за път (работи и с `/`, и с `\`).
*   `std::filesystem::exists()`: Проверка дали файл съществува.
*   `std::filesystem::directory_iterator`: Обхождане на папка.

```cpp
for (const auto& entry : std::filesystem::directory_iterator(".")) {
    std::cout << entry.path() << std::endl;
}
```

---

## 7. Професионални съвети и Капани

1.  **Проверка за успех:** Винаги проверявайте `if (file.is_open())` или просто `if (file)`.
2.  **Буфериране:** `std::endl` не просто слага нов ред, но и **изчиства буфера** (flush). Това е бавно при писане във файл. Използвайте `\n`.
3.  **Stringstreams:** За да парсвате сложен текст в паметта, използвайте `<sstream>`. Това е като файл, но живее в `std::string`.
4.  **Race Conditions:** Стандартната библиотека не гарантира безопасност, ако две нишки пишат в един и същ файл.

---

## 8. Професионално обобщение

*   Използвайте **RAII** за управление на файловете (деструкторът затваря файла).
*   Използвайте **`std::filesystem`** за навигация.
*   За конфигурации ползвайте JSON/XML библиотеки, не пишете свои парсери с `fstream`.
*   За огромни файлове (GBs), разгледайте **Memory Mapped Files** (OS-specific), тъй като са по-бързи от потоците.
