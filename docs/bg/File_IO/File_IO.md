# Работа с Файлове (File I/O) в C++ - Пълно техническо ръководство

## 1. Въведение: Потоците (Streams) като абстракция
В C++ работата с външни носители (дискове) е абстрахирана чрез концепцията за "потоци" (streams). Библиотеката `<fstream>` ни предоставя класове, които имитират поведението на стандартните `cin` и `cout`, но насочени към файловата система. Това е един от най-добрите примери за силата на ООП дизайна в C++.

---

## 2. Ключови класове и тяхната роля

### 2.1. `std::ifstream` (Input File Stream)
Използва се единствено за четене. Опит за писане в него няма да се компилира.

### 2.2. `std::ofstream` (Output File Stream)
Използва се за създаване и писане във файлове. По подразбиране изтрива съдържанието на съществуващ файл (`trunc`), освен ако не е указано друго.

### 2.3. `std::fstream` (Bidirectional)
Позволява едновременно четене и писане в един и същ файлов обект. Изключително полезно за бази данни на ниско ниво.

---

## 3. Режими на работа (Open Modes)

При отваряне на файл можем да комбинираме флагове:
*   `std::ios::app`: (Append) Винаги пише в края.
*   `std::ios::ate`: (At the end) Отваря и веднага отива в края, но позволява местене назад.
*   `std::ios::binary`: Отваря файла в бинарен режим (критично за нетекстови данни).
*   `std::ios::in / out`: Явно указване на посоката.

---

## 4. Позициониране (Seeking)

В C++ файловете не се четат само последователно. Можете да "скачате" до произволни байтове:
*   `seekg(offset, direction)`: (Seek Get) За четене.
*   `seekp(offset, direction)`: (Seek Put) За писане.
*   `tellg() / tellp()`: Връща текущата позиция (байта).

**Пример (Размер на файл):**
```cpp
file.seekg(0, std::ios::end);
long size = file.tellg();
```

---

## 5. Бинарни файлове срещу Текстови

### 5.1. Текстов режим
Компилаторът може да прави трансформации (напр. превръщане на `\n` в `\r\n` на Windows). Числата се записват като символи ("123" са 3 байта).

### 5.2. Бинарен режим
Записват се суровите битове от RAM паметта.
```cpp
int x = 12345;
file.write(reinterpret_cast<char*>(&x), sizeof(x)); // Точно 4 байта
```
⚠️ **Опасност:** Бинарните файлове не са преносими между различни процесори (заради Endianness).

---

## 6. Професионални капани
1.  **Забравен `close()`?** Благодарение на RAII, деструкторът на `fstream` автоматично затваря файла. Но е добре да го викате ръчно, ако искате да хванете грешки при писане.
2.  **Проверка за успех:** Винаги проверявайте `if (!file)` след отваряне. Опит за четене на липсващ файл е тиха грешка в STL.
3.  **Производителност:** Работата с диска е хиляди пъти по-бавна от RAM. Използвайте буфериране (четене на големи блокове), вместо байт по байт.

---

## 7. Професионално обобщение
*   Използвайте **RAII** за управление на файловете.
*   Предпочитайте **бинарни формати** за големи данни (скорост).
*   Предпочитайте **JSON/XML** за конфигурации (четимост).
