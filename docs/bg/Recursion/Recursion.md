# Рекурсия (Recursion) в C++ - Пълно ръководство

## 1. Въведение: Изкуството на самоизвикването
Рекурсията е техника в програмирането, при която една функция извиква сама себе си, директно или индиректно. Това е мощен математически инструмент за решаване на сложни проблеми чрез разбиването им на по-малки, идентични подпроблеми.

---

## 2. Анатомия на рекурсивната функция

Всяка правилно написана рекурсивна функция **задължително** съдържа две части:

1.  **Базов случай (Base Case):** Условието, при което рекурсията спира. Без него функцията ще се вика безкрайно, което води до **Stack Overflow**.
2.  **Рекурсивна стъпка (Recursive Step):** Мястото, където функцията извиква себе си с "по-малък" или "по-прост" аргумент, доближавайки се до базовия случай.

---

## 3. Рекурсия и Памет (The Call Stack)

Когато една функция се извика, в системния стек се заделя нов **Stack Frame**. При рекурсията тези фреймове се трупат един върху друг.
*   Всеки фрейм пази собствени копия на локалните променливи и параметри.
*   Ако рекурсията е твърде дълбока, паметта на стека се изчерпва (**Stack Overflow**).

---

## 4. Видове рекурсия

### 4.1. Директна и Индиректна
*   **Директна:** Функция А вика функция А.
*   **Индиректна:** Функция А вика функция Б, която от своя страна вика функция А.

### 4.2. Опашкова рекурсия (Tail Recursion)
Това е оптимизирана форма, при която рекурсивното извикване е **последното действие** във функцията.
```cpp
int factorial_tail(int n, int accumulator = 1) {
    if (n == 0) return accumulator;
    return factorial_tail(n - 1, n * accumulator); // Резултатът се предава надолу
}
```
Съвременните компилатори могат да превърнат това извикване в обикновен цикъл, пестейки памет в стека.

---

## 5. Класически примери

1.  **Факториел:** `n! = n * (n-1)!`
2.  **Числа на Фибоначи:** `F(n) = F(n-1) + F(n-2)` (⚠️ Внимавайте с производителността тук!)
3.  **Ханойски кули:** Класически пример за алгоритъм, който е почти невъзможен за писане без рекурсия.
4.  **Обхождане на дървета (DFS):** Рекурсията е естественият начин за работа с йерархични структури.

---

## 6. Рекурсия срещу Итерация

| Характеристика | Рекурсия | Итерация (Цикли) |
| :--- | :--- | :--- |
| **Код** | По-кратък и елегантен | По-дълъг, изисква управление на състоянието |
| **Памет** | Висок разход (Stack Frames) | Нисък разход (O(1) често) |
| **Производителност** | По-бавна (overhead от извиквания) | По-бърза |

---

## 7. Кога да използваме рекурсия?
*   Когато проблемът има естествена рекурсивна структура (дървета, графи).
*   Когато чистият код е по-важен от микро-оптимизацията на паметта.
*   При алгоритми като **QuickSort**, **MergeSort** и **Backtracking**.
