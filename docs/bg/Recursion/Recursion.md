# Рекурсия (Recursion) - Пълно техническо ръководство

## 1. Въведение: Да дефинираш себе си чрез себе си

Рекурсията е един от най-елегантните и мощни похвати в програмирането. Това е техника, при която функция извиква самата себе си, за да реши по-малка инстанция на същия проблем.
Тя е естественият начин за описване на задачи, които имат самоподобна (фрактална) структура: обхождане на дървета, графи, файлови системи, парсване на JSON/XML, комбинаторни задачи (генериране на пермутации).

Всяка правилна рекурсия се състои от два задължителни компонента:
1.  **Дъно (Base Case):** Условието за спиране. Най-простият възможен случай, който се решава директно без нови извиквания (напр. `if (n == 0) return 1;`). Без дъно, рекурсията е безкрайна и води до краш.
2.  **Рекурсивна стъпка:** Логиката, която свежда проблема до по-малък под-проблем и извиква функцията отново.

## 2. Механика на Стека (Stack Frames)

За да разберете рекурсията (и нейните опасности), трябва да разберете как работи компютърът на ниско ниво.
Всеки път, когато извикате функция, в паметта (в зоната, наречена **Стек**) се заделя нова "рамка" (Stack Frame). Тази рамка съдържа:
*   Локалните променливи на функцията.
*   Аргументите, с които е извикана.
*   Адресът за връщане (къде да продължи програмата, след като функцията приключи).

При рекурсия, тези рамки се натрупват една върху друга като чинии.
`factorial(3)` вика `factorial(2)`, който вика `factorial(1)`, който вика `factorial(0)`.
В този момент имаме 4 активни рамки в паметта едновременно. Когато `factorial(0)` върне резултат, най-горната рамка се унищожава (Pop) и управлението се връща на предишната.

### Опасността: Stack Overflow
Стекът е бърз, но малък. Обикновено размерът му е ограничен от Операционната Система (напр. 1MB в Windows, 8MB в Linux).
Ако вашата рекурсия е твърде дълбока (напр. обхождате свързан списък с 1 милион елемента рекурсивно), вие ще запълните цялата памет на стека.
Резултатът е мигновен краш на програмата с грешка **Stack Overflow**. Това е фатална грешка, която не може да бъде хваната с `try-catch`.

## 3. Tail Recursion (Опашкова рекурсия)

Има специален вид рекурсия, която е безопасна и ефективна. Нарича се "Опашкова рекурсия" (Tail Recursion).
При нея рекурсивното извикване е **абсолютно последното** действие във функцията. Няма никакви сметки *след* като вътрешната функция върне резултат.

**Обикновена рекурсия (Лоша):**
```cpp
int fact(int n) {
    if (n == 0) return 1;
    return n * fact(n - 1); // Умножението се случва СЛЕД връщането!
}
```
Тук компютърът трябва да пази текущата рамка (заради `n`), докато чака `fact(n-1)`.

**Опашкова рекурсия (Добра):**
```cpp
int factTail(int n, int acc = 1) {
    if (n == 0) return acc;
    return factTail(n - 1, n * acc); // Директно връщане на резултата.
}
```
Тук няма нищо за правене след извикването.

**Защо е важно? (Tail Call Optimization - TCO)**
Модерните компилатори (GCC, Clang с `-O2` или `-O3`) разпознават този модел. Те оптимизират кода, като превръщат рекурсията в обикновен цикъл (`jmp` инструкция). Вместо да създават нова рамка в стека, те просто презаписват старата с новите аргументи. Това прави рекурсията безкрайно дълбока без риск от Stack Overflow!

## 4. Мемоизация (Dynamic Programming)

Една от най-големите грешки на начинаещите е "наивната рекурсия". Класически пример е числата на Фибоначи: `fib(n) = fib(n-1) + fib(n-2)`.
Това решение има експоненциална сложност **O(2^N)**. За да сметне `fib(50)`, компютърът ще трябва да направи трилиони операции и ще забие за минути (или часове). Проблемът е, че преизчисляваме едни и същи стойности отново и отново (напр. `fib(3)` се смята хиляди пъти).

**Мемоизацията** е техника за кеширане на резултатите.
```cpp
std::map<int, long long> cache;

long long fib(int n) {
    if (n <= 1) return n;
    
    // Проверка в кеша
    if (cache.contains(n)) return cache[n];
    
    // Смятане и записване в кеша
    long long res = fib(n-1) + fib(n-2);
    cache[n] = res;
    return res;
}
```
Това превръща алгоритъма в линеен **O(N)**.

## 5. Рекурсия срещу Итерация

Вечният въпрос: Кога да ползвам рекурсия и кога цикъл?

**Използвайте Рекурсия, когато:**
1.  Структурата от данни е рекурсивна (Дървета, Графи, JSON, XML, Файлова система).
2.  Алгоритъмът е "Разделяй и владей" (Merge Sort, Quick Sort).
3.  Имплементирате Backtracking (търсене на път в лабиринт, решаване на Судоку, AI за шах).
4.  Четимостта е по-важна от микро-оптимизацията.

**Използвайте Итерация (Цикъл), когато:**
1.  Структурата е линейна (Списък, Вектор).
2.  Критична е производителността (Function call overhead е малък, но съществува).
3.  Има риск от Stack Overflow и компилаторът не гарантира TCO.

**Експлицитен стек:**
Ако имате сложен рекурсивен алгоритъм (напр. DFS в огромен граф), но се страхувате от Stack Overflow, можете да го пренапишете итеративно, използвайки `std::stack<T>`. Така използвате Heap паметта (която е гигабайти), вместо Stack паметта.

## 6. Професионално обобщение

1.  **Дъното е най-важно:** Винаги започвайте писането на рекурсия с дъното (Base case). Уверете се, че то се достига при всякакви входове.
2.  **Debug:** Дебъгването на дълбока рекурсия е кошмар. Използвайте хартия и молив или логирайте дълбочината (с indent), за да визуализирате процеса.
3.  **Елегантност:** Рекурсията често води до по-кратък и по-ясен код. Не се борете да я премахнете на всяка цена, освен ако нямате доказан проблем с паметта.
