# Рекурсия (Recursion) в C++ - Пълно техническо ръководство

## 1. Въведение: Математическа красота и Системна реалност

Рекурсията е концепция, при която една функция извиква себе си директно или индиректно, за да реши по-малка инстанция на същия проблем.
В компютърните науки това е мощна техника за справяне със задачи, които имат самоподобна структура (обхождане на дървета, графи, фрактали).
В C++ обаче, тя не е безплатна. Тя идва със значителна "ценова етикетка": **Call Stack Usage**.

---

## 2. Анатомия на Рекурсивния Процес

Всяка коректна рекурсивна функция трябва да има два компонента:
1.  **Base Case (Базов случай):** Котвата, която спира процеса. Без нея програмата ще влезе в безкраен цикъл и ще катастрофира (Stack Overflow).
2.  **Recursive Step (Рекурсивна стъпка):** Частта, която разбива проблема на по-малки парчета и ги подава на себе си.

### Пример: Факториел
```cpp
int factorial(int n) {
    if (n <= 1) return 1;        // Base Case
    return n * factorial(n - 1); // Recursive Step
}
```

---

## 3. Рекурсия и Памет (Physical Stack Analysis)

⚠️ **КРИТИЧНО ЗА ПРОФЕСИОНАЛИСТИ:**
Всеки път, когато функцията извика себе си, в RAM паметта се заделя нов **Stack Frame** (Рамка). Тази рамка съдържа:
1.  Аргументите на функцията (`n`).
2.  Локалните променливи.
3.  Адресът за връщане (Return Address) – къде да се върне процесорът след като функцията приключи.

**Математиката на срива:**
*   Ако стекът на вашата операционна система е ограничен до **1 MB** (стандарт за Windows/Visual Studio) или **8 MB** (Linux).
*   Ако един фрейм заема **64 байта**.
*   Можете да направите само около **16,000** (Windows) до **130,000** (Linux) вложени извиквания.
*   Ако опитате да изчислите `factorial(200000)`, програмата ще гръмне със **Stack Overflow Exception**.

---

## 4. Опашкова Рекурсия (Tail Call Optimization - TCO)

Това е свещеният граал на рекурсията.
TCO е техника, при която рекурсивното извикване е **абсолютно последното нещо**, което функцията прави. Няма "умножение след връщането".

**Лоша рекурсия (Non-Tail):**
```cpp
return n * factorial(n - 1); // Трябва да помним 'n', за да умножим СЛЕД като се върне резултата.
```

**Добра рекурсия (Tail Recursive):**
Използваме "акумулатор" за резултата.
```cpp
int factorial(int n, int result = 1) {
    if (n == 0) return result;
    return factorial(n - 1, result * n); // Нищо не се прави след това извикване!
}
```

**Защо е важно?**
Съвременните оптимизиращи компилатори (GCC -O2, Clang) разпознават този модел. Вместо да правят нов `CALL` и да хабят памет за нов Stack Frame, те просто презаписват аргументите и правят `JUMP` (goto) към началото на функцията.
Така рекурсията се превръща в **цикъл** на ниво асемблер. Паметта остава константна O(1).

## 5. Стратегии за Решаване на Задачи

### 5.1. Divide and Conquer (Разделяй и Владей)
Разбиваме проблема на независими подпроблеми, решаваме ги и комбинираме резултатите.
*   **Merge Sort:** Раздели масива на две, сортирай всяка половина, слей ги.
*   **Quick Sort:** Избери пивот, премести по-малките вляво, по-големите вдясно, повтори.

### 5.2. Backtracking (Търсене с връщане)
Използваме рекурсия, за да изследваме всички възможни решения, и се "връщаме назад", когато стигнем до задънена улица.
*   **Судоку:** Пробвай число. Ако доведе до конфликт, върни се и пробвай друго.
*   **Търсене на път в лабиринт.**

## 6. Рекурсия срещу Итерация

| Характеристика | Рекурсия | Итерация |
| :--- | :--- | :--- |
| **Чистота на кода** | Изключително висока (особено за дървета) | По-ниска (нужда от ръчен stack) |
| **Памет** | Висока (Stack frames) | Ниска (Constant) |
| **Скорост** | По-бавна (Function call overhead) | По-бърза |
| **Риск** | Stack Overflow | Infinite Loop (по-лесно се дебъгва) |

---

## 7. Професионално обобщение

1.  Използвайте рекурсия за **йерархични данни** (дървета, DOM, JSON, File System). Итеративното обхождане на дърво е сложно и грозно.
2.  Винаги проверявайте дали алгоритъмът ви може да ползва **TCO (Tail Call Optimization)**.
3.  При критични за паметта системи (Embedded / Microcontrollers), **избягвайте рекурсията** на всяка цена, защото стекът там е само няколко KB.
4.  Ако дълбочината на рекурсията зависи от входните данни (напр. N елемента), винаги имайте план Б (итерация), за да не крашнете при N=1,000,000.
