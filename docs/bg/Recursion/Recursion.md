# Рекурсия (Recursion) в C++ - Пълно техническо ръководство

## 1. Въведение: Математическа красота и Системна реалност
Рекурсията е концепция, при която една функция извиква себе си, за да реши по-малка инстанция на същия проблем. Това е гръбнакът на много фундаментални алгоритми, но в езика C++ тя идва с една много важна "ценова етикетка": **Call Stack**.

---

## 2. Анатомия на Рекурсивния Процес

Всяка здрава рекурсивна функция трябва да има две части:
1.  **Base Case (Базов случай):** Котвата, която спира процеса. Без нея програмата ще се върти, докато не свърши паметта.
2.  **Recursive Step (Рекурсивна стъпка):** Намаляване на сложността на проблема.

---

## 3. Рекурсия и Памет (Physical Stack Analysis)

⚠️ **КРИТИЧНО ЗА ПРОФЕСИОНАЛИСТИ:** Всеки път, когато функцията извика себе си, в RAM паметта се заделя нов **Stack Frame**.
*   Ако стекът на вашата операционна система е 1 MB (често срещан лимит), а всеки фрейм заема 1 KB, след 1000 извиквания ще получите **Stack Overflow**.
*   **Решение:** За дълбоки рекурсии използвайте итерация или разширете стека на системата.

---

## 4. Опашкова Рекурсия (Tail Call Optimization - TCO)

Това е техника, при която рекурсивното извикване е **последното нещо** във функцията.
```cpp
int factorial(int n, int res = 1) {
    if (n == 0) return res;
    return factorial(n - 1, res * n); // Tail call
}
```
Съвременните компилатори (G++, Clang) разпознават този модел и превръщат рекурсията в обикновен цикъл на ниво асемблер. Това напълно елиминира риска от Stack Overflow.

---

## 5. Рекурсия срещу Итерация

| Характеристика | Рекурсия | Итерация |
| :--- | :--- | :--- |
| **Чистота на кода** | Изключително висока | Средна |
| **Памет** | Висока (Stack frames) | Ниска (Constant) |
| **Скорост** | По-бавна (overhead) | По-бърза |

---

## 6. Приложения в реалния свят
1.  **Обхождане на Дървета (DFS):** Директории във файлова система, XML/JSON структури.
2.  **Divide and Conquer:** QuickSort и MergeSort.
3.  **Backtracking:** Решаване на Судоку, Лабиринти, Генериране на пароли.

---

## 7. Професионално обобщение
*   Използвайте рекурсия за **йерархични данни**.
*   Винаги търсете начин за **TCO (Tail Call Optimization)**.
*   При критични за паметта системи (Embedded), избягвайте рекурсията на всяка цена.
