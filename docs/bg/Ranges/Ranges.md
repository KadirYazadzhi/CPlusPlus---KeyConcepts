# Обхвати (Ranges) в C++20 - Пълно техническо ръководство

## 1. Въведение: Парадигмата на Тръбопроводите (Pipelines)

Библиотеката **Ranges** (`<ranges>`) е най-голямата еволюция в STL от неговото създаване през 90-те. Тя променя фундаментално начина, по който работим с колекции, като преминава от императивен стил (как да обхождам) към **декларативен стил** (какво да направя).

**Основната идея:** Вместо да манипулираме итератори ръчно, ние създаваме "тръбопроводи" (pipelines) от операции, които трансформират данните. Това прави C++ да изглежда като език от високо ниво (Python, Rust, C# LINQ).

## 2. Views (Изгледи): Магията на мързеливото изчисляване

⚠️ **ИНЖЕНЕРЕН ПОГЛЕД:** Изгледите (Views) са леки обекти, които **не притежават данните**. Те са просто "умни прозорци" към съществуващи колекции. Копирането на View е O(1) и е евтино.

### 2.1. Lazy Evaluation (Мързеливо изчисление)
Операциите в Ranges са мързеливи.
```cpp
std::vector<int> nums = {1, 2, 3, 4, 5};
auto heavy_calc = nums 
                | std::views::filter(is_even)      // 1. Не се изпълнява веднага
                | std::views::transform(super_heavy_func); // 2. Не се изпълнява веднага

// Реалното изчисление започва ЕДВА ТУК:
int first_result = *heavy_calc.begin(); 
```
Това спестява процесорно време, ако не използвате всички резултати (напр. търсите само първия).

## 3. Композиция чрез Pipeline оператор (`|`)

C++20 претоварва побитовия оператор ИЛИ (`|`), за да позволи Unix-style композиция.

```cpp
#include <ranges>
#include <vector>
#include <iostream>

namespace rv = std::ranges::views; // Псевдоним за краткост

int main() {
    std::vector<int> numbers = {1, 2, 3, 4, 5, 6};

    auto result = numbers 
                | rv::filter([](int n){ return n % 2 == 0; }) // Вземи четните: 2, 4, 6
                | rv::transform([](int n){ return n * n; })   // Вдигни на квадрат: 4, 16, 36
                | rv::reverse                                 // Обърни: 36, 16, 4
                | rv::take(2);                                // Вземи първите 2: 36, 16

    for (int n : result) std::cout << n << " ";
}
```

## 4. Алгоритми с Ranges (std::ranges)

Старите алгоритми изискваха `begin(), end()`. Новите (`std::ranges::`) работят директно с контейнера.

### 4.1. Dangling Iterators Protection
Старите алгоритми не знаеха за живота на обектите.
```cpp
auto it = std::find(getTemporaryVector().begin(), ...); // ГРЕШКА: Връща итератор към мъртъв вектор
```
Новите Ranges алгоритми откриват това и връщат специален итератор `std::ranges::dangling`, който не може да бъде дерефериран, предпазвайки ви от бъгове.

## 5. Проекции (Projections): Сбогом на сложните ламбди

Ranges позволяват да подавате "проекция" на данните – функция, която се прилага върху елемента, *преди* той да бъде сравнен.

**Стар начин:**
```cpp
std::sort(people.begin(), people.end(), [](const Person& a, const Person& b) {
    return a.name < b.name;
});
```

**Нов начин (с Проекция):**
```cpp
// 1. Контейнер, 2. Компаратор (default {}), 3. Проекция
std::ranges::sort(people, {}, &Person::name); 
```
Това е изключително елегантно за масиви от структури.

## 6. Създаване на собствени Views

Можете да напишете свой View, наследявайки `std::ranges::view_interface`. Трябва само да дефинирате `begin()` и `end()`.

```cpp
template<std::ranges::input_range R>
class AddOneView : public std::ranges::view_interface<AddOneView<R>> {
    // ... имплементация на итератор, който добавя +1 при *it ...
};
```

## 7. Професионално обобщение

1.  **Safety:** Ranges алгоритмите (Constrained Algorithms) използват Concepts, за да дадат смислени грешки, ако подадете грешен тип.
2.  **Performance:** Ranges често са **по-бързи** от ръчни цикли, защото избягват създаването на междинни буфери (`std::vector` след всяка стъпка).
3.  **Limitations:** Не всички STL контейнери поддържат всички Ranges операции. Например, `std::list` не е Random Access Range, така че не може да се сортира с `ranges::sort`.
4.  **Infinite Sequences:** Ranges позволяват работа с безкрайни потоци (напр. генератор на числа), стига да използвате `views::take(N)`.
