# Обхвати (Ranges) в C++20 - Пълно техническо ръководство

## 1. Въведение: Парадигмата на Тръбопроводите (Pipelines)
Библиотеката **Ranges** (`<ranges>`) е най-голямата еволюция в STL от неговото създаване. Тя променя начина, по който работим с колекции, като преминава от итератори към **декларативен** стил. Вместо да казваме на компилатора *как* да обхожда данните, ние казваме *какво* искаме да направим с тях.

---

## 2. Views (Изгледи): Магията на мързеливото изчисляване

⚠️ **ИНЖЕНЕРЕН ПОГЛЕД:** Изгледите (Views) са леки обекти, които не притежават данните. Те са просто "прозорци" към съществуващи колекции.

### 2.1. Lazy Evaluation
Операциите в Ranges са **мързеливи**. Когато филтрирате или трансформирате колекция, реалното изчисление се случва едва в момента, в който започнете да четете данните.
```cpp
auto result = vec | std::views::filter(is_even) | std::views::transform(square);
// Дотук нищо не е сметнато!
```

---

## 3. Композиция чрез Pipeline оператор (`|`)
Подобно на Unix терминала или езици като F# и Elixir, C++20 Ranges позволяват верижно свързване на операции.
```cpp
#include <ranges>
#include <vector>

std::vector<int> numbers = {1, 2, 3, 4, 5};

auto res = numbers 
         | std::views::filter([](int n){ return n > 2; })
         | std::views::take(2); // Вземи само първите два елемента от филтрираните
```

---

## 4. Алгоритми с Ranges (std::ranges)
Вече няма нужда да подавате `begin()` и `end()`. Всички стандартни алгоритми имат свои "range" версии.
*   `std::ranges::sort(vec);`
*   `std::ranges::find(vec, value);`

---

## 5. Проекции (Projections): Сбогом на сложните ламбди
Ranges позволяват да подавате "проекция" на данните. Ако имате списък с обекти и искате да ги сортирате по едно поле:
```cpp
struct Person { int id; string name; };
std::ranges::sort(people, {}, &Person::name); // Сортирай по име автоматично!
```

---

## 6. Предимства за производителността
Ranges често са **по-бързи** от традиционните цикли, защото:
1.  **Избягват междинни алокации:** Не се създават временни вектори между филтрирането и трансформирането.
2.  **По-добро вграждане (Inlining):** Компилаторът може да види целия поток от операции наведнъж.

---

## 7. Професионално обобщение
*   Ranges правят кода **самодокументиращ се**.
*   Използвайте ги, за да замените сложни вложени цикли с ясни потоци.
*   Внимавайте с живота на оригиналната колекция – Изгледите (Views) стават невалидни, ако изтриете оригиналния контейнер.
