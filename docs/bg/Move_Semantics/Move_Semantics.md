# Семантика на Преместването (Move Semantics) - Пълно техническо ръководство

## 1. Въведение: Защо Move е по-добро от Copy?

До 2011 година (C++98/03), езикът C++ имаше един голям структурен проблем: прехвърлянето на данни между обекти изискваше пълно копиране.
Ако имате вектор с 1 милион елемента и го върнете от функция, старият C++ щеше:
1.  Да задели памет за новия вектор.
2.  Да копира всички 1 милион елемента.
3.  Да изтрие стария вектор.

**Move Semantics** (C++11) промени това фундаментално. Тя позволява на програмата да разпознае, че старият обект "умира", и просто да **открадне** неговия вътрешен указател към паметта. Цената пада от O(N) на O(1).

## 2. Категории стойности: L-values срещу R-values

За да разберете преместването, трябва да знаете категориите стойности (Value Categories):

### 2.1. L-value (Left Value)
Обект, който има **име** и постоянен **адрес** в паметта. Можете да вземете адреса му с `&`.
*   `int x = 5;` -> `x` е l-value.
*   `std::string s;` -> `s` е l-value.

### 2.2. R-value (Right Value)
Временен обект (Temporary), който няма име и ще бъде унищожен в края на израза. Не можете да вземете адреса му.
*   `5` (литерал).
*   `x + y` (резултат от израз).
*   `FunctionReturningValue()` (резултат от функция).

### 2.3. R-value Референция (`T&&`)
Това е "детекторът" за временни обекти.
*   `void func(int& x)` -> приема само l-values (истински променливи).
*   `void func(int&& x)` -> приема само r-values (временни обекти, които можем да ограбим).

## 3. Магията на `std::move()`

⚠️ **МИСКОНЦЕПЦИЯ:** `std::move` **не мести нищо**. Той не генерира машинен код за местене.

Физически той е просто един **cast** (`static_cast<T&&>`).
Неговата единствена цел е да излъже компилатора: *"Хей, третирай този именуван обект (l-value) като временен (r-value), за да мога да извикам неговия Move Constructor."*

```cpp
std::string s1 = "Hello World";
std::string s2 = std::move(s1); 
// 1. std::move казва "s1 е r-value".
// 2. Извиква се string(string&&).
// 3. s2 взима буфера на s1.
// 4. s1 става празен (но валиден) стринг.
```

## 4. Имплементиране на Move Semantics

За да направите вашия клас "местещ се", трябва да напишете два специални метода.

### 4.1. Move Constructor
```cpp
class Buffer {
    int* data;
    size_t size;
public:
    // Move Constructor
    Buffer(Buffer&& other) noexcept 
        : data(other.data), size(other.size) { // 1. Крадем ресурса
        
        // 2. Нулираме източника (МНОГО ВАЖНО)
        other.data = nullptr;
        other.size = 0;
    }
    
    ~Buffer() { delete[] data; } // Безопасно е да се трие nullptr
};
```

### 4.2. Move Assignment Operator (`operator=`)
Трябва да се справим със съществуващия ресурс в `this`, преди да откраднем новия.
```cpp
Buffer& operator=(Buffer&& other) noexcept {
    if (this != &other) {          // 1. Self-assignment check
        delete[] data;             // 2. Освобождаваме текущия ресурс
        
        data = other.data;         // 3. Крадем новия
        size = other.size;
        
        other.data = nullptr;      // 4. Нулираме източника
        other.size = 0;
    }
    return *this;
}
```

### 4.3. Защо `noexcept`?
Винаги маркирайте Move методите с `noexcept`. Ако `std::vector` трябва да се разшири (reallocate), той ще използва Move конструкторите на елементите **само ако** те са `noexcept`. Ако не са, той ще ги копира (за безопасност), което убива производителността.

## 5. Perfect Forwarding и `std::forward`

В шаблонното програмиране (Templates), често искаме да подадем аргумент на друга функция, запазвайки неговата категория (ако е бил r-value, да остане r-value).

**Universal Reference (`T&&` в темплейт):**
Приема и l-value, и r-value.

```cpp
template<typename T>
void wrapper(T&& arg) {
    // std::forward запазва категорията
    worker(std::forward<T>(arg)); 
}
```
*   Ако подадем `lvalue` -> `forward` връща `lvalue`.
*   Ако подадем `rvalue` -> `forward` връща `rvalue` (и позволява move).

## 6. Професионално обобщение

1.  **Rule of Five:** Ако дефинирате деструктор, копиране или местене, дефинирайте всичките 5 метода.
2.  **Move след Use:** След `std::move(x)`, обектът `x` е в "валидно, но неопределено състояние". Не го ползвайте, освен за да му присвоите нова стойност или да го разрушите.
3.  **Return by Value:** Не връщайте `std::move(local_var)`. Това пречи на **RVO** (Return Value Optimization). Просто върнете `local_var`.
