# Мултикарти (std::multiset) - Пълно техническо ръководство

## 1. Въведение: Защо ни трябват дубликати?

В стандартния `std::set`, всеки елемент е уникален. Това е математическо множество. Ако опитате да вмъкнете числото `5` два пъти, второто вмъкване се игнорира.
Но в реалния свят, дубликатите са навсякъде.
*   **Leaderboards (Класации):** Много играчи могат да имат еднакъв резултат (напр. 100 точки). Ние искаме да видим всички тях в списъка, подредени.
*   **Търговия (Order Book):** Много продавачи предлагат акции на една и съща цена ($150.00). Тези оферти се подреждат на опашка.
*   **Планиране на събития:** В една и съща милисекунда могат да се случат няколко събития.

`std::multiset` решава това. Той е **винаги сортиран** контейнер, който позволява повторения.

---

## 2. Приложения в Операционните Системи

`multiset` е абстракцията зад много системни алгоритми.

### 2.1. Scheduler (Планировчик)
В една ОС процесите имат приоритет. Процесорът трябва винаги да изпълнява задачата с най-висок приоритет.
Тъй като много процеси могат да имат *еднакъв* приоритет, не можем да ползваме `set`. Използваме `multiset` (или Priority Queue, но multiset позволява търсене и премахване на произволен процес, ако той бъде убит).

### 2.2. Таймери
Браузърът или сървърът поддържат хиляди активни таймери ("изпълни това след 50ms").
`multiset<TimeEvent>` държи всички събития сортирани по време. Много събития могат да се случат в един и същи момент.
Цикълът на събитията (Event Loop) просто взима началото на сета (`begin()`), чака до нужното време и изпълнява задачата.

## 3. Структура и Производителност

`std::multiset` (както и `std::set`) е имплементиран като **Червено-черно дърво (Red-Black Tree)**.
Това е балансирано двоично дърво за търсене.

*   **Вмъкване (Insert):** O(log N).
*   **Търсене (Find):** O(log N).
*   **Изтриване (Erase):** O(log N).
*   **Памет:** Висока консумация (всеки int е в отделен Node с 3 указателя).

**Stable Insertion (Стабилност):**
C++ стандартът гарантира, че ако вмъкнете дубликати, техният относителен ред се запазва. Вторият вмъкнат елемент винаги ще бъде **след** първия. Това е критично за FIFO поведение при равни приоритети (Fair Scheduling).

## 4. Капани при работа с дубликати

Работата с дубликати изисква специално внимание към методите.

### 4.1. Изтриване (`erase`)
Това е най-важното нещо, което трябва да запомните.
```cpp
std::multiset<int> ms = {2, 2, 2};

// Вариант А: Изтриване по стойност
ms.erase(2); // ИЗТРИВА ВСИЧКИ ТРОЙКИ! Размерът става 0.

// Вариант Б: Изтриване по итератор
auto it = ms.find(2); // Намира първата двойка
if (it != ms.end()) {
    ms.erase(it); // Изтрива САМО ЕДНА двойка. Размерът става 2.
}
```

### 4.2. Броене (`count`)
`ms.count(2)` връща 3.
Внимавайте! В дървовидна структура, `count()` не е O(1). Той трябва да обходи всички дубликати. Сложността е **O(log N + брой дубликати)**. Ако имате милиони дубликати, това става линейна операция O(N).

## 5. Node Extraction и Merging (C++17)

Това е мощна оптимизация. Преди C++17, ако искахте да промените стойност в `set` (дори ако новата стойност запазва реда), трябваше да изтриете стария елемент и да вмъкнете нов (delete + new).
Сега можем да "изтръгнем" възела от дървото:

```cpp
// 1. Extract
auto node = ms.extract(it); // Вадим възела (без delete)
node.value() = 5; // Променяме стойността

// 2. Insert (Merge)
ms.insert(std::move(node)); // Вмъкваме го обратно (без new)
```
Това е изключително бързо за тежки обекти (като `std::string`), защото не се копира нищо, само се местят 3 указателя.

### Merge
Можете дори да преместите всички елементи от един `multiset` в друг `multiset` (или `set` -> `multiset`) без нито една алокация!
`dest.merge(source);`

## 6. Професионално обобщение

1.  **Не ползвайте `std::vector` + `std::sort`,** ако трябва постоянно да добавяте и махате елементи по време на работа (динамично). `multiset` е по-добър за този случай.
2.  **Не ползвайте `std::priority_queue`,** ако ви трябва търсене или изтриване на произволен елемент (не само върха). `multiset` е по-гъвкавата, макар и по-тежка структура.
3.  **Кеш локалност:** `multiset` е "Pointer Chasing" структура (лоша за кеша). Ако данните са малко (няколко стотин), сортиран `vector` може да е по-бърз въпреки теоретичната O(N) сложност на вмъкването.
