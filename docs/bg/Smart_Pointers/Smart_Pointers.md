# Smart Pointers (Интелигентни Указатели) - Пълно техническо ръководство

## 1. Въведение: Еволюцията на собствеността

C++ е език без Garbage Collection (като Java/C#). Това му дава предвидимост и скорост, но поставя тежко бреме върху програмиста: управлението на паметта.
В "стария" C++ (преди 2011), всяко `new` изискваше съответно `delete`. Една забравена команда водеше до теч на памет. Едно излишно `delete` водеше до краш.

Интелигентните указатели (`smart pointers`) са решението. Те са C++ класове, които се държат като указатели (имат оператори `*` и `->`), но автоматично управляват живота на обекта, към който сочат, използвайки идиома **RAII (Resource Acquisition Is Initialization)**.

---

## 2. `std::unique_ptr`: Ексклузивният владетел

Това е най-важният и най-често използван указател. Той е директен заместител на `std::auto_ptr` (който е deprecated/removed).
Той изразява идеята: *"Аз притежавам този ресурс. Никой друг не може да го притежава."*

### 2.1. Move-Only семантика
`unique_ptr` **не може да се копира**. Копиращият конструктор е изтрит (`delete`).
Можете само да го **премествате** (`std::move`), прехвърляйки собствеността от един обект на друг. Това гарантира, че във всеки един момент има точно един собственик.

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(42);
// std::unique_ptr<int> p2 = p1; // ГРЕШКА при компилация!
std::unique_ptr<int> p2 = std::move(p1); // OK. p1 става nullptr.
```

### 2.2. Защо `std::make_unique`?
Въведена в C++14, тази функция е предпочитаният начин за създаване.
*   **Безопасност:** `func(unique_ptr<T>(new T()), other())`. Ако `new T()` мине, но `other()` хвърли изключение преди конструктора на unique_ptr, имаме теч. `make_unique` е атомарна операция.
*   **Удобство:** Не пишете типа `T` два пъти.

### 2.3. PIMPL Idiom (Pointer to Implementation)
`unique_ptr` е идеален за PIMPL идиома, където искаме да скрием имплементацията в .cpp файл. Важно е деструкторът на класа да е дефиниран в .cpp файла (където е дефиниран пълният тип на имплементацията), иначе ще получите грешка за "incomplete type".

## 3. `std::shared_ptr`: Споделената собственост

Използва се, когато един ресурс има **много собственици** и не е ясно кой ще приключи работа последен. Ресурсът се освобождава, когато броячът на референциите (Reference Count) стане 0.

### 3.1. Control Block (Контролен блок)
`shared_ptr` е по-тежък от `unique_ptr`. Той пази два указателя:
1.  Указател към самия обект.
2.  Указател към **Control Block** (динамично заделен в хийпа).

Контролният блок съдържа:
*   Strong Reference Count (брой на живите `shared_ptr`).
*   Weak Reference Count (брой на живите `weak_ptr`).
*   Custom Deleter (ако е зададен).
*   Allocator (ако е зададен).

### 3.2. Aliasing Constructor
Малко известна, но мощна функция. Можете да създадете `shared_ptr`, който сочи към **член** на обект, но споделя собствеността на **целия** обект.
```cpp
struct Data { int x; };
auto ptr = std::make_shared<Data>();
std::shared_ptr<int> intPtr(ptr, &ptr->x); // Сочи към x, но държи Data жив!
```

## 4. `std::weak_ptr`: Слабата връзка

Това е специален указател, който наблюдава `shared_ptr`, без да увеличава брояча на собствениците. Той не предпазва обекта от изтриване.

### 4.1. Циклични зависимости (Circular Dependency)
Класическият проблем на Reference Counting системите (като в Python или Swift).
Ако А държи `shared_ptr` към Б, и Б държи `shared_ptr` към Обект А, броячите им никога няма да станат 0. Паметта изтича завинаги.
Решението е едната връзка (обикновено "родител към дете" е силна, "дете към родител" е слаба) да бъде `weak_ptr`.

### 4.2. Заключване (Locking)
Тъй като обектът може да е изтрит по всяко време, не можете да го достъпите директно през `weak_ptr`. Трябва да го "заключите", което го превръща временно в `shared_ptr`.

```cpp
if (auto shared = weak.lock()) {
    // Обектът е жив. Ползваме го безопасно.
} else {
    // Обектът вече е изтрит.
}
```

## 5. Pointer Casts

Как да превърнем `shared_ptr<Base>` в `shared_ptr<Derived>`?
Не ползвайте C-style cast! Стандартът предоставя функции, които се грижат за правилната работа на броячите:
*   `std::static_pointer_cast`
*   `std::dynamic_pointer_cast`
*   `std::const_pointer_cast`
*   `std::reinterpret_pointer_cast`

---

## 6. Професионално обобщение

1.  **Rule of Thumb:** По подразбиране винаги ползвайте `std::unique_ptr`. Той е най-бърз и най-чист.
2.  **Shared:** Ползвайте `shared_ptr` само ако наистина имате споделена собственост (напр. в графи, кешове или многонишкови опашки). Не го ползвайте просто "за всеки случай".
3.  **Raw Pointers:** В модерен C++, "голите" указатели (`T*`) се ползват само като **Non-owning observers**. Те казват "Знам къде е това, но не отговарям за живота му". Никога не ползвайте `new` и `delete` в потребителски код.
