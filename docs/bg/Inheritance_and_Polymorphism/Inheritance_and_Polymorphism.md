# Наследяване и Полиморфизъм - Пълно техническо ръководство

## 1. Въведение: IS-A релацията

Обектно-ориентираното програмиране (ООП) се гради върху три стълба: Енкапсулация, Наследяване и Полиморфизъм.
Наследяването позволява на един клас (Derived) да придобие свойствата и поведението на друг (Base). Това моделира връзката "Е" (IS-A).
*   "Кучето Е Животно".
*   "Студентът Е Човек".

Полиморфизъм (от гръцки "много форми") е способността на един интерфейс (пойнтер към Base) да работи с различни реализации (Dog, Cat) по време на изпълнение, без да знае точния им тип.

## 2. Виртуални Функции и Vtable: Механиката на магията

В C++ методите не са виртуални по подразбиране (за разлика от Java или C#). Това е направено заради принципа "Не плащаш за това, което не ползваш".
За да активирате полиморфизма, трябва изрично да маркирате метода с `virtual`.

```cpp
class Base {
public:
    virtual void speak() { cout << "Base says hi"; }
};

class Derived : public Base {
public:
    void speak() override { cout << "Derived says hello"; }
};
```

### Как работи "под капака"?
Когато компилаторът види клас с поне една виртуална функция, той създава скрита статична таблица, наречена **vtable** (Virtual Method Table). Тази таблица съдържа адресите на функциите за съответния клас.
Всеки обект от този клас получава скрит указател – **vptr** (Virtual Pointer), който сочи към vtable на неговия клас.

При извикване `ptr->speak()` се случва следното (Dynamic Dispatch):
1.  Отиди на адреса на обекта (`ptr`).
2.  Прочети скрития `vptr`.
3.  Отиди в таблицата (`vtable`).
4.  Вземи адреса на функцията от съответния слот.
5.  Скочи на този адрес.

Това добавя малък overhead (индирекция) и пречи на CPU Branch Prediction и Inlining, но дава огромна гъвкавост.

## 3. Виртуален Деструктор: Критичното правило

Това е най-важното техническо правило при наследяването в C++.
**Ако класът ви е предназначен да бъде наследяван (има виртуални функции), деструкторът му ТРЯБВА да бъде виртуален.**

Представете си следната ситуация:
```cpp
Base* b = new Derived();
delete b;
```
*   Ако `~Base()` **НЕ Е** виртуален: Компилаторът вижда, че pointer-ът е от тип `Base*`, и извиква статично само `~Base()`. Деструкторът на `Derived` никога не се изпълнява! Всичката памет и ресурси, заделени в `Derived`, изтичат (Memory Leak).
*   Ако `~Base()` **Е** виртуален: Извикването минава през vtable. Изпълнява се първо `~Derived()`, който автоматично извиква `~Base()` след себе си. Всичко се почиства коректно.

## 4. Абстрактни Класове и Чисти Виртуални Функции

В C++ няма ключова дума `interface`. Интерфейсите се реализират чрез **Абстрактни класове** с **Чисти виртуални функции** (Pure Virtual Functions).

```cpp
class IShape {
public:
    virtual void draw() const = 0; // Чиста виртуална функция (= 0)
    virtual ~IShape() = default;   // Виртуален деструктор
};
```
Класове, които съдържат поне една такава функция, са абстрактни. Не можете да създавате техни инстанции (`new IShape` е грешка). Наследниците са задължени да имплементират тези методи, иначе и те стават абстрактни.

## 5. Covariant Return Types (Ковариантни типове)

Едно малко известно, но мощно правило. Наследникът може да промени връщания тип на виртуална функция, стига новият тип да е наследник на стария (като указател или референция).

```cpp
class Factory {
    virtual Product* create() = 0;
};

class CarFactory : public Factory {
    // Връщаме Car*, което е валидно (Car наследява Product)
    // Това е по-удобно за клиента, който знае, че работи с CarFactory.
    Car* create() override { return new Car(); } 
};
```

## 6. Композиция срещу Наследяване (Composition over Inheritance)

В модерното софтуерно инженерство има тенденция към избягване на дълбоки йерархии на наследяване.
Наследяването е най-силната връзка ("Твърдо свързване") в C++. Ако промените базовия клас, чупите всички наследници (Fragile Base Class problem).

**Принципът:** "Предпочитайте композиция пред наследяване".
Вместо `class Car : public Engine`, използвайте `class Car { Engine engine; }`.
*   Наследявайте само за да споделите интерфейс (Liskov Substitution Principle).
*   Не наследявайте само за да преизползвате код (Implementation Inheritance).

## 7. Професионално обобщение

1.  **NVI (Non-Virtual Interface):** Идиом, при който публичните методи не са виртуални, а виртуалните методи са `protected/private`. Публичният метод прави проверки (валидация, логване) и тогава вика виртуалния. Това дава контрол на базовия клас върху инвариантите.
2.  **Final:** Използвайте `final` (C++11) за класове, които не трябва да се наследяват, или методи, които не трябва да се презаписват. Това позволява на компилатора да прави **Devirtualization** (да премахне vtable търсенето и да извика функцията директно), което е голяма оптимизация.
3.  **Object Slicing:** Внимавайте! Полиморфизмът работи само с указатели и референции. Ако присвоите `Derived` на променлива `Base` (по стойност), частта на наследника се "отрязва" и се губи завинаги.
