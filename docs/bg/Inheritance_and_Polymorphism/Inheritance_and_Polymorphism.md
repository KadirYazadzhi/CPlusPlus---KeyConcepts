# Наследяване и Полиморфизъм (Inheritance and Polymorphism) в C++

## 1. Наследяване (Inheritance)

Наследяването позволява създаването на нов клас (Derived/Child) на базата на съществуващ клас (Base/Parent). Новият клас наследява свойствата и методите на родителя, като може да добавя нови или да променя съществуващите.

Това насърчава **повторното използване на код** (Code Reusability).

### 1.1. Синтаксис

```cpp
class Animal {
public:
    void eat() { std::cout << "Eating...\n"; }
};

// Dog наследява Animal
class Dog : public Animal {
public:
    void bark() { std::cout << "Barking...\n"; }
};

int main() {
    Dog d;
    d.eat();  // Наследен метод
    d.bark(); // Собствен метод
}
```

### 1.2. Видове наследяване (Access Specifiers)
*   `public` наследяване (най-често): Public членовете на родителя остават public в наследника.
*   `protected` наследяване: Public и protected членовете стават protected.
*   `private` наследяване: Всички членове стават private.

### 1.3. protected достъп
Ключовата дума `protected` прави членовете недостъпни за външния свят (като private), но достъпни за класовете наследници.

## 2. Полиморфизъм (Polymorphism)

Полиморфизъм означава "много форми". В C++ той позволява на обекти от различни класове да бъдат третирани като обекти от общ базов клас, като същевременно изпълняват специфичното за тях поведение.

Това се постига чрез **Виртуални функции**.

### 2.1. Виртуални функции (Virtual Functions)
Ключовата дума `virtual` в базовия клас казва на компилатора: "Не свързвай тази функция веднага (Compile-time). Изчакай да видиш какъв е реалният тип на обекта по време на изпълнение (Run-time binding)."

```cpp
class Animal {
public:
    // Virtual позволява пренаписване (Overriding)
    virtual void makeSound() { 
        std::cout << "Generic animal sound\n"; 
    } 
};

class Cat : public Animal {
public:
    // override указва изрично, че пренаписваме виртуален метод
    void makeSound() override { 
        std::cout << "Meow!\n"; 
    } 
};

class Dog : public Animal {
public:
    void makeSound() override { 
        std::cout << "Woof!\n"; 
    } 
};

int main() {
    Animal* a1 = new Cat();
    Animal* a2 = new Dog();

    a1->makeSound(); // Meow! (Без virtual щеше да изведе "Generic...")
    a2->makeSound(); // Woof!

    delete a1;
    delete a2;
}
```

## 3. Абстрактни класове и Чисти виртуални функции

Понякога базовият клас е твърде общ, за да има имплементация. Например, какъв звук издава просто "Животно"? Никакъв.

**Чиста виртуална функция (Pure Virtual Function)** е функция без тяло, инициализирана с `= 0`.

Клас, който съдържа поне една чиста виртуална функция, става **Абстрактен клас**. Не могат да се създават обекти от него.

```cpp
class Shape {
public:
    // Интерфейс: Всеки наследник ТРЯБВА да имплементира това
    virtual double area() = 0; 
};

class Circle : public Shape {
    double r;
public:
    Circle(double radius) : r(radius) {}
    double area() override { return 3.14 * r * r; }
};

// Shape s; // ГРЕШКА! Абстрактен клас.
Shape* s = new Circle(5); // ОК, указател към абстрактен клас е позволен.
```

## 4. Виртуален Деструктор (Virtual Destructor)

⚠️ **КРИТИЧНО ВАЖНО:**
Ако един клас има поне една виртуална функция, той **трябва** да има и **виртуален деструктор**.

Ако деструкторът не е виртуален, при изтриване на обект наследник чрез указател към базовия клас (`delete basePtr`), ще се извика само деструкторът на базовия клас. Това води до **теч на памет** (ресурсите на наследника не се освобождават).

```cpp
class Base {
public:
    virtual ~Base() { std::cout << "Base destr\n"; } 
};

class Derived : public Base {
public:
    ~Derived() { std::cout << "Derived destr\n"; } 
};

// delete basePtr ще извика ~Derived(), после ~Base() -> Правилно!
```

## 5. Final и Override (C++11)

*   **override:** Гарантира, че наистина пренаписвате метод от базовия клас. Ако сбъркате името или параметрите, компилаторът ще даде грешка.
*   **final:** Забранява по-нататъшно наследяване на метод или клас.

```cpp
class Base {
    virtual void foo();
};

class Derived final : public Base { // Никой не може да наследява Derived
    void foo() override final;      // Никой не може да пренаписва foo
};
```

## 6. Как работи? (V-Table)

За да реализира полиморфизма, компилаторът създава скрита таблица за всеки клас с виртуални функции, наречена **V-Table** (Virtual Table).
Всеки обект съдържа скрит указател (**vptr**), който сочи към таблицата на своя клас.
При извикване на `object->method()`, програмата проверява vptr, намира адреса на правилната функция в таблицата и я извиква. Това добавя малък overhead, но позволява гъвкавостта на полиморфизма.
