# Тестване на Код (Unit Testing) в C++ - Пълно техническо ръководство

## 1. Въведение: Софтуерното качество като дисциплина

Unit Testing (Модулно тестване) не е просто проверка дали кодът работи. Това е инженерна практика за гарантиране на коректността на най-малките изолирани части от софтуера (функции, методи, класове). В професионалната разработка на C++ код без автоматизирани тестове се счита за "незавършен" или дори за "технически дълг".

Тестовете са вашата "предпазна мрежа". Те ви дават увереност да рефакторирате и оптимизирате кода без страх, че ще счупите нещо, което е работело преди 5 години.

---

## 2. Анатомия на Модулния тест (Шаблонът AAA)

Всеки професионален тест трябва да следва тристепенната структура:
1.  **Arrange (Подготовка):** Инициализиране на обектите, задаване на входните данни и подготовка на средата.
2.  **Act (Действие):** Извикване на функционалността, която тестваме.
3.  **Assert (Проверка):** Сравняване на реалния резултат с очаквания.

---

## 3. Инструментариум: Google Test (GTest)

Google Test е индустриалният стандарт за C++.

### 3.1. Макроси за проверка
*   **ASSERT_EQ(val1, val2):** Фатална грешка. Ако проверката се провали, тестът спира веднага.
*   **EXPECT_EQ(val1, val2):** Нефатална грешка. Тестът продължава, за да видим и други потенциални проблеми.
*   **EXPECT_THROW(code, ExceptionType):** Проверява дали кодът хвърля правилното изключение.

### 3.2. Test Fixtures (Фикстури)
Ако много тестове използват една и съща начална конфигурация (напр. отваряне на връзка към тестова база), използваме `Test Fixture` (наследяване от `testing::Test`).

```cpp
class DatabaseTest : public testing::Test {
protected:
    void SetUp() override { db.connect(); } // Преди всеки тест
    void TearDown() override { db.disconnect(); } // След всеки тест
    Database db;
};

TEST_F(DatabaseTest, InsertWorks) { // TEST_F вместо TEST
    db.insert("user", "data");
    EXPECT_TRUE(db.hasUser("user"));
}
```

### 3.3. Параметризирани Тестове
Позволяват ви да изпълните една и съща тестова логика с хиляди различни входни данни.
```cpp
class MathTest : public testing::TestWithParam<int> {};

TEST_P(MathTest, IsEven) {
    int n = GetParam();
    EXPECT_EQ(n % 2, 0);
}

INSTANTIATE_TEST_SUITE_P(EvenNumbers, MathTest, testing::Values(2, 4, 6, 8, 100));
```

## 4. Изолация и Заместване: Google Mock (GMock)

В реалните системи класовете зависят от външни ресурси (мрежа, файлова система). Модулният тест трябва да е **изолиран**.
**Google Mock** ни позволява да създаваме "фалшиви" обекти, които имитират поведението на реалните.

```cpp
class MockBank : public IBank {
public:
    MOCK_METHOD(bool, withdraw, (int amount), (override));
};

TEST(ATM, WithdrawFailsOnNoMoney) {
    MockBank bank;
    // Очаквания: "withdraw" ще се извика веднъж с аргумент 100 и трябва да върне false.
    EXPECT_CALL(bank, withdraw(100)).Times(1).WillOnce(testing::Return(false));
    
    ATM atm(&bank);
    bool result = atm.requestMoney(100);
    EXPECT_FALSE(result);
}
```

## 5. Методология: TDD (Test-Driven Development)

TDD променя реда на работа:
1.  **Red:** Пишете тест, който се проваля (защото функцията още не съществува).
2.  **Green:** Пишете минималния код, само колкото тестът да мине.
3.  **Refactor:** Почиствате и оптимизирате кода, докато тестовете продължават да светят в зелено.

---

## 6. Интеграция с CMake

За да бъде тестването част от билд процеса, добавете го в `CMakeLists.txt`:

```cmake
enable_testing()
add_executable(my_tests tests.cpp)
target_link_libraries(my_tests GTest::gtest_main)
include(GoogleTest)
gtest_discover_tests(my_tests)
```
Сега можете да пуснете всички тестове с командата `ctest`.

## 7. Професионално обобщение

1.  **Code Coverage:** Не се стремете сляпо към 100% покритие. Тествайте критичната бизнес логика и граничните случаи (Edge cases).
2.  **Без логика в тестовете:** Тестовият код трябва да е глупав (линеен). Ако имате `if` или `for` в теста, вероятно ви трябва тест за теста.
3.  **Бързина:** Модулните тестове трябва да са мигновени. Бавните тестове се пускат рядко и губят своята стойност.
