# Тестване на Код (Unit Testing) в C++ - Пълно ръководство

## 1. Въведение: Защо тестваме?
Модулното тестване (Unit Testing) е процесът на проверка на най-малките компоненти на кода (функции, класове) в изолация. Професионалният C++ код е немислим без автоматизирани тестове, които гарантират, че промените днес няма да счупят работещата функционалност от вчера.

---

## 2. Google Test (GTest) - Индустриалният стандарт
Въпреки че има много библиотеки (Catch2, doctest), Google Test е най-разпространената.

### 2.1. Базов синтаксис
Тестовете се пишат чрез макроси:
*   `EXPECT_EQ(val1, val2)`: Продължава дори при грешка.
*   `ASSERT_EQ(val1, val2)`: Спира теста веднага при грешка.

```cpp
#include <gtest/gtest.h>

int sum(int a, int b) { return a + b; }

TEST(MathTests, AdditionWorks) {
    EXPECT_EQ(sum(2, 2), 4);
    EXPECT_NE(sum(2, 2), 5);
}
```

---

## 3. Фикстури (Test Fixtures)
Когато имате нужда от една и съща среда (напр. база данни или сложен обект) за няколко теста, използвате класове, наследяващи `::testing::Test`.

---

## 4. TDD (Test-Driven Development)
Философия, при която първо пишете теста, той се проваля (защото кодът го няма), след това пишете кода, за да мине теста, и накрая рефакторирате.

---

## 5. Mocking (Заместване)
Библиотеката **googlemock** позволява да симулирате поведението на сложни зависимости (напр. мрежови услуги), за да тествате логиката на вашия клас напълно изолирано.

---

## 6. Ползи
1.  **Намаляване на бъговете:** Откриват се в момента на писане.
2.  **Документация:** Тестовете служат като примери за това как се ползва кода.
3.  **Дизайн:** Кодът, който е труден за тестване, обикновено е лошо проектиран.
