# Многонишково Програмиране (Multithreading) в C++

## 1. Въведение

От C++11 езикът има вградена поддръжка за многонишковост чрез библиотеката `<thread>`. Това позволява на програмата да изпълнява няколко задачи **едновременно** (паралелно), използвайки многоядрените процесори.

---

## 2. Създаване на Нишка

Нишката стартира веднага щом създадем обект `std::thread` и му подадем функция за изпълнение.

```cpp
#include <iostream>
#include <thread>

void task(int id) {
    std::cout << "Thread " << id << " is working...\n";
}

int main() {
    // Стартираме нишка
    std::thread t1(task, 1);
    
    // Главната нишка продължава да работи
    std::cout << "Main thread is working...\n";

    // join(): Главната нишка чака t1 да приключи
    t1.join(); 
    
    std::cout << "Done.\n";
    return 0;
}
```

⚠️ **Важно:** Задължително трябва да извикате или `join()` (изчакване), или `detach()` (пускане на самотек) преди обектът `std::thread` да бъде унищожен. В противен случай програмата ще крашне (`std::terminate`).

---

## 3. Проблемът с Данните (Race Conditions)

Когато няколко нишки се опитват да четат и пишат в една и съща памет едновременно, настъпва хаос (Data Race). Резултатът е неопределен.

```cpp
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; ++i) counter++;
}
// Ако пуснем две нишки, counter няма да е 200000!
```

---

## 4. Синхронизация с Mutex

`std::mutex` (Mutual Exclusion) се използва за защита на споделени данни. Той позволява само на една нишка да достъпва кода между `lock` и `unlock` в даден момент.

```cpp
#include <mutex>

int counter = 0;
std::mutex mtx; // Глобален мутекс

void safeIncrement() {
    for (int i = 0; i < 100000; ++i) {
        mtx.lock();
        counter++; // Критична секция
        mtx.unlock();
    }
}
```

### std::lock_guard
Ръчното заключване/отключване е опасно (ако забравите `unlock` или стане грешка). `std::lock_guard` автоматично заключва при създаване и **отключва при унищожаване** (RAII).

```cpp
void betterIncrement() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(mtx);
        counter++; 
    } // lock се унищожава тук и отключва мутекса автоматично
}
```

## 5. Асинхронни задачи (std::async)

Ако искате просто да върнете стойност от нишка, `std::async` е по-лесен интерфейс от `std::thread`. Той връща `std::future`, който ще съдържа резултата в бъдеще.

```cpp
#include <future>

int calculate() {
    return 42;
}

int main() {
    // Стартира задача (може би в нова нишка)
    std::future<int> result = std::async(std::launch::async, calculate);

    // Върши друга работа...
    
    // Взимане на резултата (блокира, ако не е готов)
    std::cout << "Result: " << result.get() << std::endl;
}
```

---

## 6. Atomic променливи

За прости броячи и флагове, `std::mutex` е твърде тежък. `std::atomic` позволява безопасни операции без заключване (lock-free).

```cpp
#include <atomic>
std::atomic<int> atomicCounter(0);

void atomicInc() {
    atomicCounter++; // Това е атомарна операция, безопасно е.
}
```

---

## 7. Обобщение

*   Многонишковото програмиране е мощно, но сложно.
*   Винаги защитавайте споделените данни с `mutex` или `atomic`.
*   Използвайте `lock_guard`, за да избегнете Deadlock (мъртва хватка).
*   Предпочитайте `std::async` за прости задачи, които връщат резултат.
