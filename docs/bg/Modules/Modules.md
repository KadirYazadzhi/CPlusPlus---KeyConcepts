# Модули (Modules) в C++20 - Пълно ръководство

## 1. Въведение: Краят на #include
От създаването си през 80-те години, C++ използва механизъм за текстово вмъкване на файлове (`#include`). Това е бавно (един файл се компилира хиляди пъти) и води до конфликти с макроси. **Модулите** са модерната алтернатива, която променя начина, по който структурираме проектите си.

---

## 2. Основен синтаксис

### 2.1. Създаване на модул (math.cppm)
```cpp
export module math;

export int add(int a, int b) {
    return a + b;
}

// Тази функция не е видима отвън
int secret_helper() { return 42; }
```

### 2.2. Използване (main.cpp)
```cpp
import math;
import <iostream>;

int main() {
    std::cout << add(5, 10);
}
```

---

## 3. Предимства на модулите
1.  **Скорост:** Модулите се компилират само веднъж до бинарен формат. Всеки `import` е почти мигновен.
2.  **Изолация:** Макросите дефинирани в модула не "изтичат" навън и не чупят кода на потребителя.
3.  **Логическа структура:** Вече няма нужда от разделяне на `.h` и `.cpp` файлове. Целият клас/функция може да бъде в една модулна единица.

---

## 4. Сравнение

| Характеристика | #include (Headers) | import (Modules) |
| :--- | :--- | :--- |
| **Механизъм** | Textual Copy-Paste | Logical Import |
| **Компилация** | Повтаряща се (бавно) | Еднократна (бързо) |
| **Макроси** | Изтичат навсякъде | Остава капсулирани |
| **Сложност** | Трудни за управление | Чисти зависимости |

---

## 5. Бъдещето на C++
Въпреки че поддръжката за модули в компилаторите вече е добра, индустрията все още е в преходен период. В големите проекти се очаква модулите да намалят времето за компилация с до 50-80%.
