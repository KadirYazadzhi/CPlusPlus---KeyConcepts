# SIMD Векторизация в C++ - Пълно техническо ръководство

## 1. Въведение: Разчупване на бариерата на SISD

Повечето програмисти пишат код, мислейки за модела **SISD** (Single Instruction, Single Data).
*   "Вземи число А, събери го с число Б, запиши резултата."

Съвременните процесори обаче са **SIMD** (Single Instruction, Multiple Data) машини. Те могат да съберат 8 двойки числа едновременно с една единствена инструкция.
Ако не използвате SIMD, вие използвате само около 5-10% от изчислителната мощ на процесора (ALU) при тежки математически задачи.

---

## 2. Хардуерни архитектури (x86_64 и ARM)

За да използваме SIMD, трябва да познаваме регистрите на процесора. Те са много по-широки от стандартните 64-битови регистри (`rax`, `rbx`).

### 2.1. Intel/AMD (x86_64)
*   **SSE (Streaming SIMD Extensions):** 128-битови регистри (`xmm0` - `xmm15`). Побират 4 `float` или 2 `double`. Налични във всеки модерен процесор.
*   **AVX / AVX2 (Advanced Vector Extensions):** 256-битови регистри (`ymm0` - `ymm15`). Побират 8 `float`. Де факто стандартът за High Performance днес.
*   **AVX-512:** 512-битови регистри (`zmm0` - `zmm31`). Побират 16 `float`. Основно в сървърни процесори (Xeon) и някои нови десктоп модели.

### 2.2. ARM (Mobile & Apple Silicon)
*   **NEON:** 128-битови регистри (`q0` - `q15`). Всички Android телефони и iPhone/Mac (M1/M2) ги поддържат.

## 3. Нива на Векторизация

Как да накараме кода си да ползва тези регистри?

### 3.1. Ниво 1: Автоматична Векторизация (Auto-vectorization)
Компилаторите (GCC, Clang, MSVC) са невероятно умни. Ако напишете прост цикъл, те сами ще го превърнат в SIMD инструкции.

```cpp
// Компилирайте с -O3 -mavx2
void add(float* a, float* b, float* c, int n) {
    for (int i = 0; i < n; ++i) {
        c[i] = a[i] + b[i];
    }
}
```
**Изисквания за авто-векторизация:**
1.  **Без зависимости:** Резултатът от итерация `i` не трябва да зависи от итерация `i-1`.
2.  **Pointer Aliasing:** Компилаторът трябва да е сигурен, че масивите не се припокриват в паметта. Използвайте ключовата дума `__restrict` (или `std::restrict` в бъдеще), за да му помогнете.
3.  **Alignment:** Данните трябва да са подравнени (виж т.5).

### 3.2. Ниво 2: SIMD Библиотеки (Препоръчително)
Писането на асемблер е трудно и не е преносимо. Библиотеките предоставят C++ класове, които обвиват SIMD инструкциите.
*   **Google Highway:** Най-добрата модерна библиотека. Избира най-добрите инструкции по време на изпълнение.
*   **XSIMD:** Популярна библиотека (ползва се в Apache Arrow).
*   **EnTT (Simd):** За гейм енджини.

### 3.3. Ниво 3: Intrinsics (Ръчно управление)
Това е най-ниското ниво преди чистия асемблер. Използвате функции, предоставени от компилатора, които съответстват 1:1 на процесорни инструкции.

```cpp
#include <immintrin.h> // За AVX

void avx_add(float* a, float* b, float* c) {
    // Зареждаме 8 числа от паметта в регистър
    __m256 vec_a = _mm256_loadu_ps(a); 
    __m256 vec_b = _mm256_loadu_ps(b);
    
    // Една инструкция събира 8 двойки числа
    __m256 vec_res = _mm256_add_ps(vec_a, vec_b);
    
    // Записваме резултата обратно
    _mm256_storeu_ps(c, vec_res);
}
```
**Недостатък:** Този код няма да работи на ARM процесори (трябва да напишете отделна версия с NEON intrinsics).

## 4. Branching (Разклонения) в SIMD

SIMD инструкциите мразят `if-else`. Тъй като инструкцията се прилага върху всички 8 числа едновременно, не може за едни да направим `+`, а за други `-`.
**Решение:** Masked Execution (Изпълнение с маска).
Изчисляваме *и двата* резултата и ги смесваме накрая чрез битова маска.

```cpp
// if (a > b) return a; else return b;
__m256 mask = _mm256_cmp_ps(a, b, _CMP_GT_OQ); // Генерира маска (0xFF или 0x00)
__m256 res = _mm256_blendv_ps(b, a, mask);     // Избира a или b според маската
```

## 5. Подравняване на Паметта (Data Alignment)

SIMD инструкциите са най-бързи (а старите дори изискваха), когато адресът на паметта е кратен на размера на регистъра (32 байта за AVX).
Ако заредите данни от "неподравнен" адрес, процесорът трябва да направи допълнителни четения, което забавя кода.

```cpp
struct alignas(32) Vector8 {
    float data[8];
};

// Динамично заделяне на подравнена памет
void* ptr = std::aligned_alloc(32, 1024 * sizeof(float));
```

## 6. Професионално обобщение

1.  **Разчитайте на компилатора:** Преди да пишете SIMD ръчно, проверете дали `-O3` вече не го е направил. Използвайте сайта **Godbolt.org**, за да видите генерирания асемблер.
2.  **Data Layout:** Организацията на данните е по-важна от инструкциите. Използвайте **SoA (Structure of Arrays)** вместо **AoS (Array of Structures)**.
    *   *SoA:* `struct { float x[N]; float y[N]; }` -> Перфектно за SIMD.
    *   *AoS:* `struct Point { float x, y; }; Point p[N];` -> Трудно за SIMD (трябва разбъркване/shuffling).
3.  **Профилиране:** SIMD не винаги е по-бърз. Ако обработвате малко данни (N < 100), overhead-ът по зареждане в регистрите може да направи кода по-бавен от скаларния.
