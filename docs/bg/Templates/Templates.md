# Шаблони (Templates) в C++ - Пълно техническо ръководство

## 1. Въведение: Парадигмата на Генеричното Програмиране

Шаблоните са "ядреното оръжие" на C++. Те позволяват писането на код, който е независим от типа данни (**Generic Programming**). За разлика от Java/C# Generics, които работят с Type Erasure по време на изпълнение, C++ шаблоните са **Compile-time** механизъм.

**Как работи?** Шаблонът не е код. Той е "чертеж" (blueprint). Когато използвате `std::vector<int>`, компилаторът взема чертежа на вектора и генерира (инстанцира) напълно нов клас `Vector_Int`, оптимизиран специално за цели числа.

---

## 2. Шаблони на Функции (Function Templates)

Вместо да претоварваме една функция 10 пъти за `int`, `float`, `double`, дефинираме шаблон:

```cpp
template <typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}
```

### 2.1. Template Type Deduction
Не е нужно да пишете `maximum<int>(5, 10)`. Компилаторът е достатъчно умен, за да разбере, че 5 и 10 са `int`, и автоматично инстанцира правилната версия.

---

## 3. Шаблони на Класове (Class Templates)

Това е гръбнакът на STL (`vector`, `map`, `list`).

```cpp
template <typename T, size_t N>
class Array {
    T data[N]; // Размерът N е известен по време на компилация!
public:
    size_t getSize() const { return N; }
};

Array<int, 5> arr; // Създава се уникален тип Array_int_5
```

⚠️ **Важно:** Non-type template parameters (като `size_t N`) позволяват на компилатора да прави луди оптимизации (напр. loop unrolling), защото знае точния размер на масива преди програмата да тръгне.

---

## 4. Шаблонна Специализация (Template Specialization)

Понякога общият алгоритъм не работи за всички типове. Пример: Искате `Box<T>` да работи за всичко, но `Box<bool>` да бъде оптимизиран да заема 1 бит, а не 1 байт.

```cpp
// 1. Основен шаблон
template <typename T>
class Box { T val; };

// 2. Пълна специализация
template <>
class Box<bool> {
    unsigned char data; // Битови операции...
};
```
Това прави `std::vector<bool>` толкова различен от `std::vector<int>`.

## 5. Вариадични Шаблони (Variadic Templates) - C++11

Позволяват на шаблона да приема произволен брой аргументи. Това е основата на `std::printf`-подобни функции и `std::tuple`.

### 5.1. Fold Expressions (C++17)
Преди C++17 трябваше да пишем рекурсия. Сега е магия:

```cpp
template<typename... Args>
auto sum(Args... args) {
    return (... + args); // Събира всички аргументи: (arg1 + arg2 + arg3...)
}

int total = sum(1, 2, 3, 4, 5); // 15
```

## 6. Метапрограмиране (Template Metaprogramming - TMP)

Тъй като шаблоните са Тюринг-пълни, можете да пишете програми, които се изпълняват **по време на компилация**.

### 6.1. SFINAE (Substitution Failure Is Not An Error)
Това е старата техника (преди C++20) за филтриране на типове. "Ако типът `T` няма метод `quack()`, не гърми с грешка, а просто премахни тази функция от списъка с кандидати."

```cpp
// Активира се само ако T е число
template <typename T>
typename std::enable_if<std::is_arithmetic<T>::value, T>::type
add(T a, T b) { return a + b; }
```

## 7. Модерен C++: Концепти (Concepts) - C++20

Концептите убиха SFINAE. Те правят кода четим и дават ясни съобщения за грешки.

```cpp
template <typename T>
concept Number = std::integral<T> || std::floating_point<T>;

template <Number T>
T add(T a, T b) { return a + b; }
```
Ако подадете `string`, компилаторът ще каже: *"Грешка: string не удовлетворява концепцията Number"*, вместо да изплюе 10 страници шаблонни грешки.

---

## 8. Професионално обобщение

1.  **Header-Only:** Шаблоните трябва да се дефинират изцяло в `.h` / `.hpp` файловете. Ако ги сложите в `.cpp`, linker-ът няма да ги намери.
2.  **Code Bloat:** Внимавайте. `Array<int, 1>`, `Array<int, 2>`... `Array<int, 100>` ще генерира 100 различни класа в бинарния файл.
3.  **Performance:** Шаблоните са най-бързият начин за полиморфизъм (Static Polymorphism), защото избягват виртуалните таблици.
4.  **Използвайте C++20 Concepts:** Те са бъдещето на чистия API дизайн.
