# Lock-free структури от данни в C++ - Пълно ръководство

## 1. Въведение: Проблемът с Мутексите
В многонишковото програмиране стандартният начин за защита на данни е `std::mutex`. Мутексите обаче имат сериозни проблеми:
*   **Blocking:** Нишката спира и чака, което забавя системата.
*   **Priority Inversion:** Нишка с нисък приоритет може да блокира такава с висок.
*   **Deadlock:** Риск от вечно блокиране.

**Lock-free** програмирането позволява на нишките да работят върху една и съща структура **без нито една нишка да бъде спирана**.

---

## 2. Сърцето на Lock-free: CAS (Compare-And-Swap)

Всички Lock-free структури разчитат на една специална хардуерна инструкция: **Compare-And-Swap**. В C++ тя е достъпна през `std::atomic`.

**Логика:** "Смени стойността на `X` с `Нова`, само ако `X` в момента е равен на `Очаквана`. Кажи ми дали успя."

```cpp
std::atomic<int> value(10);
int expected = 10;
if (value.compare_exchange_strong(expected, 20)) {
    // Успех! Стойността е 20.
}
```

## 3. Lock-free Стек (Treiber Stack)

Ето как изглежда един прост lock-free стек. Вместо да заключваме целия списък, ние използваме CAS, за да сменим указателя към върха (`head`).

```cpp
template<typename T>
class LockFreeStack {
    struct Node { T data; Node* next; };
    std::atomic<Node*> head;

public:
    void push(T val) {
        Node* newNode = new Node{val, head.load()};
        // Опитваме се да сложим новия възел на върха.
        // Ако някой друг ни изпревари, пробваме отново (loop).
        while (!head.compare_exchange_weak(newNode->next, newNode));
    }
};
```

## 4. Предизвикателството: Управление на паметта (The ABA Problem)

Lock-free програмирането е изключително трудно заради паметта.
**ABA проблем:**
1. Нишка А чете адрес 0x100 (A).
2. Нишка Б изтрива 0x100 (B) и заделя нов обект на същия адрес 0x100 (A).
3. Нишка А мисли, че нищо не се е променило, и счупва структурата.

**Професионални решения:**
*   **Hazard Pointers:** Нишките "маркират" кои адреси ползват в момента.
*   **Epoch-based Reclamation:** Паметта се трие едва когато цяла "епоха" от нишки приключи.

---

## 5. Производителност: Кога да ги ползваме?

Lock-free структурите невинаги са по-бързи!
*   **Ниско натоварване:** Мутексите са по-прости и често по-бързи.
*   **Високо натоварване (Contention):** Когато стотици нишки се борят за един ресурс, Lock-free мащабира много по-добре.

---

## 6. Професионално обобщение
*   **Не пишете свои Lock-free структури**, освен ако не сте експерт по компютърна архитектура. Това е "висш пилотаж" в C++.
*   Използвайте готови библиотеки като **Boost.Lockfree**.
*   Lock-free е задължителен за **HFT (High-Frequency Trading)**, ядра на операционни системи и гейм енджини.
