# Optional, Variant и Any (C++17) - Пълно техническо ръководство

## 1. Въведение: Сбогом на void* и Null
До C++17 работата с "липсващи" или "динамични" типове данни изискваше използването на опасни указатели (`nullptr`, `void*`) или тромави йерархии. C++17 въведе три нови типа контейнери за стойности, вдъхновени от функционалното програмиране, които правят кода по-сигурен и изразителен.

---

## 2. std::optional: Стойности, които може да не съществуват
Най-често използваният от трите. Той решава проблема: "Какво да върне функция, ако не намери резултат?".

### 2.1. Защо е по-добър от nullptr?
*   **Типова безопасност:** Използва се за обекти, а не само за указатели.
*   **Изразителност:** `return std::nullopt;` ясно казва, че липсата на стойност е валиден сценарий.

```cpp
std::optional<int> findUserAge(int id) {
    if (id == 1) return 25;
    return std::nullopt; // Няма стойност
}
```

---

## 3. std::variant: Алгебрични типове данни (Sum Types)
`std::variant` е модерната и безопасна версия на `union`. Той може да съдържа стойност от точно един тип от предварително зададен списък.

### 3.1. std::visit (The Visitor Pattern)
Това е професионалният начин за работа с `variant`. Той ви позволява да дефинирате ламбда функции за всеки възможен тип, гарантирайки, че сте покрили всички случаи по време на компилация.

```cpp
std::variant<int, std::string> data = 10;
std::visit([](auto&& arg) { std::cout << arg; }, data);
```

---

## 4. std::any: Пълният динамизъм
`std::any` е контейнер, който може да съдържа **абсолютно всеки** тип (стига да е копируем). Прилича на `Object` в Java.

⚠️ **ВНИМАНИЕ:** Тъй като `std::any` често използва динамична алокация (Heap), той е много по-бавен от `variant` и трябва да се избягва, освен ако типовете не са напълно неизвестни.

---

## 5. Сравнителен анализ

| Тип | Предназначение | Памет |
| :--- | :--- | :--- |
| **optional<T>** | Стойност 0 или 1 | T + bool флаг |
| **variant<A, B>** | Стойност А или Б | Max(A, B) + index |
| **any** | Всеки тип | Heap + RTTI |

---

## 6. Професионално обобщение
*   Използвайте `optional` за търсене и опционални настройки.
*   Използвайте `variant` за хендлъри на събития или резултати (Success/Error).
*   Използвайте `any` само в крайни случаи при работа с външни плъгин системи.
