# Препроцесор и Макроси (Preprocessor & Macros) - Пълно техническо ръководство

## 1. Въведение: Програмата преди Програмата

C++ компилацията не започва с компилация. Тя започва с **Препроцесиране**.
Препроцесорът е текстов манипулатор ("Copy-Paste машина"), който минава през вашия код, изпълнява всички директиви започващи с `#`, и генерира чист C++ код (Translation Unit), който чак тогава се подава на компилатора.

Можете да видите резултата от тази фаза с командата:
`g++ -E main.cpp > preprocessed.cpp`
(Ще видите файл от 50,000 реда, защото всички `#include` са копирани вътре).

## 2. `#include`: Механиката

*   `#include <vector>`: Търси в системните папки (Include Path, `-I` флагове).
*   `#include "myheader.h"`: Търси в текущата папка на файла.

**Header Guards:**
Всеки `.h` файл трябва да бъде защитен от двойно включване.
```cpp
// Старият (стандартен) начин
#ifndef MY_CLASS_H
#define MY_CLASS_H
   class MyClass {};
#endif

// Модерният начин (поддържан от всички компилатори)
#pragma once
   class MyClass {};
```

## 3. Макроси (`#define`): Двуострият меч

Макросите са текстова замяна. Те нямат обхват (scope), нямат типове, и игнорират C++ правилата.

### 3.1. Трагедията на Windows Headers
Един от най-известните проблеми в историята на C++ е хедърът `<windows.h>`. Той дефинира макроси `min` и `max`.
```cpp
#define min(a,b) ((a)<(b)?(a):(b))
#define max(a,b) ((a)>(b)?(a):(b))
```
Това чупи стандартната библиотека на C++! Когато напишете `std::max(a, b)`, препроцесорът вижда `max` и го заменя, преди компилаторът да види `std::`. Резултатът е синтактична грешка: `std::((a)>(b)?(a):(b))(a, b)`.
Затова почти всеки Windows проект започва с `#define NOMINMAX` преди включването на хедърите.

### 3.2. Опасностите
```cpp
#define SQUARE(x) x * x

int result = SQUARE(1 + 2);
// Разгъва се до: 1 + 2 * 1 + 2;
// Заради приоритета на операциите, това е: 1 + 2 + 2 = 5.
// Очаквахме (1+2)^2 = 9.
```
**Правило:** Винаги слагайте скоби около аргументите и целия макрос!
`#define SQUARE(x) ((x) * (x))`

## 4. Специални Макроси и Оператори

### 4.1. Stringizing (`#`)
Превръща аргумент в низ.
```cpp
#define LOG_NAME(x) std::cout << "Variable name is: " << #x << "\n"
int value = 42;
LOG_NAME(value); // "Variable name is: value"
```

### 4.2. Token Pasting (`##`)
Слепя два токена в едно.
```cpp
#define MAKE_GETTER(name) int get_##name() { return name; }
int score;
MAKE_GETTER(score); // Генерира функция: int get_score() { return score; }
```

### 4.3. Variadic Macros (`...` и `__VA_ARGS__`)
Макроси с променлив брой аргументи (като `printf`).
```cpp
#define LOG(fmt, ...) printf("[LOG] " fmt, __VA_ARGS__)
```

## 5. Условна Компилация (Conditional Compilation)

Това е начинът да пишете крос-платформен код.

```cpp
#if defined(_WIN32)
    #include <Windows.h>
    void sleep(int ms) { Sleep(ms); }
#elif defined(__linux__)
    #include <unistd.h>
    void sleep(int ms) { usleep(ms * 1000); }
#else
    #error "Unknown OS!"
#endif
```

### Feature Test Macros (C++20)
Можем да проверяваме дали компилаторът поддържа дадена C++ функционалност.
```cpp
#ifdef __cpp_concepts
    template<std::integral T> void func(T x);
#else
    template<typename T> void func(T x); // Fallback за стари компилатори
#endif
```

## 6. C++20 Modules: Убиецът на `#include`

С C++20 идват **Модулите** (`import std;`). Те целят да премахнат нуждата от препроцесора за управление на зависимости.
*   Modules са компилирани, не се копи-пействат.
*   Modules са изолирани (макросите не "изтичат" навън).
*   Компилацията е драстично по-бърза.

Но докато индустрията мигрира (което ще отнеме десетилетие), препроцесорът остава тук.

## 7. Професионално обобщение

1.  **Чистота:** Ако можете да го направите с `constexpr`, `enum`, `template` или `inline function` - направете го така. Не ползвайте макрос.
2.  **Naming:** Макросите винаги се пишат с `UPPER_CASE`, за да крещят на програмиста "Аз съм макрос, внимавай!".
3.  **Undef:** Ако дефинирате помощен макрос в .cpp файл, използвайте `#undef` в края на файла, за да не замърсявате глобалното пространство.
