# Препроцесор и Макроси (Preprocessor & Macros) - Пълно техническо ръководство

## 1. Въведение: Първата фаза на компилацията

Преди компилаторът (напр. GCC или Clang) изобщо да види вашия C++ код, той преминава през **Препроцесора**. Това е проста програма за текстова обработка, която копира файлове, замества текст и премахва коментари.
Всички директиви започват с `#`. Препроцесорът не разбира от типове, класове или scope – той вижда само текст.

---

## 2. Директивата `#include`

Тя казва на препроцесора: *"Намери този файл, копирай цялото му съдържание и го постави на този ред."*

*   `#include <header>`: Търси в системните пътища (напр. `/usr/include`). Използва се за стандартни библиотеки.
*   `#include "file.h"`: Първо търси в текущата директория на проекта. Използва се за ваши собствени файлове.

⚠️ **Header Hell:** Ако файл А включва Б, а Б включва В, всички те стават част от една огромна единица за компилация (Translation Unit).

## 3. Макроси (#define): Защо са опасни?

Макросите са "търси и замени" (Search & Replace).

### 3.1. Макроси за константи
```cpp
#define PI 3.14159
```
**Проблем:** `PI` няма тип. Няма namespace. Той замърсява целия код.
**Решение:** Използвайте `constexpr double PI = 3.14159;`.

### 3.2. Макроси-функции
```cpp
#define SQUARE(x) x * x
```
**Класически капан:**
`int res = SQUARE(1 + 2);` се разгръща до `1 + 2 * 1 + 2`. Резултатът е 5, а не 9!
**Решение:** Винаги слагайте скоби: `#define SQUARE(x) ((x) * (x))`.
**Още по-добро решение:** Използвайте `template` или `inline` функции.

## 4. Условна компилация (Conditional Compilation)

Това е единственият начин да поддържате един сорс код за множество платформи (Windows, Linux, Mac).

```cpp
#ifdef _WIN32
    #include <windows.h>
    void clearScreen() { system("cls"); }
#elif defined(__linux__)
    #include <unistd.h>
    void clearScreen() { system("clear"); }
#else
    #error "Неподдържана платформа!"
#endif
```
Така можете да компилирате различен код в зависимост от това дали е `Debug` или `Release` билд.

## 5. Include Guards срещу `#pragma once`

Ако включите `header.h` два пъти (директно и индиректно), ще получите грешка "Redefinition of class".

### 5.1. Include Guards (Стандартният начин)
```cpp
#ifndef MY_HEADER_H
#define MY_HEADER_H

class MyClass { ... };

#endif
```
Работи навсякъде, но изисква уникално име за всеки файл.

### 5.2. `#pragma once` (Модерният начин)
```cpp
#pragma once
class MyClass { ... };
```
Казва на компилатора: "Включи този файл само веднъж". По-бързо е и по-малко код, но теоретично не е част от ISO стандарта (макар всички компилатори да го поддържат).

## 6. Advanced Techniques: Stringification и Token Pasting

### 6.1. Stringification (`#`)
Превръща аргумента в C-string.
```cpp
#define PRINT_VAR(x) std::cout << #x << " = " << x << std::endl;
int counter = 42;
PRINT_VAR(counter); // Извежда: counter = 42
```

### 6.2. Token Pasting (`##`)
Слепя два токена, за да създаде ново име на променлива/функция.
```cpp
#define GEN_FUNC(type) void func_##type(type x) { cout << x; }
GEN_FUNC(int); // Генерира void func_int(int x) { ... }
```

### 6.3. X-Macros
Техника за генериране на код (напр. Enum и масив от стрингове едновременно) чрез предефиниране на макрос и многократно включване на списък.

---

## 7. Професионално обобщение

1.  **Избягвайте `#define`** за константи и логика. Използвайте `constexpr` и `templates`.
2.  **Използвайте препроцесора** само за:
    *   Включване на файлове.
    *   Header Guards.
    *   Условна компилация (Platform-specific code).
    *   Дебъгване (`__FILE__`, `__LINE__`).
3.  **Изолация:** Ако трябва да ползвате макрос, `#undef`-вайте го веднага след употреба, за да не счупите чужд код.
