# SOLID Принципи (SOLID Principles) в C++

## 1. Въведение

SOLID са 5 принципа на обектно-ориентирания дизайн, дефинирани от Robert C. Martin (Uncle Bob). Те помагат кодът да бъде лесен за поддръжка и разширение.

---

## 2. S - Single Responsibility Principle (SRP)
**"Един клас трябва да има само една причина да се променя."**

Лош пример: Клас `User`, който пази данни, записва ги в базата и праща имейли.
Добър пример:
*   `User` (Данни)
*   `UserRepository` (Запис в базата)
*   `EmailService` (Пращане на имейл)

---

## 3. O - Open/Closed Principle (OCP)
**"Софтуерните единици трябва да са отворени за разширение, но затворени за модификация."**

Ако искате да добавите нова функционалност, не трябва да променяте съществуващия (работещ) код, а да добавите нов клас.

```cpp
// ЛОШО: Трябва да променяме класа всеки път при нова форма
class GraphicEditor {
    void drawShape(Shape s) {
        if (s.type == Circle) drawCircle(s);
        else if (s.type == Square) drawSquare(s); // Промяна тук!
    }
};

// ДОБРЕ: Използване на полиморфизъм
class Shape {
public:
    virtual void draw() = 0; // Абстракция
};

class Circle : public Shape {
    void draw() override { /* ... */ }
};

class Editor {
    void drawShape(Shape* s) {
        s->draw(); // Работи за всяка нова форма без промяна тук!
    }
};
```

## 4. L - Liskov Substitution Principle (LSP)
**"Обектите от наследен клас трябва да могат да заместват обекти от базовия клас, без да чупят програмата."**

Класически пример за нарушение: Клас `Square` наследява `Rectangle`.
Ако имате функция `setWidth(w)`, при правоъгълника се променя само ширината. При квадрата обаче се променя и височината (защото страните са равни). Това неочаквано поведение чупи логиката на програмата, която очаква правоъгълник.

**Извод:** Квадратът НЕ Е правоъгълник в ООП смисъл (поведение), въпреки че е такъв в математиката.

---

## 5. I - Interface Segregation Principle (ISP)
**"Клиентите не трябва да бъдат принуждавани да зависят от интерфейси, които не използват."**

Вместо един огромен интерфейс `IMachine` (print, scan, fax), разделете го на `IPrinter`, `IScanner`, `IFax`. Така един прост принтер няма да бъде принуден да имплементира празен метод `scan()`.

---

## 6. D - Dependency Inversion Principle (DIP)
**"Модулите от високо ниво не трябва да зависят от модули на ниско ниво. И двата трябва да зависят от абстракции."**

Вместо клас `Car` да създава вътрешно `PetrolEngine` (твърда връзка), той трябва да приема `IEngine` в конструктора си (Dependency Injection).

```cpp
// Абстракция
struct IEngine {
    virtual void start() = 0;
};

class Car {
    IEngine* engine; // Зависи от абстракция
public:
    Car(IEngine* e) : engine(e) {} // Dependency Injection
};
```

Така лесно можем да сменим двигателя с електрически или да мокнем (mock) двигателя за тестове.

---

## 7. Обобщение

Спазването на SOLID води до код, който е:
*   По-лесен за тестване.
*   По-лесен за разбиране.
*   По-устойчив на промени.
