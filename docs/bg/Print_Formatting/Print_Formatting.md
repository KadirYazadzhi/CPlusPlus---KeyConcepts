# std::print и Форматиране в C++ - Пълно техническо ръководство

## 1. Въведение: Еволюцията на изхода в C++
В продължение на 40 години C++ програмистите бяха раздвоени между два свята:
1.  **C-style `printf`:** Бърз, но напълно небезопасен (не знае типовете на данните).
2.  **C++ `iostream` (`std::cout`):** Типобезопасен, но изключително тромав, бавен и труден за форматиране (напр. за задаване на прецизност на числа).

C++20 и C++23 въведоха библиотеките `<format>` и `<print>`, които съчетават най-доброто от двата свята: скоростта и лесния синтаксис на `printf` с пълната типова безопасност и разширяемост на C++.

---

## 2. std::format (C++20): Модерният низ

`std::format` работи подобно на f-strings в Python. Той връща `std::string`, което го прави идеален за логване и подготовка на текст.

### 2.1. Базов синтаксис
```cpp
#include <format>
std::string msg = std::format("Hello, {}! You have {} messages.", "Ivan", 5);
```

### 2.2. Разширено форматиране
Можете да контролирате подравняване, запълване и прецизност директно в низа:
*   `{:>10}`: Подравняване вдясно (ширина 10).
*   `{:.2f}`: Две цифри след запетаята.
*   `{:0x}`: Извеждане в шестнадесетичен формат с водещи нули.

## 3. std::print и std::println (C++23)

Докато `std::format` само подготвя низа, `std::print` го извежда директно на екрана или във файл по най-ефективния възможен начин.

### 3.1. Защо е по-добър от `std::cout`?
`std::cout` е обект от тип `ostream`, който носи със себе си огромен товар от състояние (locale, състояние на грешка). `std::print` избягва този товар и комуникира директно с операционната система (през Unicode поддръжка, където е налична).

### 3.2. Уникод поддръжка (UTF-8)
Най-голямото предимство на `std::print` е гарантираната поддръжка на UTF-8 в Windows конзолата. Преди C++23 извеждането на кирилица в Windows беше истинско предизвикателство.

```cpp
#include <print>
int main() {
    std::println("Здравей, свят! Числото Pi е {:.2f}", 3.14159);
}
```

## 4. Разширяване на библиотеката (Custom Formatters)

Професионалният C++ код изисква възможност да печатаме наши собствени класове по същия начин като вградените типове.

### 4.1. Пример за персонализиран клас
```cpp
struct Point { int x, y; };

template <>
struct std::formatter<Point> : std::formatter<std::string> {
    auto format(Point p, format_context& ctx) const {
        return formatter<string>::format(
            std::format("({}, {})", p.x, p.y), ctx);
    }
};
```

## 5. Производителност: Бенчмарк анализ

В мащабни тестове:
*   `std::format` е до **20-30% по-бърз** от `std::stringstream`.
*   Бинарният размер на програмата с `std::print` е **по-малък**, защото не се налага инстанциране на тежките шаблони на `iostream`.
*   `std::print` е по-бърз от `printf` при работа с низове, защото не се налага да парсва формата по време на изпълнение (парсването става в Compile-time).

## 6. Сравнителна таблица

| Характеристика | printf | std::cout | std::print |
| :--- | :--- | :--- | :--- |
| **Safety** | Ниска (Crash) | Висока | Висока (Compile-time check) |
| **Speed** | Бързо | Бавно | Най-бързо |
| **Syntax** | Кратък | Тромав | Кратък и мощен |
| **Unicode** | Проблемен | Зависи от OS | Пълна поддръжка |

---

## 7. Професионално обобщение
*   Забравете за `std::cout` и `printf` в новите проекти.
*   Използвайте `std::format` за подготовка на данни.
*   Използвайте `std::println` за извеждане на информация.
*   Библиотеката `<format>` е Type-safe по време на компилация – ако сбъркате типа, кодът просто няма да се компилира.
