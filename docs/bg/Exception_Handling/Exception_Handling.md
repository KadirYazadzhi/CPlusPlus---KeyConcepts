# Обработка на Изключения (Exception Handling) - Пълно техническо ръководство

## 1. Въведение: Различният поток на управление

Изключенията са механизъм за справяне с грешки, който разделя "нормалния път" на програмата от "пътя за обработка на грешки". В C, грешките се предават чрез връщани стойности (Return Codes) или глобални променливи (`errno`). Това води до "спагети код", където след всяка функция има `if (err != 0)`.

В C++, когато възникне проблем, функцията не връща код, а **хвърля** (`throw`) обект. Изпълнението на програмата спира и започва да се връща назад по стека (**Stack Unwinding**), докато не намери подходящ `catch` блок.

---

## 2. Гаранции за безопасност (Exception Safety Guarantees)

Това е най-важната концепция за C++ архитекта. Какво става с вашите обекти, ако функция хвърли изключение по средата?

1.  **No-throw Guarantee (Най-силна):** Функцията гарантира, че никога няма да хвърли изключение. Задължително за деструктори, `swap` и `move` операции.
2.  **Strong Guarantee (Transaction Semantics):** Операцията или успява напълно, или (ако хвърли грешка) програмата остава в състоянието, в което е била преди операцията. Няма странични ефекти. (`std::vector::push_back` дава тази гаранция – ако няма памет, векторът не се променя).
3.  **Basic Guarantee (Най-слаба):** Ако стане грешка, няма да има Memory Leaks и обектите са във валидно (но неизвестно) състояние. Всички STL контейнери дават поне тази гаранция.
4.  **No Guarantee:** Всичко е счупено, паметта изтича, програмата е в недефинирано състояние.

## 3. RAII и Stack Unwinding

По време на "развиването" на стека, всички локални обекти се унищожават в обратен ред на създаването им.
Това е моментът, в който RAII (Resource Acquisition Is Initialization) блести. Smart Pointers автоматично освобождават паметта, `std::lock_guard` отключва мутексите, `std::fstream` затваря файловете.

**Златно правило:** Деструкторът никога не трябва да хвърля изключение!
Ако по време на Unwinding (заради Еxception A), някой деструктор хвърли Exception B, C++ се оказва с две активни изключения едновременно. Езикът не поддържа това и веднага вика `std::terminate`, убивайки програмата безцеремонно.

## 4. `noexcept`: Договорът с компилатора

От C++11 можем да маркираме функции с `noexcept`.
```cpp
void fast() noexcept { ... } 
```
Това прави две неща:
1.  **Оптимизация:** Компилаторът не генерира код за обработка на изключения (unwind tables) за тази функция, което я прави по-бърза и по-малка.
2.  **Терминация:** Ако функцията въпреки това хвърли изключение, програмата веднага извиква `std::terminate()` и умира. Няма catch.

**Важно:** STL контейнерите (като `vector`) използват Move Constructor само ако е `noexcept`. Ако не е, те копират елементите при разширяване, което е драстично по-бавно. Винаги правете move операциите `noexcept`!

## 5. Изключения в Конструктори

Ако конструктор хвърли изключение:
1.  Обектът се счита за **несъздаден**.
2.  Деструкторът на този обект **НЯМА** да бъде извикан.
3.  ОБАЧЕ, деструкторите на всички вече конструирани член-променливи (fields) и базови класове ЩЕ бъдат извикани.

**Капан:** Ако използвате "голи" указатели (`new`) в конструктора, и хвърлите изключение преди да ги изтриете, ще имате Memory Leak, защото деструкторът на класа няма да тръгне.
**Решение:** Използвайте `std::unique_ptr` за членовете. Те ще се почистят сами.

## 6. `std::terminate` и Handlers

Ако никой не хване изключението, то стига до върха на `main` и ОС убива програмата.
Можете да инсталирате собствен handler преди смъртта чрез `std::set_terminate`.
Това е полезно за логване на Crash Dumps (Stack Trace) преди програмата да изчезне.

```cpp 
void my_handler() {
    std::cerr << "Uncaught exception! Logging...\n";
    std::abort();
}
int main() {
    std::set_terminate(my_handler);
    throw 1;
}
```

## 7. Function-try Blocks

Малко известен синтаксис, който позволява да хванете изключение, хвърлено в списъка за инициализация на конструктора.

```cpp
MyClass() try : member(init()) {
    // Тяло на конструктора
} catch (...) {
    // Хваща грешки от init() или от тялото.
    // Внимание: Тук обектът е само частично конструиран!
    // Изключението автоматично се прехвърля нагоре (rethrow) след края на блока.
}
```

## 8. Професионално обобщение

1.  **Изключенията са за ИЗКЛЮЧИТЕЛНИ ситуации:** Не ги ползвайте за контрол на потока (напр. "Край на файл" или "Грешна парола"). Те са бавни при хвърляне (заради Unwinding).
2.  **Throw by value, catch by reference:** Винаги хвърляйте обекти (`throw std::runtime_error("...")`), а не указатели. Винаги хващайте по референция (`catch (const std::exception& e)`), за да избегнете копиране и Object Slicing.
3.  **std::exception:** Винаги наследявайте стандартния клас за вашите грешки, за да могат да бъдат хванати от общия `catch`.
4.  **Zero-cost Exceptions:** В модерните компилатори (Itanium ABI), `try` блокът няма цена, ако не се хвърли изключение.
