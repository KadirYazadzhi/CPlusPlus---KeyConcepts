# Обработка на Изключения (Exception Handling) - Пълно техническо ръководство

## 1. Въведение: Философията на "Изключителните" ситуации

В програмирането грешките са неизбежни. Преди изключенията, C-програмистите използваха кодове за грешка (напр. връщане на -1 или `NULL`). Това водеше до "спагети код", където бизнес логиката е смесена с `if (err)` проверки на всеки ред.

**Изключенията** в C++ позволяват:
1.  Отделяне на логиката за обработка на грешки от нормалния поток.
2.  Гаранция, че грешките не могат да бъдат игнорирани мълчаливо.
3.  Автоматично пренасяне на информацията нагоре по стека.

---

## 2. Механизмът: Try, Catch, Throw

### 2.1. Throw (Хвърляне)
Когато възникне проблем, който функцията не може да реши сама, тя "хвърля" изключение. Това прекратява изпълнението на функцията **моментално**.
```cpp
void connect(string ip) {
    if (ip.empty()) {
        throw std::invalid_argument("IP адресът не може да е празен!");
    }
    // ... останалият код не се изпълнява при грешка
}
```

### 2.2. Catch (Хващане)
Изключението "лети" нагоре по стека (през всички извикващи функции), докато не срещне `catch` блок, който може да го обработи.
```cpp
try {
    connect("");
} catch (const std::invalid_argument& e) { // Хващаме по const reference!
    std::cerr << "Грешка: " << e.what() << std::endl;
} catch (...) {
    std::cerr << "Неизвестна грешка!" << std::endl;
}
```

## 3. Stack Unwinding: Най-важната концепция

⚠️ **ИНЖЕНЕРЕН ПОГЛЕД:** Какво става с локалните променливи, когато функцията прекъсне заради `throw`?

Тук влиза в сила **Stack Unwinding (Развиване на стека)**. C++ гарантира, че за всички автоматични обекти (създадени в стека) ще бъдат извикани техните деструктори.

**Пример за RAII сила:**
```cpp
void riskyFunction() {
    std::vector<int> data(1000000); // Заделя памет
    std::ofstream file("log.txt");  // Отваря файл
    
    throw std::runtime_error("Бум!"); 
    
    // file.close() и delete[] data НИКОГА не се пишат тук експлицитно.
    // Деструкторите се викат автоматично при throw!
}
```
Това прави **RAII** (Resource Acquisition Is Initialization) единственият правилен начин за управление на ресурси в C++ с изключения.

## 4. Цената на Изключенията (Zero-Cost Exceptions)

В модерните компилатори (GCC, Clang, MSVC) се използва моделът **Zero-Cost Abstractions**.
*   **Ако няма грешка:** Кодът работи със същата скорост, както ако нямаше `try-catch`. Няма проверки `if` след всяка инструкция.
*   **Ако има грешка:** Тогава (и само тогава) системата влиза в скъп режим. Трябва да се прочете специална таблица (Exception Table), да се намери catch handler-а и да се развие стека.

**Извод:** Използвайте изключения само за **наистина изключителни** събития (мрежата падна, дискът е пълен). Не ги ползвайте за контрол на потока (напр. "край на цикъл"), защото са бавни при хвърляне.

## 5. Модерен C++: `noexcept`

Ключовата дума `noexcept` (C++11) е договор.
`void func() noexcept;`

*   **Значение:** "Обещавам, че тази функция никога няма да хвърли изключение."
*   **Полза:** Позволява на компилатора да прави агресивни оптимизации (напр. да не генерира Exception Tables за тази функция).
*   **Риск:** Ако излъжете и функцията хвърли, програмата умира веднага (`std::terminate`).

**Задължително ползвайте `noexcept` за:**
1.  Деструктори (Винаги!).
2.  Move Constructors.
3.  Swap функции.

---

## 6. Дефиниране на собствени грешки

Не хвърляйте просто `int` или `string`. Наследете `std::exception`.

```cpp
class DatabaseError : public std::runtime_error {
public:
    int errorCode;
    DatabaseError(const string& msg, int code) 
        : std::runtime_error(msg), errorCode(code) {}
};
```

## 7. Exception Safety Guarantees (Нива на сигурност)

Когато пишете функция, вие трябва да гарантирате едно от следните при грешка:
1.  **Basic Guarantee:** Няма течове на памет (благодарение на RAII), но програмата може да е в променено състояние.
2.  **Strong Guarantee (Transactional):** Операцията или успява напълно, или не променя нищо (Rollback). `std::vector::push_back` дава тази гаранция.
3.  **No-throw Guarantee:** Функцията никога не се проваля.

---

## 8. Професионално обобщение

1.  **Throw by value, catch by reference:** Винаги `catch (const std::exception& e)`. Това избягва Object Slicing (отрязване на информацията от наследниците).
2.  **RAII:** Никога не ползвайте `new/delete` в код с изключения. Ползвайте `unique_ptr`.
3.  **Destructors:** Деструктор, който хвърля изключение по време на Stack Unwinding, води до незабавен краш. Деструкторите трябва да са "мълчаливи".
