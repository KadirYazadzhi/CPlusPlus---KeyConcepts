# Препроцесор и Макроси (Preprocessor and Macros) в C++

## 1. Въведение

Препроцесорът е първата стъпка от процеса на компилация. Той обработва изходния код (`.cpp` / `.h`) **преди** същинският компилатор да го види.

Всички команди към препроцесора започват със символа `#`.
Той извършва текстови замествания (copy-paste), без да разбира синтаксиса на C++.

---

## 2. Директива #include

Казва на препроцесора да вземе съдържанието на друг файл и да го копира дословно на текущото място.

*   `#include <header>`: Търси в системните директории (стандартната библиотека).
*   `#include "file.h"`: Търси първо в текущата директория на проекта.

---

## 3. Директива #define (Макроси)

Използва се за дефиниране на константи или макро-функции.

### 3.1. Константи
```cpp
#define PI 3.14159
#define BUFFER_SIZE 1024

// Преди компилация, навсякъде където пише BUFFER_SIZE, 
// ще бъде заменено с 1024.
int buffer[BUFFER_SIZE]; 
```

⚠️ **Проблем:** Макросите нямат тип (type safety) и не спазват scope (обхват). Те са глобални.
**Решение:** В C++ предпочитайте `const` или `constexpr`.
```cpp
const double Pi = 3.14159; // По-добре
```

### 3.2. Макро-функции
Това са фрагменти код, които изглеждат като функции, но се разгръщат inline.

```cpp
#define SQUARE(x) ((x) * (x))

int result = SQUARE(5); // Разгръща се до: ((5) * (5))
```

⚠️ **Опасност:** Странични ефекти.
```cpp
int a = 5;
int result = SQUARE(++a); 
// Разгръща се до: ((++a) * (++a))
// a се увеличава ДВА пъти! Недефинирано поведение.
```
**Решение:** Използвайте `inline` функции или шаблони.

## 4. Условна Компилация (Conditional Compilation)

Позволява да включваме или изключваме части от кода в зависимост от условия. Много полезно за крос-платформен код (Windows vs Linux).

```cpp
#ifdef _WIN32
    #include <windows.h>
    void clearScreen() { system("cls"); }
#else
    #include <unistd.h>
    void clearScreen() { system("clear"); }
#endif
```

*   `#ifdef NAME`: Ако NAME е дефинирано.
*   `#ifndef NAME`: Ако NAME **НЕ** е дефинирано.
*   `#if CONDITION`: Ако условието е истина (напр. `#if VERSION > 2`).
*   `#endif`: Край на блока.

## 5. Include Guards (Защита от повторно включване)

Ако файл `A.h` включва `Common.h`, и `B.h` също включва `Common.h`, а `main.cpp` включва и `A.h` и `B.h`, тогава `Common.h` ще бъде копиран два пъти. Това води до грешка "redefinition".

За да го предотвратим, използваме Include Guards:

```cpp
// Common.h

#ifndef COMMON_H  // Ако символът не е дефиниран...
#define COMMON_H  // Дефинирай го сега.

struct Data {
    int x;
};

#endif // Край на проверката
```

### #pragma once
Модерна алтернатива, поддържана от почти всички компилатори. Прави същото, но е по-кратко и по-малко податливо на грешки.

```cpp
#pragma once

struct Data {
    int x;
};
```

## 6. Специални Макроси

Компилаторът предоставя предефинирани макроси за информация:

*   `__LINE__`: Текущият номер на ред.
*   `__FILE__`: Името на текущия файл.
*   `__DATE__`, `__TIME__`: Дата и час на компилация.
*   `__func__`: Името на текущата функция.

Полезни са за логване на грешки.

```cpp
std::cerr << "Error in " << __FILE__ << " at line " << __LINE__;
```

---

## 7. Обобщение

*   Препроцесорът е мощен инструмент за конфигурация на кода.
*   Използвайте `#include` и `#pragma once` (или guards) във всеки хедър.
*   **Избягвайте `#define`** за константи и функции в C++. Използвайте `const`, `constexpr`, `enum` и `template`.
*   Условната компилация е незаменима за поддръжка на различни операционни системи.
