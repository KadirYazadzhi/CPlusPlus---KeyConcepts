# Оптимизация и Кеш (Optimization and Cache) в C++

## 1. Въведение

В C++ често гоним максимална производителност. За да я постигнем, не е достатъчно да знаем O(N) сложността на алгоритмите. Трябва да знаем как работи хардуерът.

Процесорът е много по-бърз от RAM паметта. За да не чака, той използва **Кеш** (L1, L2, L3). Достъпът до L1 кеша е мигновен (~1 ns), докато до RAM може да отнеме 100 ns.

---

## 2. Cache Locality (Локалност на данните)

Най-важното правило за оптимизация: **Дръж данните, които обработваш заедно, физически близо в паметта.**

Когато процесорът чете един `int`, той не чете само 4 байта. Той зарежда цяла **Cache Line** (обикновено 64 байта).

### Пример: Vector vs List

*   `std::vector`: Всички елементи са един до друг. Четенето на `v[0]` зарежда и `v[1]`, `v[2]`... в кеша.
*   `std::list`: Всеки елемент е на различно място в паметта (pointer chasing).

Резултат: Обхождането на вектор може да е **50-100 пъти по-бързо** от списък, дори при еднаква алгоритмична сложност O(N).

## 3. Data-Oriented Design (DOD)

Вместо да мислим за "Обекти", мислим за "Данни".

### Array of Structs (AoS) - Стандартно ООП
```cpp
struct Particle {
    float x, y, z;
    float r, g, b; // Цвят
    bool active;
};
std::vector<Particle> particles;
```
Ако искаме да обновим само позицията (x, y, z), ние зареждаме в кеша и излишните данни за цвят (r, g, b), замърсявайки го.

### Structure of Arrays (SoA) - DOD
```cpp
struct Particles {
    std::vector<float> x, y, z;
    std::vector<float> r, g, b;
    std::vector<bool> active;
};
```
Тук `x, y, z` са в отделни масиви. Процесорът зарежда само тях и може да използва SIMD инструкции за паралелна обработка.

## 4. Branch Prediction (Предсказване на разклонения)

Процесорът се опитва да познае накъде ще тръгне `if`-ът, преди да го е сметнал, за да зареди инструкциите (Pipelining). Ако сбърка, трябва да изхвърли всичко и да започне отначало (скъпо!).

**Сортираните масиви се обработват по-бързо от несортираните**, ако има `if (data[i] > 128)`, защото pattern-ът става предвидим (TTTFFF вместо TFTFTF).

В C++20 можем да подскажем на компилатора:
`[[likely]]` и `[[unlikely]]`.

```cpp
if (error) [[unlikely]] {
    // Този код се слага в "студена" част на паметта
    handleError();
}
```

---

## 5. Обобщение

1.  **Измервайте!** Никога не оптимизирайте без профайлър.
2.  **Contiguous Memory:** Използвайте `std::vector` за всичко.
3.  **Data layout:** Подреждайте структурите си така, че да пестите памет (alignment).
4.  **Avoid Pointers:** Указателите са враг на кеша.
