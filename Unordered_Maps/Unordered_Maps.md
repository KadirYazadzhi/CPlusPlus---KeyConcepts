# Неподредени Карти (Unordered Maps) в C++

## 1. Въведение

`std::unordered_map` е асоциативен контейнер, който (както и `std::map`) съхранява двойки ключ-стойност с уникални ключове. Разликата е във вътрешната реализация и производителността.

Той използва **хеш таблица** (Hash Table). Това означава, че елементите **не са сортирани** в никакъв конкретен ред, но за сметка на това достъпът до тях е изключително бърз.

Дефиниран е в заглавния файл `<unordered_map>`.

### Характеристики:
*   **Сложност:** Средно време за търсене, добавяне и триене е **O(1)** (константно).
*   **Най-лош случай:** O(N) (при много колизии на хеша), но това се случва рядко при добра хеш функция.
*   **Подредба:** Няма. Редът на елементите при итерация изглежда случаен и зависи от хеша.

---

## 2. Кога да изберем Unordered Map?

Използвайте `unordered_map`, когато:
1.  **Не ви пука за реда** на елементите.
2.  Искате **максимална скорост** на търсене (Look-up speed).
3.  Работите с голям обем данни, където O(log N) на `std::map` би било бавно.

Използвайте `map`, когато:
1.  Трябва да обхождате данните в сортиран ред.
2.  Искате да използвате функции като `lower_bound`/`upper_bound`.
3.  Ключът няма добра хеш функция.

---

## 3. Основни Операции

Синтаксисът е почти идентичен с този на `std::map`.

```cpp
#include <iostream>
#include <unordered_map>
#include <string>

int main() {
    std::unordered_map<std::string, double> products;

    // Вмъкване
    products["Laptop"] = 999.99;
    products["Mouse"] = 19.50;
    products["Keyboard"] = 45.00;

    // Търсене - O(1)
    if (products.find("Mouse") != products.end()) {
        std::cout << "Mouse price: " << products["Mouse"] << std::endl;
    }

    // Обхождане
    // Редът е неопределен (напр. може да излезе Keyboard, после Laptop...)
    for (const auto& [name, price] : products) {
        std::cout << name << ": " << price << "\n";
    }

    return 0;
}
```

## 4. Хеш функции и Потребителски типове

За да използвате собствен клас като ключ в `unordered_map`, трябва да предоставите две неща:
1.  **Оператор за равенство (`==`)**: За да се провери дали два ключа са еднакви.
2.  **Хеш функция**: Специална структура, която превръща обекта в число (`size_t`).

```cpp
#include <functional> // За std::hash

struct Key {
    int id;
    std::string code;

    bool operator==(const Key& other) const {
        return id == other.id && code == other.code;
    }
};

// Специализация на std::hash за нашия тип Key
namespace std {
    template <>
    struct hash<Key> {
        size_t operator()(const Key& k) const {
            // Комбиниране на хешовете на полетата
            // (Проста XOR комбинация за пример)
            return hash<int>()(k.id) ^ hash<string>()(k.code);
        }
    };
}

int main() {
    std::unordered_map<Key, std::string> data;
    data[{1, "ABC"}] = "Value 1";
}
```

## 5. Управление на "Кофите" (Buckets)

Хеш таблицата вътрешно е масив от "кофи" (buckets). Хеш функцията определя в коя кофа да отиде елементът. Ако два елемента имат еднакъв хеш (колизия), те отиват в една и съща кофа (обикновено като свързан списък).

`unordered_map` предоставя API за инспекция на тези кофи (полезно за дебъгване на производителността):

*   `bucket_count()`: Общ брой кофи.
*   `load_factor()`: Среден брой елементи в кофа. Ако стане твърде голям, таблицата се преоразмерява (Rehashing).
*   `bucket_size(n)`: Колко елемента има в n-тата кофа.

```cpp
std::cout << "Load factor: " << products.load_factor() << std::endl;
// Ако load_factor > 1.0, това значи много колизии и вероятно забавяне.
```
