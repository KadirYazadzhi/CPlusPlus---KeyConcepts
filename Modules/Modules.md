# Модули (Modules) в C++20

## 1. Проблемът с #include

От 40 години C++ използва `#include` за вмъкване на код. Това има сериозни недостатъци:
1.  **Бавна компилация:** Ако включите `<vector>` в 100 файла, той се парсва и компилира 100 пъти.
2.  **Липса на изолация:** Макросите (`#define`) от един хедър могат да "изтекат" и да счупят друг хедър.
3.  **Зависимост от реда:** `#include "A.h"` преди `#include "B.h"` може да работи, а обратното - не.

**Модулите** решават всички тези проблеми. Те са модерният заместител на хедър файловете.

## 2. Hello World с Модули

Вместо `.h` и `.cpp`, използваме модулни интерфейсни единици (обикновено `.ixx` или `.cppm`).

### Създаване на модул (math.ixx)
```cpp
// Декларираме, че това е модул
export module math;

// Само нещата маркирани с 'export' са видими отвън
export int add(int a, int b) {
    return a + b;
}

// Тази функция е скрита (private за модула)
int helper(int x) { return x * 2; }
```

### Използване на модул (main.cpp)
```cpp
import math; // Вместо #include
import <iostream>; // Дори стандартната библиотека може да се импортва

int main() {
    std::cout << add(5, 3) << "\n";
    // helper(5); // ГРЕШКА! Не е експортирана.
}
```

---

## 3. Предимства

1.  **Скорост:** Модулът се компилира **само веднъж** до бинарен формат (BMI). Всеки `import` е почти мигновен. При големи проекти това може да намали времето за компилация с 50-90%.
2.  **Изолация:** Макросите и скритите символи не изтичат. `import` не копира текст, а зарежда интерфейс.
3.  **Няма нужда от Header Guards:** (`#pragma once` е излишен).

## 4. Разделяне на Интерфейс и Имплементация

Можем да разделим модула на части, подобно на `.h` и `.cpp`, но по-чисто.

**math.ixx (Interface)**
```cpp
export module math;

export int multiply(int a, int b); // Само декларация
```

**math.cpp (Implementation)**
```cpp
module math; // Казваме "това е имплементация на модул math"

int multiply(int a, int b) {
    return a * b;
}
```

---

## 5. Състояние на поддръжката

Към 2024-2025 г., поддръжката на модули в компилаторите (GCC, Clang, MSVC) и build системите (CMake) е вече добра, но все още има ръбове за изглаждане, особено при смесване със стари библиотеки.

Старата библиотека все още се включва с `#include`:
```cpp
import std; // C++23 style
#include <vector> // Старият начин работи и вътре в модули
```
